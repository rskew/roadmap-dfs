# W179 · Archiving a chat should navigate back rather than always going to the chat menu

## Summary

Archiving a chat in the web page now closes the chat and leaves you on the screen you opened it from, as Back does, instead of always jumping to the Chats list. Archiving from the Chats list redraws that list at once. The terminal screen already stayed where it was, so it is unchanged. The Goal is met.

## Goal

Archiving a chat should navigate back rather than always going to the chat menu

## Tree

### W179.1 · Archive closes the chat like Back does
Status: confirmed
Approach:
- **The question**: after Archive, why does the web page always show the Chats list, and what should it do instead?
- **Why it matters**: the chat is a dialog over the screen it was opened from (a task, or the Chats list). Back closes it and shows that screen. Archive calls `toChats()`, so a chat opened from a task jumps to the Chats list.
- **What this node does**: in `scripts/web/index.html`, the `chatend` action closes the dialog and stays on the screen beneath. When that screen is the Chats list, it redraws at once so the chat moves under Archived. The terminal screen's `end_chat` in `scripts/tui.py` already stays where it was, so it is left alone. `chat_end` in `scripts/ui_flows.mjs` now expects the task to be current after Archive from a task.
- **How we will know it worked**: the `chat_end` browser flow passes: Archive from a task leaves the task showing, and Archive from the Chats list leaves the list redrawn with the chat under Archived. The flow also had a click on a Chats tab that a phone's task screen does not have; it now sets the `#/chats` hash instead.
Determination: Archive now closes the chat and leaves the screen it was opened from, so the goal is met.
