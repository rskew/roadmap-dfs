# W115 · Login to Claude from dfs page

## Summary

The project dialog on the web page now has a "Claude account" control. It shows who claude is signed in as, and Sign in gives claude's own link; you open it, paste the code it shows back into the page, and the page reports the account now signed in or claude's own error. It runs `claude auth login` through the same pinned claude the runs start, so it replaces the one stored login every run, chat and the terminal read. The Goal is met for one account at a time; keeping several accounts to switch between, or a long-lived token, was left out because the single stored login is what everything already reads.

## Goal

Login to Claude from dfs page

## Tree

### W115.1 · The web server signs claude in by running `claude auth login` with pipes
Status: confirmed
Approach: A new `run.sh --claude-auth <args>` execs the pinned claude (the same `CLAUDE_CMD` or nixpkgs pin the runs use) as `claude auth <args>`. A new `scripts/login.py` holds one sign-in at a time: it starts `run.sh --claude-auth login` with stdin and stdout as pipes, reads the sign-in URL it prints, writes the code the author pastes to its stdin, and reports `claude auth status --json` (signed in, email, plan) once it ends. web.py serves it at `GET /api/login` and `POST /api/login/{start,code,cancel,check}`. Checked by a test of login.py and test_web against a stub `CLAUDE_CMD` that prints the URL, reads a code and writes a status.
Hypothesis: The Goal means signing the claude CLI that this machine's runs and chats use in to one Anthropic account (claude.ai subscription by default) from the dfs web page, replacing its stored login, as when one account has hit its weekly limit or a login has expired. Wrong if the author meant keeping several accounts and switching between them, an API key, or signing in to something other than the agents' CLI. .dfs/artefacts/28c9c785-868a-41c2-b950-97633974bf86.html

- for: the pinned claude-code 2.1.308, run as `claude auth login` with stdin a pipe and a throwaway HOME, printed "If the browser didn't open, visit: https://claude.com/cai/oauth/authorize?code=true&…" and "Paste code here if prompted >", and a code piped in after 8s got "Login failed: Request failed with status code 400": the flow needs no terminal.
- for: `claude auth status` printed JSON with `loggedIn`, `authMethod`, `email` and `subscriptionType`, enough for the page to say who is signed in.
Determination: Confirmed: `run.sh --claude-auth` and `scripts/login.py` sign claude in from `/api/login`; driven against the real pinned claude with a throwaway HOME the server reached the real claude.com link and reported claude's own "Login failed: Request failed with status code 400" for a made-up code, and test_login and test_web pass against a stub, with the full suite failing only the two UI flows (walktags, markdown) that fail on main.
