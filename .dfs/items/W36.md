## Tree

### W36.1 · Interrupt a headless chat turn
Status: confirmed
Approach: In scripts/chat.py `run_turn` takes an `on_start(process)` callback and starts the turn in its own process group; `Chats` keeps the running turn's process per scope and gains `interrupt(scope)`, which ends the group as a timeout does (SIGTERM, SIGKILL after TURN_GRACE) and makes the turn finish with a `note` message ("Stopped before it answered.") instead of an error. A new chat's session id is chosen before the turn (CHAT_SID without CHAT_RESUME starts it under that id), so the conversation survives an interrupt of its first turn. Check: a test with a stub claude that sleeps.
Determination: Confirmed: test_chat's new stop test passes (the sleeping stub's turn ends within seconds with roles you, note, the session is kept and the next message is answered); the only other test_chat failure, "will not send while the screens chat is open", fails the same without my change, and every test needs TMPDIR on an exec-capable mount since /tmp here is noexec.
