# W119 · Yellow assumptions item background should be transparent so the background shows through

## Summary

Task-list rows that rest on an assumption no longer have a yellow fill, so the page background and any background picture show through them. A yellow stripe on the left edge still marks them as assumptions, hover uses the shared selection tint, a test keeps those rows unfilled, and the design system notes it. The red blocker rows, the tags and the node tree's assumption rows were left as they were, since the Goal named the yellow task item only.

## Goal

Yellow assumptions item background should be transparent so the background shows through

## Tree

### W119.1 · Task-list rows with an assumption are drawn without a yellow fill
Status: confirmed
Approach: In scripts/web/index.html, drop the `--assumption-wash` fill from `.item.assumes` (the task list) and `.railitem.assumes` (the wide-layout rail), and delete the `.item.assumes:hover` rule that re-applied it, so the page background (and any background picture) shows through and hover falls to the shared `--sel`. Keep a yellow cue so the row still reads as an assumption: an inset left stripe in `--assumption-fill` on `.item.assumes` (the rail already has its `border-left` in that colour). Red blocker rows, tags, and the node tree's `.row.assumes .main` are left as they are. Check by serving the page with a background picture in headless chromium and reading the computed background of an `.item.assumes`, then run scripts/test_web.py.
Determination: The assumption rows in the task list and the rail now have a transparent background with a yellow left stripe; in headless chromium the page gradient shows through them while the red blocker row stays filled, so the Goal is met. ![an assumption row unfilled over a gradient page, beside a filled red row](.dfs/artefacts/7c0e0d1c-51ef-45f0-8c30-3a93c5d4b69c.png)

### W119.2 · Guard the unfilled assumption rows with a test and say so in the design system
Parent: W119.1
Status: confirmed
Approach: Add a test in scripts/test_web.py that reads the `.item.assumes` and `.railitem.assumes` rules from scripts/web/index.html and fails if either sets a `background` (so the unfilled row cannot regress), and that the JS gives a row `blocks` or `assumes`, never both (drawTasks and the rail use `!blocks && ...`), which is why no red-over-amber CSS is needed. Update docs/design-system.md so the colour table says task-list rows and the rail mark an assumption with the amber stripe only, unfilled, while node-tree rows keep the wash. Check by running scripts/test_web.py.
Determination: The new test fails when `.item.assumes` is given a background and passes as built, the design system now says task-list and rail assumption rows are unfilled, and the two remaining test_web.py failures (chat, Claude sign-in) are the same ones that fail on the parent commit.
