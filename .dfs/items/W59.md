# W59 · Option to run sandbox in docker daemon mode to start automatically on reboot

## Summary

`sandbox daemon [command args]` now runs the sandbox detached with the container engine's `--restart unless-stopped`, so it starts again when the host reboots (default command: the repo's app command), and `sandbox stop` removes it (and a start that fails part-way removes what it had started). The nix sidecar is restarted the same way, and its socket now lives in `.container-state/nix-proxy` and is mounted as a directory so a restarted sidecar is picked up in either start order. The Goal is met in the script and README; it was checked against a stub engine, not a real reboot, since no docker daemon was available. It relies on the engine being enabled at boot and on the tool's store paths surviving garbage collection; a systemd-unit alternative was left aside.

## Goal

Option to run sandbox in docker daemon mode to start automatically on reboot

## Tree

### W59.1 · `sandbox daemon`: detached containers with a restart policy
Status: confirmed
Approach: Add a `daemon` mode to scripts/sandbox.sh: `sandbox daemon [command args...]` runs the command (default: CONTAINER_APP_CMD, as the container's main process) in a detached container started with `--restart unless-stopped` and without `--rm`, so the engine brings it back on reboot until `sandbox stop` removes it. The nix proxy sidecar gets the same policy and stays up after the script exits (no EXIT trap); its socket directory moves from a mktemp dir under XDG_RUNTIME_DIR (wiped on reboot) to `.container-state/nix-proxy`, and the main container mounts that directory rather than the socket file, so a restarted sidecar's new socket is seen and start order does not matter. Add `sandbox stop` (removes both containers) and document both in the header and README. Check with a stub `docker` on PATH in scripts/test_sandbox.py asserting the arguments, plus `bash -n`.
Determination: Confirmed against a stub engine only: scripts/test_sandbox.py (9 tests, passing) shows daemon mode passes `-d --restart unless-stopped` and no `--rm` to both containers, keeps the sidecar after the script exits, replaces an earlier daemon, cleans up a failed start, and `stop` removes both, while the ordinary modes stay `--rm`; no docker daemon runs in this environment, so a real reboot was not tried.

### W59.2 · Generate a systemd unit instead of using the engine restart policy
Status: parked
Approach: `sandbox daemon` would write a user systemd unit that runs the foreground sandbox, enabled with `systemctl --user enable`, so boot start does not depend on the engine's restart policy.
Determination: Parked: it adds a second supervisor and a systemd dependency, while docker's `--restart unless-stopped` already does this wherever the docker service is enabled at boot; take it up if the restart policy proves unreliable (e.g. rootless podman without podman-restart.service).

### W59.3 · Fix: a failed `sandbox daemon` start leaves the restart-policy sidecar running
Parent: W59.1
Status: confirmed
Approach: In daemon mode scripts/sandbox.sh starts the nix sidecar (`start_nix_proxy`, with `--restart unless-stopped` and no EXIT trap) and only afterwards can still fail, and only the final `docker run` failure calls `stop_daemon`. Two other exits leave the sidecar behind: `start_nix_proxy` itself, when the socket never appears (`exit 1` at the "did not come up" message, after dumping logs), and the `OLLAMA_SOCKET` check in `run_in_container` (`exit 1` when it is not a unix socket), which runs after the sidecar is up; any `set -e` abort between them does the same. The orphan then survives the script, restarts at every boot, and holds the `.container-state/nix-proxy` directory, with nothing but a later `sandbox stop`/`daemon` to remove it (ordinary modes are cleaned by the trap, so this is new with daemon mode). Fix: in daemon mode make every failure after the sidecar starts call `stop_daemon` (e.g. a `trap` set in the daemon branch that removes both containers unless the start succeeded, cleared once the main container is running, or call `stop_daemon` before those two `exit 1`s). Settle with test_sandbox.py cases using the stub engine: one where the socket never appears (stub that does not bind it; shorten the 50x0.2s wait if needed) and one with `OLLAMA_SOCKET` set to a non-socket, each asserting the last engine call is `rm -f app-dev app-dev-nix` and the exit status is non-zero.
Determination: Confirmed: start_nix_proxy now sets `trap stop_daemon EXIT` in daemon mode and run_in_container clears it once the main container is running, so every failure in between (sidecar socket never appears, a bad OLLAMA_SOCKET, the main `docker run`) removes both containers; two new tests in scripts/test_sandbox.py fail on the old script and pass now (11 tests passing), against a stub engine as before.

### W59.4 · Minor findings from the review
Parent: W59.1

Approach: README.md "Running the sandbox as a daemon": the last sentence of the paragraph ("Running it again replaces the daemon; ...") is a very long line, unlike the wrapped lines around it, and the example uses `docker logs <repo>-dev` although `CONTAINER_ENGINE` may be podman.
Approach: `sandbox daemon` passes `-d` but the header comment says "there is no terminal, so the agent modes are not daemons" while `exec`/`run`/`app` modes are not mentioned as unsupported; `sandbox daemon` with `CONTAINER_START_APP` never starts the background app, which the header does not say.
Approach: test_sandbox.py `test_the_sidecar_survives_the_script_and_a_reboot` asserts the no-trap property with a convoluted filter that cannot fail if the rm uses another name; assert directly that no `rm` call follows the main `run`.
Approach: daemon mode wipes `.container-state/nix-proxy` and the sidecar on every start; `sandbox stop` leaves the (empty) `.container-state/nix-proxy` dir behind, and the sidecar's stale socket is relied on being unlinked by `nix daemon` on restart (true of nix's socket creation, but unchecked here).
Determination: Confirmed: README wraps the long sentence, notes podman for logs and that only `daemon` is detached; the header says the same and that the background app is not started; the sidecar test asserts the main run is the last engine call; `sandbox stop` now also removes `.container-state/nix-proxy`, tested; the stale-socket reliance on `nix daemon` unlinking is written down in a comment, not exercised (no real nix daemon here). The tree is complete and the Goal is met against a stub engine.
