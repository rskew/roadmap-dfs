# W45 · Show the logs of runs

## Goal

Show the logs of runs

## Tree

### W45.1 · Show a task's run logs on the web page
Status: confirmed
Approach: Treat "show the logs of runs" as the web page's gap: a task's page lists the runs of its work chains and opens any one's log. The terminal screen already does this (`l` opens a run's console and agent transcript), so it is left as it is.
Hypothesis: The web page is the surface the Goal means, and "logs of runs" are the chain runs under `.dfs/runs/*/console.log` for a task. Wrong if the author meant the terminal screen's log pane, or the chat logs. .dfs/artefacts/a75b5cb1-8b86-4371-983b-4d167ac68911.html
Evidence:
- for: `grep` of `scripts/tui.py` finds the `l` run-log pane (console and agent transcript); `scripts/web.py` has no route that reads a run directory and `scripts/web/index.html` has no runs section, so the web page shows no run log at all.
- for: `scripts/runs.py` `run_dirs()` already gives each run's item, run number, state (live, finished, stopped, unknown), start, stop reason and `console.log` path, so the web side needs only to serve it.
Determination: Confirmed on the evidence that the web page is the only surface without run logs; the author can still refute it on the page.

### W45.2 · Serve a task's runs and a run's log from web.py
Parent: W45.1
Status: confirmed
Approach: In `scripts/web.py`, add `runs` to `task_json` (this task's `runs.run_dirs()` entries, newest first: name = the run directory's basename, state, run/cap, mode, started, finished, stop, peak, turns) and a GET `/api/run/<name>?tail=<n>` that finds the directory among `run_dirs()` by basename (never joins a path from the request) and returns its `console.log` tail with the byte offset, so a live log is followed by asking from that offset. Add the runs' `meta.json` mtimes to the page's change signature if missing. Tests in `scripts/test_web.py`: a fixture run directory appears under its task, its log tail is returned, a made-up or path-like name is refused with 404, a large log is cut to the tail.
Determination: Confirmed: `task_json` now carries `runs` (the task's newest 12 chains, by directory name and no path) and GET `/api/run/<name>[?from=N]` returns a log's tail from a line start, or what was written since byte N, holding back a live chain's half-written line and refusing any name that is not a run directory; four new `test_web` tests pass, and the rest of `test_web` passes but for the chat test, which fails here without the change too.
