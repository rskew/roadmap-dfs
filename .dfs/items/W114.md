# W114 · Bug reports

## Goal

roadmap-dfs f9d0b9b: two stops of the walk, three defects

1. A killed walk leaves the task file empty (W118, Oct 23)
run.sh W118 14 started run 5, the implementation review, at 11:52:37 UTC. Within the same second, .dfs/worktrees/W118/.dfs/items/W118.md was truncated to 0 bytes and run-5.json stayed empty.
No died or hold line was written. meta.json still says open for a pid that is gone, and the TUI restarted in a new container on Oct 24.
With the empty file, state.py reported "no nodes yet — plan the task". A restart would have planned W118 from scratch over a finished 96-line tree.
Cause: tree.py rewrites task files with p.write_text(render(t)) in compact, shelve, append_log, edit_task, delete_node, edit_node, start_node and add_node. That call truncates and then writes, so a kill in between leaves an empty file. A full disk is unlikely, since 289 GB was free. I don't know which of those functions was running, or what killed the process.
Fix suggested: write through a temp file in the same directory and os.replace it, as runs.py and agent.py already do. This applies to the archive and order.md too.
Work-around used: git checkout -- .dfs/items/W118.md in the worktree restored the file from the branch HEAD. Anything the review had written but not committed was lost.

2. A walk killed with its supervisor leaves no record
died and hold lines come from the supervisor, so when it dies too, nothing records the end and nothing restarts the walk.
Fix suggested: on start, the TUI closes any meta.json that is open while its pid is dead, with a died line saying the supervisor was lost.
Fix suggested: on start, run.sh refuses a task file that is empty while the branch HEAD has a non-empty version.

3. A new task's first walk refuses to start (W127, Oct 25)
run.sh W127 12 stopped at 15:21:47 UTC with "a session could not be briefed: the worktree … has no .dfs/items/W127.md … the branch carries only what git tracks".
A task created from the TUI or chat is written to .dfs/items/<task>.md but not committed. Its worktree is cut from git, so the file is missing. W117 and W118 hit the same problem and were fixed by hand in 2b5b4d6.
Fix suggested: creating a task commits its file and its place in order.md. Failing that, branch.py enter copies untracked task files into the new worktree, or commits them, instead of stopping the walk.
Work-around used: I committed the file on main as 03fe0bc and removed the empty dfs/W127 worktree and branch so the walk recuts them.

## Tree

### W114.1 · Write task files, their archive and order.md through a temp file and os.replace
Status: confirmed
Approach: Add `paths.write_atomically(path, text)` (a temp file from `tempfile.mkstemp` in the same directory, flushed and fsynced, then `os.replace`), and use it for every rewrite of a `.dfs` planning file: the `p.write_text(render(t))` calls and the archive writes in `tree.py` (`compact`, `shelve`, `append_log`, `edit_task`, `delete_node`, `edit_node`, `start_node`, `add_node`, new parts and new tasks), `order.py`'s `write`, and the TUI's order undo. A `test_tree` test makes `os.replace` raise during each rewrite and checks the task file keeps its old text and no temp file is left; `test_tree`, `test_order` and `test_tui` pass.
Determination: Every rewrite of a task file, its archive, `order.md` and an author's edit put back after a merge now goes through `paths.write_atomically`: the new `AtomicWrites` test, with `os.replace` failing, finds all eight `tree.py` rewrites leave every `.dfs` file as it was (it fails on all eight with the old code) and a rewritten file keeps its mode, and `test_tree`, `test_order`, `test_web`, `test_screen`, `test_chain`, `test_ignored` and `test_walk` pass with TMPDIR inside the repo (two tests fail under the noexec /tmp before and after).

### W114.2 · run.sh refuses to start on an empty task file whose branch HEAD has text
Status: open
Approach: In `run.sh`'s briefing check (beside the missing-file cause), stop `brief` when `.dfs/items/<task>.md` in the checkout the chain works is empty or whitespace while `git show HEAD:<it>` is not, with a cause naming the file, the line count at HEAD and `git checkout -- <it>` to restore it, so `state.py` never reports "no nodes yet" over a finished tree. A `test_chain` test truncates a committed task file in the worktree and checks the chain stops `brief` with that cause and starts no session.

### W114.3 · The TUI closes a run left open by a dead process when it starts, with a died line
Status: open

A `test_tui` test starts the screen over such a run directory and checks the line and the closed record, and that a live chain's record is left alone.
