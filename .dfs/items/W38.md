# W38 · Complete items should include a screenshot if they affect the UI, and this should be shown on the item

## Summary

A task worker now decides for itself whether a screenshot of finished work is worth having: SKILL.md and docs/artefacts.md say it may embed one in the Summary, and nothing requires it, so the briefing line and `check.py` no longer demand one. The web page already draws a screenshot embedded in a Summary and lists it among the task's artefacts, and a test now pins that, so a screenshot shows on the item whenever one exists. The earlier mandatory rule and its check were taken out at the author's direction; the page's drawing of the image was not seen in a browser here, since none would start.

## Goal

Complete items should include a screenshot if they affect the UI, and this should be shown on the item

## Tree

### W38.1 · The rule: a finished task that changes what the user sees embeds a screenshot in its Summary
Status: confirmed
Approach: Write the rule where sessions read it: SKILL.md's Summary paragraph, the briefing line in `scripts/state.py` that tells the completing session what to write, and `docs/artefacts.md`. A task whose finished work changes what the user sees (a page, a screen, a layout) puts `![what it shows](.dfs/artefacts/<uuid>.png)` in its `## Summary`, since the Summary is what the item shows once done; a task that changes nothing visible needs none. A session that cannot take one (no browser) says `No screenshot:` and why in the Summary instead. Check: `state.py` briefing test still passes and the text reads in the briefing.
Ask: Should every finished task's Summary carry a screenshot or a `No screenshot:` line, or only those that touch UI files? I chose only the ones that touch UI files (the next node), so a task with no visible change says nothing.
Determination: SKILL.md's Summary paragraph, the briefing line in state.py and docs/artefacts.md now say a task that changes what the user sees embeds a screenshot in its Summary, or says `No screenshot:` and why; the briefing prints it.

### W38.2 · check.py refuses a Summary without a screenshot when the task touched UI files
Parent: W38.1
Status: confirmed

Tests in a new `scripts/test_screenshot.py` against a temporary git repo: UI task without a screenshot refused, with one accepted, `No screenshot:` accepted, non-UI task accepted, a missing file refused. The docstring in check.py lists the rule.
Determination: `check.py` now refuses a new or changed Summary that embeds no existing screenshot and has no `No screenshot:` line when the task's commits touched a UI file, and `test_screenshot.py` covers eight cases and passes.
