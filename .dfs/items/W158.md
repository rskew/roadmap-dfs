# W158 · tree.py start is lost when the task file is restored from git

## Summary

The started mark stays a working-copy hint that is lost when the task file is restored from git, and that is now accepted and written in `SKILL.md`. A log line was ruled out because it lives in the same file and is dropped by the same restore; committing the mark was left aside because it breaks one commit per node. The Goal was fully met; no tool code changed.

## Goal

`tree.py start <task> <node>` writes `Status: started` to the working copy and commits nothing, so `git checkout -- .dfs/items/<task>.md`, `git stash` or a rebase that restores the file drops the mark with no sign. A session cut off mid-node then leaves the next session without the signal that the node was begun. Found while working W153 (filed there as a draft, not fixed there; seen by earlier sessions of that task, not re-run when filing).

Goal: decide whether the mark should survive a restore (for example a line in the log, which only grows) or whether losing it is acceptable, and say so in `SKILL.md`. Show the case first: start a node, restore the file, and read the briefing.

Re-run on 2026-11-08 (W153.51): in a scratch repo, `tree.py start W900 W900.1` set `Status: started`, then `git checkout -- .dfs/items/W900.md` put `Status: open` back and the log held no trace of the mark. The case reproduces.
