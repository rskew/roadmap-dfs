# W22 · All the all-caps text, should be lowercase instead

## Summary

The web page and the terminal screen now show their labels, tabs, buttons and status words in lowercase: the CSS that forced capitals is gone and the all-caps words in the TUI (raise, walk, staged, missing) are written lowercase. The design notes describe lowercase labels. The Goal is fully met; internal data values such as a log entry's `RAISE` type are still capitals because they are compared in code and never shown. Some test suites already fail in this environment (a missing claude stub and curses errors), and they fail the same way with and without the change.

## Goal

All the all-caps text, should be lowercase instead

### W22.3 · Fix: the TUI footer no longer draws "w stop walk" in red
Parent: W22.2
Status: confirmed
Approach: `Tui.draw_footer` in scripts/tui.py (~line 3909) decides which footer labels are "loud" (drawn red and bold) with `loud = label.isupper()`; its docstring says "A capitalised label is a state that wants seeing (`w STOP WALK`)". W22.2 lowercased that label to "w stop walk" (~line 3747), so `isupper()` is now false for every footer label and the one state-is-on highlight (a walk is running) is silently gone. Settle it by giving the footer a signal that does not depend on capitals (for example `footer` returns the label with a marker, or `draw_footer` is told which labels are loud, such as `label == "stop walk"` when `self.walk_on`), draw "w stop walk" red again, and fix the docstring. Add a test that fails if the loud label is drawn in the chrome colour (a fake `puts` capturing the attrs), and run the TUI tests with and without the change as W22.2 did.
Determination: `draw_footer` now draws "stop walk" red while `walk_on`, via an explicit test not capitals, with the docstring fixed; the new test fails on the old code and passes now, and test_screen has the same 10 environment errors with and without the change.
