# W18 · Add under creates a sibling rather than a child

## Summary

"Add under" already stored the new node as a child of the node it was added under. What looked like a sibling was the tree view, which draws a node that is its parent's only child in its parent's column. Such a node now carries a `↳` before its id in the terminal screen and the web page, so it reads as a child; the layout is unchanged, so long chains still do not form a staircase. This was checked in tests and by reading the page code, not in a browser, since none runs in this environment.

## Goal

Add under creates a sibling rather than a child

## Tree

### W18.1 · Find where "Add under" can produce a sibling
Status: confirmed
Approach: Follow "Add under" from the web sheet (scripts/web/index.html addForm → web.py `add` → tree.add_node) and the TUI `i` key (tui.py tree_add → add_node), and add children by hand to a copy of W17 with `tree.py add`, reading back each stored `Parent:` and each drawn row.
Hypothesis: The "sibling" is how the tree is drawn, not what is stored: tui.tree_entries puts a node that is its parent's only child in its parent's column (the fork-only indent), so a child added under a childless node looks like its sibling. Wrong if a stored `Parent:` is ever not the node the author added under, or a browser path sends a different parent.
Evidence:
- for: `tree.py add W17 W17.9 ...` and `... W17.3 ...` on a copy of W17 wrote `Parent: W17.9` and `Parent: W17.3`; test_web's /api/add test and test_tree's add_node test pass with the parent kept.
- for: tui.py `walk` recurses with `d + (1 if len(kids) > 1 else 0)`, and test_review_tree asserts a chain W1.1 → W1.2 → W1.3 is drawn at depth 0 for all three, so a lone new child has its parent's depth in both the TUI and web (web `--d:${r.depth}`).
- against: I could not drive the web page: chromium fails to start here (glibc mismatch) and no playwright, so the sheet's click path was read, not run.
Determination: Confirmed: every path stores the child under the node it was added under; the only thing that reads as a sibling is a lone child drawn at its parent's column.

Determination: Confirmed: tree_entries rows carry `chain`, the TUI draws `↳` before such an id and the web list before its `.nid`; new tests in test_review_tree and test_web pass, `i` on W1.3 passes parent W1.3 to add_node, and the one test_web failure (chat) and ten test_screen errors are the same with the change stashed.
