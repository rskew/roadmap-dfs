# W86 · Use a high res icon for loading screen in installed pwa

## Summary

The web manifest now lists 1024px icons, `any` and `maskable`, beside the 512px ones, so any screen that asks for a larger icon gets a sharp one. The Goal was not met: the soft picture on the author's phone is Android's own launch screen, which draws a launcher icon Chrome builds itself when it installs the app, and after a reinstall it looked the same. Nothing in the manifest changes that, so the task closes as out of reach; the 1024px icons stay since they are harmless.

## Goal

Use a high res icon for loading screen in installed pwa

## Tree

### W86.1 · List 1024px icons in the manifest for the installed app's splash
Status: refuted
Approach: Render `scripts/web/icon.svg` with headless Chromium (playwright) to `icon-1024.png` and `icon-maskable-1024.png` at 1024x1024, list both in the `/manifest.json` icons in `scripts/web.py` (`any` and `maskable`) and in its `STATIC` table, and extend `test_web.py`'s installability test to require a `purpose: any` icon of at least 768px and each icon's PNG to be the size the manifest claims. Built, uncommitted, while the raise on which loading screen looks soft is open: `test_web` runs 88 tests OK, and the new assertion fails against the old manifest.
Hypothesis: Chrome's own splash on the author's phone asks for an icon wider than 512px (Chromium's `webapp_splash_image_size_ideal` times the screen's density), so it scales today's 512px icon up, and a 1024px icon is scaled down instead. Wrong if that ideal is still 128dp, which 512px covers up to a 4× screen, or the soft picture is Android 12's own launch screen, the launcher icon in a circle, which the manifest's splash icon does not draw, or the drawing is sharp but small. .dfs/artefacts/2d113cbe-bd9e-4988-89fa-faf2faf50f2b.html
Evidence:
- for: `file scripts/web/*.png` shows the largest manifest icon is 512x512, so any splash that asks for more than 512px scales it up.
- for: README's "The web page on a phone" and the page's `NO_INSTALL` note speak only of Chrome on Android, so the loading screen meant is Android's, not an iPhone startup image.
- against: Chromium's `WebappsIconUtils.java` (main, fetched 2026-10-19) sizes the splash image from `webapp_splash_image_size_ideal`, and the only value found for it, quoted from `chrome/android/java/res/values/dimens.xml` in Lighthouse issue #291 (2015), is 128dp: 512px at 4×, so no phone would scale the 512px icon up. Its current value was not found.
- against: two web searches found no source for a 192dp splash size, the figure this Hypothesis first rested on from memory.
- against: the author's screenshot, ![the launch screen on the author's phone: the drawing alone in a grey circle on paper, soft edges](.dfs/artefacts/7e9dd912-582d-4e6d-ab36-28f9de92e530.png), is Android 12's launch screen (the icon alone in a circle, no name under it), not Chrome's splash, so the soft picture is the one the manifest's splash icon does not draw.
Determination: Refuted: the soft picture is Android's launch screen, which draws the launcher icon Chrome builds from the maskable icon, not the splash icon this node enlarged; the 1024px icons stay, since the 1024px maskable one is the only lever the manifest has on that screen and the rest costs 22 KB and breaks nothing.
