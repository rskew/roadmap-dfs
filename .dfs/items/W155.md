### W155.2 · Keep a claude-only model name out of a kiro walk
Parent: W155.1
Status: open
Approach: **The question**
- The model drop-down for a kiro walk takes a typed name ("Other") and `walk.set_model` saves any name that looks like one. Should a kiro walk refuse or flag `opus`, which kiro-cli rejects when the session starts?

**Why it matters**
- `opus` is the name the claude agent shows and the one the author asked for. Saved under kiro, the next chain starts, kiro-cli fails, and the walk stops as `failed` with kiro's raw error.

**What this node does**
- In `scripts/walk.py` `set_model`, for the kiro agent, compare the name with `kiro_models()` (the list from `kiro-cli chat --list-models`, else `MODEL_CHOICES["kiro"]`). Say in the refusal which kiro names exist.
- Cover it in `scripts/test_walker.py` and `scripts/test_web.py`; show the refusal text on the page (`scripts/web/index.html` already toasts a 409).
- Write a Hypothesis with its answer page when the node starts, since refusing a typed name is a choice the author may want the other way (warn, or map `opus` to `claude-opus-5.5`).

**How we will know it worked**
- A test that saves `opus` for kiro and sees the refusal, red before the change; a real name and any name while the list is unreadable still save.
