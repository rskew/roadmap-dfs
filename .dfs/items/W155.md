# W155 · Error 502 when selecting opus as the implement model for walk

## Summary

I could not find where the 502 came from. Choosing a model through a real server answers in JSON every time (2688 requests, none a 502 or dropped), and the page shows "error 502" only for a failed reply that is not JSON, which web.py never sends, so it most likely came from a proxy in front of it. What I changed is that a kiro walk now refuses claude-only names such as `opus` (kiro-cli rejects them when the chain starts) and lists kiro's models. A short-lived idea that the walk should retry a session when the model service answers 5xx was removed, because nothing showed it was needed and the walk's agent is kiro. The Goal is not shown to be met: where the 502 appeared is a fact only the author has.
