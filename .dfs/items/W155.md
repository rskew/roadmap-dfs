# W155 · Error 502 when selecting opus as the implement model for walk

## Summary

I could not reproduce a 502 on the page: choosing a model through the real server is fast and clean for claude, and for kiro it saves its own ids. What I found and fixed is that a kiro walk accepted claude-only names such as `opus`, which kiro-cli rejects when the chain starts; it now refuses them and lists kiro's models. A session that dies because the model service answers 5xx used to stop the whole walk with no mention of the status; it is now run again up to two times (20 s apart), and if it keeps failing the stop says "the model service answered 502". The Goal is met as far as it can be shown here, but a real claude session and a real 502 were not available, so that the report came from the model service is assumed, not seen.
