# W140 · Reorder tasks should not be so big in y axis

## Summary

In the web page's Reorder list, each task row is now much shorter. The goal and the status tags take one line each, the reason line is left out, the padding is halved, and from 600px wide the move buttons sit in the same row as the text and the grip. Every move button and grip is still 44px, so taps are as easy as before. This was checked on a static copy of the row in headless chromium, not in the full page: the browser flows in `scripts/ui_flows.mjs` could not run here because there is no node or playwright.

## Goal

Reorder tasks should not be so big in y axis

## Tree

### W140.1 · Make the web Reorder rows short
Status: confirmed
Approach: **The question**
- How do we make each row in the web page's Reorder list take far less height without making any button smaller than a thumb target (44px)?

**What this node does**
- In `scripts/web/index.html`, only for `.item.reorder`: trim the padding to `var(--s2)` above and below. Show the goal on one line with an ellipsis. Keep the status and tags on one clipped line. Hide the reason line (`.why`). Keep `.pending-tag` ("saving…") visible.
- From 600px wide, put the moves strip in the same row as the text and the grip, so a row is one 44px line plus padding. Under 600px the moves stay under the text, in one line.

**How we will know it worked**
- A static page with the real `design.css` and the page's CSS, drawn at 360px and 1000px in headless chromium, gives the row heights before and after. Every `.moves .btn` and `.grip` is still at least 44px.
Hypothesis: "Reorder tasks" means the Reorder list of the web page (`data-act=reorder`, rows with `.moves` and `.grip`), and "big in y" means each row is too tall. Wrong if the author meant the TUI's reorder or something else. .dfs/artefacts/29494370-e4db-4a6f-924c-f872ab702df9.html
Evidence:
- for: the only place that names reordering in the UI is `drawTasks` in `scripts/web/index.html`; its reorder row has a wrapping goal, a wrapping tags line, a reason line and a 44px moves strip under them, with 12px padding above and below.
- against: the goal text does not say which UI; the TUI (`scripts/tui.py`) also has `reorder`, but it is a key press (`[` and `]`) on the ordinary list, with no separate view whose rows could be too tall.
- for: headless chromium on a static page with the real `design.css` and the page's CSS, two rows (one long goal with three tags and a reason, one short): at 360px the rows were 242px and 135px high before and 115px and 111px after; at 1000px 191px and 135px before and 67px and 63px after. The smallest move button or grip stayed 44px. At 600 and 720px the rows are 67px and 63px. ![the compact rows at 640px wide](.dfs/artefacts/8ade530e-76d1-48c5-a61a-60208406dde7.png)
