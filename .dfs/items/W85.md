# W85 · Raise artefacts shouldn't follow a strict template, they should be free to express their issue in the best way, focusing on elucidating the key mechanisms and implications at different options, as well as showing the mechanisms of relevant parts of the system. Emphasis on showing visually. Raise artefacts should have a form that submits the answer though.

## Summary

A raise's answer page no longer starts from a fixed "it holds / it does not" layout: the template is now an empty page with only the answer form at its foot, and the skill and the artefact guide tell a session to draw the issue freely, showing how the relevant part of the system works now, each option as a change to that drawing, and what follows from each, with drawing first and prose as captions. The form is self-contained, sends the chosen option and the author's note as the answer (or as a confirm or refute on a node), and a raise is now refused if the page it names has no working form. The Goal is met; the same freedom was also given to the page a Hypothesis names, which the Goal did not mention, so there is one kind of answer page rather than two. .dfs/artefacts/4b782c16-52b7-4bed-9e79-8295b9a03279.html shows the choice and is itself built the new way.

## Goal

### W85.6 · Fix: the shared answer form's ids clash with the free page above it
Parent: W85.1
Status: confirmed
Approach: templates/_TEMPLATE_ANSWER.html's form script looks its parts up by bare document-wide ids (`document.getElementById` on `note`, `answer`, `confirm`, `refute`, `park`, `parkbox`, `parks`, `answerbox`, `rulebox`, `answer-status`, `rule-status`), and getElementById returns the first match in the document, which is the page's own element whenever the page above uses the same id. docs/artefacts.md says the form "needs nothing above it, so the page around it is yours", and pages here often draw the answer and confirm flow itself, so such ids are likely. Checked in headless Chromium: the template copied with `<div class="box" id="answer">` and `<p id="note">` above the form, the form's own "Send as my answer" button does nothing (status stays empty, the handler went to the div), while the unmodified template reports "Not recorded: no server"; with `id="note"` on a non-input above, said() would throw on `.value.trim()`. tree.can_answer and check.py pass such a page, so the raise is accepted and the author cannot answer from it. Fix by scoping the form: give its parts `dfs-` prefixed ids or look them up inside `#dfs-answer` (`section.querySelector`), update the ui_flows.mjs flows (template_answer, park_page) and test_templates.py's stands-alone test to match, and add a test that a page with clashing ids above the form still answers (a ui flow, or a test_templates check that every id the form uses is `dfs-` prefixed).
Determination: Every id in templates/_TEMPLATE_ANSWER.html's form now starts with `dfs-` and its radio lookup is scoped to `#dfs-answer`, so a page drawn above it can use `answer`, `note`, `confirm` or `rulebox` freely; the new test_ui flow with those ids above the form goes red on the old template (waitFor timeout) and green on the new one, test_templates now refuses an unprefixed id, template_answer and park_page pass with the new ids, test_web, test_tree and test_critic pass, and artefact_check reports the template clean, so the node is confirmed.
