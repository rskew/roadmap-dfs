# W124 · chat should work with kiro and codex and opencode and claude

## Summary

Chat now works under all four agents at their current pinned versions: codex, claude and kiro-cli already passed their live chat tests, and opencode 2.1.1 was fixed to read its new session store, accept its stream, and run each turn on a private server so scratch homes do not collide. opencode's private server sometimes crashes in Bun (a bug in opencode's runtime, not in this code), so a headless turn is run again when it ended before it began, and the tests restart a screen whose server was lost and read the page's state at the web page's pace; under heavy host load the live opencode chat test passed 7 of 7 full runs, so the crashes are survived and not prevented. A stopped or timed-out opencode turn removes its temporary files, and a message the author resends after a turn that stored no answer is shown once. Left for the author: whether the screen's opencode should always run on a private server for real use (a TUI whose server crashed still hangs, with no recovery outside the tests), whether the crash really needs the tests' fast polling and conversations stored by opencode 1.x need no support, and the live opencode, codex and claude tests were not rerun in the final sessions for lack of binaries.

## Goal

chat should work with kiro and codex and opencode and claude

### W124.3 · find why opencode's turn sometimes reports the model's socket closed

Status: confirmed

Live test_opencode_chat.py still failed 4 of 8 runs after that, with no crash and no retry in those runs, from a different fault.

### W124.6 · Fix: opencode_turn leaves its temp files behind when the turn is stopped or times out
Parent: W124.5
Status: confirmed
Approach: scripts/run.sh `opencode_turn` writes the stream and stderr of each `opencode run` to two `mktemp` files and removes them only on its last line (`cat "$err" >&2; cat "$out"; rm -f "$out" "$err"`), with no `trap`. chat.py's `run_turn` ends a Stop or a 10-minute timeout with SIGTERM to the whole process group (then SIGKILL), which kills the bash function before that line, so every stopped or timed-out opencode page turn (and the screen's opening turn) leaves both files in $TMPDIR for good, the stream file holding the whole conversation text; before W124.3 the stream went down a pipe and left nothing. Add `trap 'rm -f "$out" "$err"' EXIT TERM INT` (set after mktemp, cleared before the final cat/rm) or keep the files in a directory run.sh already cleans, and add a test_chat.py case that starts `--chat-turn` with the opencode stub made to sleep, SIGTERMs the process group, and asserts no new file is left in the test's TMPDIR. Check: test_chat.py.
Determination: opencode_turn in run.sh now removes its stream and stderr files on EXIT and exits 143 on TERM, INT and HUP, so a Stop or a timeout leaves nothing in $TMPDIR; the new test_chat case stops a sleeping opencode turn and finds the temp dir empty (it fails without the trap, leaving two files), and test_chat passes (63, rerun with TMPDIR inside the worktree as /tmp is noexec here).
