Status: confirmed
Approach: The chat stack (chat.py readers/result parsers, run.sh --chat/--chat-turn) was written to agent versions the nix store has since bumped: codex 0.163.0 (code says 0.162.0), opencode 2.1.1 (code says 1.18.35), kiro-cli 2.31.1 (code says 2.27.1), claude 2.1.x. The per-agent live tests (test_{claude,codex,kiro,opencode}_chat.py) and test_agent_interrupt.py discover their binary by a version-pinned /nix/store glob, so the stale pins skip the agents that changed. This node reads the Goal "chat should work with kiro and codex and opencode and claude" as: the existing chat feature runs a turn and reads the transcript under each agent's current pinned version, measured by the per-agent chat tests.
Determination: codex 0.163.0, claude 2.1.311 and kiro-cli 2.31.1 pass their live chat tests as they are (and test_agent_interrupt passes); only opencode 2.1.1 fails, three of three tests, from three faults: opencode_turns, opencode_exists and the updated-time query in chat.py read the dropped `session`/`message`/`part` tables (2.1.1 keeps `session_v2` and `session_message`, whose `data` holds the text as `content: [{type: text, text}]` and a `type` of user/assistant/idle); `opencode run --format json` ends without a `step_finish` event in 4 of 5 runs, so opencode_result calls a finished answer an error; and `opencode run` now starts a managed `serve --service` on fixed port 49374 that outlives the turn, so a second run under another HOME exits 1 with "port already in use" and the tests' scratch HOMEs collide. The version pins in the tests' binary globs (codex-0.162, opencode-1.18) are stale but only skip, never fail.
