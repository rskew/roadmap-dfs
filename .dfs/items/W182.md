# W182 · Add task should be a plus button in the bottom right above the bottom row rather than in the bottom row

## Summary

Add task is now a plus button floating at the bottom right, just above the bottom tab bar on phones and with nothing under it on wide screens. The "Add task" tab is gone from the bottom row, and the button's accessible name is "Add task". The page-source test passes (the other five `test_web` failures were already failing). A headless chromium screenshot of the real page shows the button at the bottom right on both sizes. The browser flows could not run because `node` is not installed, so the new wide-screen check in the `newtask` flow, the other phone flows and the badge cover on a scrolled phone list were not run or seen. The wide screen also got the plus (its old "Add a task" text button is gone) and the phone again risks covering a row's badges; both are open for you to rule on.

## Goal

Add task should be a plus button in the bottom right above the bottom row rather than in the bottom row

### W182.4 · Fix: the plus button covers a row's drag grip in reorder mode on the phone
Parent: W182.1
Status: confirmed
Approach: In `scripts/web/index.html`, `drawTasks` adds the `.fab` button after the rows in every view of the list, reorder mode included. Before W182.1 the phone hid it (`@media (max-width: 899.98px) { .fab, .fab-gap { display: none; } }`), so no phone row ever scrolled under it. Now it is `position: fixed` at `right: var(--s4)`, 52px wide, on every width. In reorder mode each row has a `.grip` button (width `var(--hit)`) at the row's right edge (`.item.reorder .grip`, grid column 4). So a row whose grip scrolls under the plus has its grip covered: a tap or a press on it lands on the plus and opens the Add task form instead of starting a drag. The up and down keys still work, a touch user's only way to drag is lost for that row until it scrolls clear. Wide screens had the same cover before, which is why `reorderbreakdrag` in `scripts/ui_flows.mjs` uses a 1400px-tall phone "so no grip lies under Add a task"; the phone flows `reorder*` that use the normal `PHONE` viewport (the drag at `ui_flows.mjs` ~1344, ~1393 and ~2062) can now be blocked the same way. Check: open the list in reorder mode in headless chromium at 390x700, scroll so a row sits at the bottom right, and use `document.elementFromPoint` at that row's grip centre; it returns the `.fab` today. Fix: do not draw the plus (and the `.fab-gap`) while `S.reorder` is on, since you are ordering rows and not adding one, or keep the grip clear of it; then add that check to the `newtask` or a reorder flow (`elementFromPoint` at the last visible grip is not the plus) and a page-source assertion in `test_web.py`. Run `python3 -m unittest test_web` and say if `node` is missing for the flows.
Determination: The plus button and its gap are no longer drawn in reorder mode, so nothing covers a drag grip; the page-source test passes, and the `newtask` flow check could not run here (no `node`).
