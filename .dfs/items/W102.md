# W102 · don't put the task or node details in each commit message, just the merge commit for each task

## Summary

The merge commit that lands a task's branch now has a body: the task's title, its Summary and one line per node with its status and Determination. Node commits carry no such body on a branch, and the gitignored-roadmap rule that asked for the node's `Parent:`, `Status:` and `Determination:` lines in each node commit now applies only to an item worked in place, which has no merge commit. The node ids at the start of commit subjects stay, because the law requires them and the tooling finds a node's commits by them; removing them is a change only the author can make.

## Goal

don't put the task or node details in each commit message, just the merge commit for each task

## Tree

### W102.1 · The merge commit carries the task's details, and node commits carry none
Status: confirmed
Approach: In `scripts/branch.py` `merge`, give the `--no-ff` merge commit a body built from `tree.load(task)`: the task's title, its `## Summary`, and one line per node, `<id> · <title>: <status>. <Determination>`. In `SKILL.md` "When `.dfs/` is gitignored" and `scripts/state.py` `_ignored_note`, remove the rule that every node commit's body carries its `Parent:`, `Status:` and `Determination:` lines. Keep that rule only for an item worked in place, which has no branch and so no merge commit. Check: a `scripts/test_chain.py` case asserts the merge commit's body, and test_chain, test_init and test_state pass.
Hypothesis: By "task or node details" the author means the node fields a gitignored roadmap tells each node commit's body to carry (`Parent:`, `Status:`, `Determination:`), and wants the whole task's details in the merge commit instead. The node id at the start of each subject stays, because §0 requires it and `tree.py` `node_commits` finds a node's commits by it. Wrong if the author also wants the ids out of the subjects, or wants the merge commit left without a body. .dfs/artefacts/7f10e1dc-e7d7-46bf-81d3-7d3210a50f79.html
Evidence:
- for: nothing in the Goal asks for ids out of subjects, and `tree.py` `node_commits` needs the prefix, so the reading that keeps them is the narrower one that works.
Determination: Confirmed: the merge commit's body now carries the task's title, Summary and a status and Determination line per node, SKILL.md and the briefing's gitignored note limit the node-commit body rule to an item worked in place, and test_chain (a new merge-body case), test_init and test_ignored pass.

### W102.2 · Drop the task and node ids from every commit subject too
Status: parked
Approach: Commit subjects would name no task or node, and only the merge commit would say which task the branch was.
Determination: Parked: §0 says a node ends with a commit whose subject starts with its id, and `tree.py` `node_commits` finds a node's commits (and the briefing finds a refuted node's commits to revert) by that prefix, so taking it out is a change to the law that only the author can make.
