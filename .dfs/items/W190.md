# W190 · The in app chat seems to go out of sync when things like limits are hit, it just hangs and does nothing with a new message

## Summary

A page chat that runs as a background claude on the terminal screen now notices when claude stops at its usage-limit menu. The chat state reports the limit and its reset time, so the page shows its limit line, and the next message gets an Esc first so claude submits it and answers that the limit is hit, instead of the message being lost in the menu. The menu and claude's limit wording are read as text with spaces and cursor moves ignored, since the real chat logs show claude drawing its blank cells that way. The limit is dropped again once claude has answered a message and gone quiet without saying it is still at the limit, so a reset time in a zone the code cannot read, or a limit lifted early, no longer leaves the line up. The Goal was met for claude's background chat, the one a real chat log showed hanging; this was checked with stubs that draw the menu text, not with a real claude at its limit, and no raw capture of claude's output was available, so how it spaces the menu's words is inferred from two chat logs. A different limit wording would drop the limit line too early (the message still reaches claude). A limit menu in codex, opencode or kiro background chats is not read, since none was seen, and headless page turns already reported a limit before this.

## Goal

The in app chat seems to go out of sync when things like limits are hit, it just hangs and does nothing with a new message
