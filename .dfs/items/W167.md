# W167 · tui should have a chats menu

## Summary

The terminal screen now has a chats menu: `T` (or `:chats`) opens a pane listing every conversation, in progress first and archived below, with each one's agent, state, message count and last message. Enter opens the chat under the cursor, including an archived project chat, which is resumed and no longer cleared (only `C` starts a new project chat). E archives the chat, and says so when it is already archived. The Goal did not say what shape the menu takes, so it is a full pane like the runs and artefacts panes, not a small pop-up; the pop-up is kept as a parked alternative.

### W167.3 · Fix: Enter on an archived project chat in the chats pane wipes the conversation
Parent: W167.1
Status: confirmed
Approach: In `scripts/tui.py`, the chats pane's Enter calls `open_chat(scope)`. For scope `project`, `open_chat` first calls `Chats.renew_ended`, and that calls `Chats.clear`. `clear` unlinks the chat's record and removes its steering dir. So pressing Enter on the archived `project` row in the pane does not open that conversation. It deletes it from the Chats list and starts a new one, with no question asked. The pane's own help says "enter opens one" and the footer says "⏎ open", so a user reading the archived project chat loses it. `C` is meant to start a new project chat, but the pane is meant to open the chat under the cursor. Fix: in the pane, open an archived project chat so it is read and resumed (as an archived task chat is), without `renew_ended`; for example give `open_chat` a flag to skip the renew, or call `start_chat` directly from the pane. Keep `C` as it is. Add a test in `scripts/test_screen.py` that an archived `project` row, opened with Enter, leaves `Chats.clear` uncalled (the test must fail on the current code). Check the footer and the `KEYS` text for Enter still say what it does.
Determination: Confirmed: `open_chat` takes `renew=False` from the chats pane, so Enter on an archived project chat opens it and no longer calls `Chats.clear`; the new test fails without the change and passes with it.
