# W42 · How are uncommitted changes attributed? They show on many items

## Summary

An item's "uncommitted" tag is now attributed by what changed in its task file. Changes outside the log read "edits"; log entries other than the runner's own session and end lines read "log"; and the runner's lines alone tag nothing, since one chain writes them to every task it runs and only a node commit of that same file takes them. A review's notes still show, labelled as log entries, so items holding only those stay tagged; whether such notes should show at all was my choice, and the node states it so the author can reverse it.

## Goal

How are uncommitted changes attributed? They show on many items

### W42.2 · Tag a task uncommitted by what changed, not by whether its file differs
Parent: W42.1
Status: confirmed
Approach: `tree.uncommitted` now returns {task: "edits" | "log"} by comparing each modified task file with HEAD: a change outside `## Log` is "edits", a change to log entries other than the runner's `session` and `end` lines is "log", and the runner's lines alone tag nothing. A new or staged file is "edits". `state.py`, `web.py`, the web list ("uncommitted log entries") and `tui.ahead_cell` (`log` beside `edits`) carry the word through; `test_unpushed` pins the four cases.
Hypothesis: The author wants the runner's session and end lines to stop tagging a task, while a review's notes or a raise left uncommitted still show, labelled as log entries and not as node work. Wrong if the author wants every touched task tagged, or wants notes hidden too (so W40 and W41, which hold review notes, would stop showing). .dfs/artefacts/f68fc503-68af-477d-ab97-95d728e6f306.html
Evidence:
- for: Before the change `tree.uncommitted()` named W40, W41 and W42; W40 and W41 differ from HEAD only by session, end and review lines.
- against: After it, W40 and W41 still show, as "log", because a review note is not a runner line; the fix narrows the tag and labels it and does not clear it. The page's text did not render in this browser (no fonts); its checker passed.
Determination: Confirmed: runner lines no longer tag a task, a log-only change is labelled as that, and test_unpushed and the other suites pass but for test_web's chat test, which fails here without the change too; so the Goal's question is answered and met on this reading.
