# W93 · Make the tests faster

## Summary

`python3 scripts/test_all.py` now runs the suite in parallel on every core and takes about 115s for the 978 tests that run on current main, against about 870s module by module for the 893 it had when this began; duplicate and over-long tests were pruned or cut (the chain tests and a few real-agent ones), the load-sensitive waits in the pty relay and browser tests were fixed, and the runner keeps only this tree's remembered times, names any test class that skipped itself (no playwright leaves the 60 browser flows unrun), fails if a test writes under `scripts/.dfs`, and kills a timed-out shard's whole process group. The 15 tests that start a real agent CLI (opencode, codex, claude, kiro) are no longer in the default run: `--real-agents` runs them one shard at a time after the parallel pass, and naming one of their modules runs it. The Goal's speed work is met; the real-agent tests still fail now and then on opencode's own start-up hangs and SIGBUS kills on this machine, so that hardening, including why a page turn can leave its message out of opencode's database, was left for a task of its own, which only the author can order.

## Goal

Prune low value tests, make tests more targeted, and parallelise where possible
