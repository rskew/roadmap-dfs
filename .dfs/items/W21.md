# W21 · Require assumptions to create an interactive artifact to explain and decide an assumption

## Summary

A node that states a Hypothesis now has to name an interactive page for it, `.dfs/artefacts/<uuid>.html`, which explains the assumption and lets the author operate it to decide. SKILL.md and docs/artefacts.md say so, templates/_TEMPLATE_ASSUMPTION.html is the starting page, and check.py refuses a commit that adds, changes or reopens a Hypothesis without a page that exists and has a control with a handler on it; it judges nothing already committed and nothing in a merge commit. A page is served sandboxed but may reach one route on the server, `/artefact-state/<itself>`: there it keeps what the reader chose, so it reopens as they left it, and the page a raise names on an `Answer with:` line records the answer itself, which closes the web page's answer form. The Goal is met; the check cannot judge whether a page says anything, and the cost of letting pages post is that a sandboxed frame on another website that knows such a page's file name could answer its raise while it is open (shown in `.dfs/artefacts/18eba8fa-4d3c-4840-8d95-48f095cec428.html`).

## Goal
