# W89 · Tell the author when the project's ignore rules hide roadmap files

## Summary

The tool now notices when a project's ignore rules keep part of the roadmap out of git. `init` asks git which roadmap files it would refuse to add and names the ignore file, line and pattern responsible, making that the next thing to fix; the same report is printed when a work chain starts, and the screen's header shows `git hides .dfs` with the rule spelled out under `h`. A roadmap kept on purpose by a rule naming `.dfs` (`.dfs/`, `.dfs/*`, `.dfs/**/*`, `**/.dfs/` and the like), in the project's `.gitignore`, `.git/info/exclude` or the global excludes file (`core.excludesFile`, or git's default `~/.config/git/ignore`), with git ignoring the roadmap and nothing in it tracked, stays the supported planning-only setup and is not reported, even when a broader rule such as `.*` also matches. A broader rule on its own, such as `.*` or `*.html`, or files force-added past a `.dfs/` rule, is reported. Untracked files git would add are not reported, since they are commits not yet made, and only the roadmap's own parts are checked, so a cache inside `.dfs` is left alone; `.dfs/artefacts/ff4032ac-938c-4c3b-9193-de400ec0feb3.html` lays out which setups are reported. A chain over a hidden roadmap warns and runs rather than refusing; that was chosen, not asked.

## Goal

The tool tells the author when the project's ignore rules hide roadmap files, and the init step checks that git add works on the roadmap directory.

Nothing currently warns that a rule such as a blanket .* is hiding the roadmap directory. In one project, tasks sat untracked for two weeks until a worktree needed them. The roadmap directory's own ignore file only excludes runs/, which suggests the tool expects everything else in it to be trackable, so a hidden file is a misconfiguration worth reporting early.

Done looks like:
- Init checks that git add works on the roadmap directory and says which ignore rule stops it if not.
- The author is told, outside init too, when roadmap files are ignored or untracked.

Worth doing: it would have caught the untracked tasks two weeks before they broke a walk, and it is the early warning for the walk and pre-commit failures in the two tasks before it.

### W89.6 · Fix: a `.dfs/` rule cannot silence the warning when a broader rule like `.*` also hides the roadmap
Parent: W89.4
Status: confirmed
Approach: `dfs_paths.hidden()` in `scripts/paths.py` decides "kept as planning" from the one rule `git check-ignore -v` names per path, and git names only the LAST matching rule by precedence. So an author who keeps `.dfs` as planning with a rule naming it, which is the setup `hidden_message` itself recommends, is still warned whenever a broader rule also matches and wins. Checked in scratch repos (ROADMAP.md, order.md, an item and an artefact, nothing tracked): `.gitignore` = `.*` then `.dfs/` is silent, but `.dfs/` then `.*` reports `.dfs/` hidden by `.*`; and `.gitignore` = `.*` with `.dfs/` in `.git/info/exclude` reports `.*` too, because a `.gitignore` outranks `info/exclude`. That last case is the natural one: a project whose shared `.gitignore` has `.*`, and an author who keeps a personal planning roadmap through the local exclude file. Every chain start and the screen's header (`git hides .dfs`) then warn for good, and `init` ends with "Settle the ignore rule named above first", with no way out except editing the project's shared `.gitignore`. Fix: when git tracks nothing under `.dfs` and `.dfs/` itself is hidden, treat the roadmap as planning if any ignore source that applies (the root `.gitignore`, `git rev-parse --git-path info/exclude`, `core.excludesFile`) has a pattern for which `_names_state_dir` is true, not only the rule check-ignore names. To settle it, add `test_ignored.Hidden` cases for `.dfs/` then `.*`, and for `.*` in `.gitignore` with `.dfs/` in `.git/info/exclude`, expecting `[]`, while `.*` alone and files force-added past `.dfs/` are still reported.
Determination: `hidden()` now also reads every ignore file that applies (the root `.gitignore`, `info/exclude`, `core.excludesFile`) and treats the roadmap as planning when any of them has a pattern naming `.dfs` and git tracks nothing under it, so `.dfs/` then `.*`, and `.*` in `.gitignore` over `.dfs/` in `info/exclude`, are silent while `.*` alone and force-added files are still reported (`test_ignored`, 13 OK; `test_init` 10 OK, `test_chain` 74 OK, `test_screen.HiddenFromGit` OK); confirmed.

### W89.8 · Fix: `hidden()`'s planning exemption must follow what git actually does with `.dfs`
Parent: W89.6
Status: confirmed
Approach: In `scripts/paths.py`, `hidden()` returns `[]` when git tracks nothing under `.dfs` and `any(_names_state_dir(p) for p in _ignore_patterns())`. That condition fails in two ways. (1) It does not check that git ignores the roadmap as a whole, so a stray `.dfs/` rule overridden by a negation silences a real report. Checked in a scratch repo (ROADMAP.md, order.md, an item, `artefacts/a.html`, nothing tracked) with `.dfs/` in `.git/info/exclude` and `!.dfs/` then `*.html` in `.gitignore`: `git check-ignore -v` names `.gitignore:2 *.html` for the artefact and `ignored()` is False, so the tool treats the roadmap as committed, but `hidden()` is `[]`. So `init`, every chain start and the screen's header say nothing about an artefact git will never add. This happens at init, the one moment the Goal names, and goes away only after something under `.dfs` is committed. (2) `ignore_files()` reads `core.excludesFile` only when it is set, but when it is unset git reads `$XDG_CONFIG_HOME/git/ignore`, or `~/.config/git/ignore`, and a personal planning rule usually lives there. Checked with `HOME` pointed at a scratch home: `.*` in `.gitignore` and `.dfs/` in `~/.config/git/ignore` make `hidden()` report `.gitignore:1 .* hides .dfs/` (and `ignored()` is True). Setting `core.excludesFile` explicitly to the same file makes it `[]`. So that author is warned at every chain start and in the header, and `init` says "Settle the ignore rule named above first". Fix: take the any-pattern branch only when git ignores `.dfs` whole (for example `ignored()`, or `.dfs/` among the paths `ls-files --directory` lists), and add the default global excludes path to `ignore_files()` when `core.excludesFile` is unset. To settle it, add `test_ignored.Hidden` cases for both: the negation case must report the artefact by `*.html`, and the default-location case (with `HOME`/`XDG_CONFIG_HOME` set to the scratch directory) must return `[]`.
Determination: `hidden()` now takes the any-pattern exemption only when `ignored()` says git ignores the roadmap, and `ignore_files()` adds `$XDG_CONFIG_HOME/git/ignore` (default `~/.config/git/ignore`) when `core.excludesFile` is unset, so the negation case reports the artefact by `*.html` and `.*` over a `.dfs/` in the default global file is silent (`test_ignored` 15 OK, the two new tests fail without the fix; `test_init` 10 OK with TMPDIR=/tmp, `test_chain` 74 OK, `test_screen` 87 OK); confirmed.
