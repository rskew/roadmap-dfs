# W89 · Tell the author when the project's ignore rules hide roadmap files

## Summary

The tool now notices when a project's ignore rules keep part of the roadmap out of git. `init` asks git which roadmap files it would refuse to add and names the ignore file, line and pattern responsible, making that the next thing to fix; the same report is printed when a work chain starts, and the screen's header shows `git hides .dfs` with the rule spelled out under `h`. A roadmap kept on purpose by a rule naming `.dfs` (`.dfs/`, `.dfs/*`, `.dfs/**/*`, `**/.dfs/` and the like), in the project's `.gitignore`, `.git/info/exclude` or the global excludes file (`core.excludesFile`, or git's default `~/.config/git/ignore`), with git ignoring the roadmap and nothing in it tracked, stays the supported planning-only setup and is not reported, even when a broader rule such as `.*` also matches. A broader rule on its own, such as `.*` or `*.html`, or files force-added past a `.dfs/` rule, is reported. Untracked files git would add are not reported, since they are commits not yet made, and only the roadmap's own parts are checked, so a cache inside `.dfs` is left alone; `.dfs/artefacts/ff4032ac-938c-4c3b-9193-de400ec0feb3.html` lays out which setups are reported. A chain over a hidden roadmap warns and runs rather than refusing; that was chosen, not asked.

## Goal

The tool tells the author when the project's ignore rules hide roadmap files, and the init step checks that git add works on the roadmap directory.

Nothing currently warns that a rule such as a blanket .* is hiding the roadmap directory. In one project, tasks sat untracked for two weeks until a worktree needed them. The roadmap directory's own ignore file only excludes runs/, which suggests the tool expects everything else in it to be trackable, so a hidden file is a misconfiguration worth reporting early.

Done looks like:
- Init checks that git add works on the roadmap directory and says which ignore rule stops it if not.
- The author is told, outside init too, when roadmap files are ignored or untracked.

Worth doing: it would have caught the untracked tasks two weeks before they broke a walk, and it is the early warning for the walk and pre-commit failures in the two tasks before it.
