# W48 · Chat in the tui has weird line wrapping since we added the background chat sessions

## Summary

A chat that runs in the background now starts at the size of the screen's terminal, instead of a fixed 40 rows by 120 columns, and is resized whenever the screen is, so what it wraps while nobody looks matches the width it is later looked at in. This is the cause found by reading the code, and it is tested with a stand-in agent; the real claude is not installed here, so the wrapping in a real chat was not seen. Attaching still resizes the chat to the terminal as before, and a chat attached at the time is left to that.

## Goal

Chat in the tui has weird line wrapping since we added the background chat sessions

## Tree

### W48.1 · Start a background chat at the width of the terminal it will be looked at in
Status: confirmed
Approach: `Relay.start` (scripts/ptyrelay.py) gives every chat a fixed 40x120 pty when no size is passed, and the web page starts chats while the screen is on curses, so a claude draws and wraps its first screens at 120 columns and `attach` then resizes it under a terminal that never saw them. Default the pty to the size of the process's own terminal (fixed 40x120 only when there is none), and make the host resize every running chat when the screen is resized (`ChatHost.resize`, called on KEY_RESIZE in scripts/tui.py). Check with test_ptyrelay.py: an agent that prints `stty size` starts at the terminal's size, and a resize reaches it.
Determination: A background chat now starts at the size of the screen's terminal and follows the screen's resizes; test_ptyrelay.py passes (24 tests), but with no claude here the wrapping itself was not seen.
