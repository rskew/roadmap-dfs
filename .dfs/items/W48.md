# W48 · Chat in the tui has weird line wrapping since we added the background chat sessions

## Summary

A chat that runs in the background now starts at the size of the screen's terminal and follows its resizes, and attaching to it first clears the screen, so the chat's upward redraw has only blank rows to erase instead of the roadmap's own text. A stand-in agent that redraws in place shows that the fixed 40x120 start does not change the final screen once attached, but does show the redraw erasing rows it never drew, which the clear removes at either width. The Goal is not shown to be met: no real claude is installed here, so the wrapping itself was never seen, before or after, and the author is the one to look at a real chat's first screen after `c`. Clearing wipes anything printed before the attach, so the `ctrl-]` hint now lives in the help text of the `c` key; replaying what the chat drew in the background instead of clearing was left out as a bigger change to what the user sees, and a chat that does not redraw on resize shows a blank screen on re-attach.

## Goal

### W48.11 · Fix: `Relay.attach` on a chat that has already ended raises TypeError and ends the screen
Parent: W48.10
Status: confirmed
Approach: `fit` in `Relay.attach` (scripts/ptyrelay.py) passes `self.fd` to `fcntl.ioctl`; once the agent has exited `_pump` sets `self.fd = None`, and `_try` catches OSError, ValueError and termios.error but not the TypeError that gives, so the traceback ends the curses screen. Seen with tui.py `c` on a chat whose run.sh could not be executed (rc=127 at once; the traceback ran through `fit(redraw=True)` in `attach` and then `curses.wrapper`'s `endwin()` returning ERR). Make `attach` return False when the chat has no fd (read `self.fd` once), and `Relay.resize` already returns on None. Add a test in scripts/test_ptyrelay.py: a Relay whose agent exits at once, then `attach()` returns False and does not raise. Check: the test is red on the current code and the suite passes.
Determination: `Relay.attach` returns False at once for a chat that has already ended, and `fit` reads `self.fd` once and does nothing when it is None, so the TypeError no longer ends the screen; the new test (attach to an agent that exited with 127) raised the TypeError on the old code and passes now, and test_ptyrelay.py passes (29 tests).
