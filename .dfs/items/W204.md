# W204 · Show artefacts on a task in reverse chronological order

## Summary

The artefacts section of a task page now lists artefacts newest first, instead of in the order the text names them. "Newest" means the git author time of the commit that added the file, which survives a rebase and a merge; a file not yet committed is placed by its file time. The Goal is fully met; sorting by the naming node or by file time was left out because the first misorders pages named twice and the second is arbitrary after a merge.

## Goal

Show artefacts on a task in reverse chronological order

## Tree

### W204.1 · Sort artefacts by the git time they were added, newest first
Parent: W204
Status: confirmed
Approach: **The question**: in what order does a task page list its artefacts, and what clock puts the newest first? **What this node does**: in `scripts/web.py`, `artefacts_for` gets a "made at" time for each artefact and sorts the list newest first. The time is the git author time of the commit that added the file (`git log --diff-filter=A --follow -1 --format=%at -- <path>`, run in the item's worktree or the main checkout, whichever holds the file), cached by path and file mtime so a page refresh does not run git again. A file git does not know (not committed yet, or `.dfs` gitignored) uses its file mtime. Ties keep the old order. The page needs no change, since it draws the list as given. **How we will know it worked**: a new test in `scripts/test_web.py` makes three artefacts in three commits with out-of-order names in the prose and checks the list is newest first; a second test checks an uncommitted file falls back to its mtime; the existing artefact tests still pass.
Hypothesis: "Newest first" means when the artefact was made, and the author time of the commit that added the file is the best record of that, since it survives a rebase and a merge. Wrong if the author meant the order the nodes name them, or if most artefacts are untracked, so the time is nearly always the file's mtime. .dfs/artefacts/c4c11e20-7406-49c6-b881-c342325bc830.html
Evidence:
- for: with commit dates all set to 2030 and author dates set to Jan, Feb and Mar 2024, the new test lists the three pages newest first by author date, so the author date is what orders them.
- for: the new test is red without the change (the list came back old, mid, new) and green with it.
- for: a file git does not know (never committed) is placed by its mtime, and the test for that passes.
- against: none seen. Not checked: a repo with `.dfs` gitignored, where every artefact falls back to its mtime.
Determination: Confirmed: the task page lists artefacts newest first by the git author time of the commit that added each, so the Goal is met.

### W204.2 · Sort artefacts by the node that names them, latest node first
Parent: W204
Status: parked
Approach: **What this node does**: `artefacts_for` already finds the first node that names each file (its `node` field). Sort by that node's number, highest first, and put artefacts no node names (named only in an answer or the Summary) by their place in the log. No git is used.
Determination: Parked: it reads the prose, not when the file was made, so a node that names an old page again, or a Summary naming earlier pages, gives the wrong order. Take it if git time proves unreliable.

### W204.3 · Sort artefacts by file modified time, newest first
Parent: W204
Status: parked
Approach: **What this node does**: sort by `stat().st_mtime`, newest first. The smallest change.
Determination: Parked: a merge or a fresh worktree writes every file at one moment, so the order is then arbitrary. Take it only if git time cannot be had.
