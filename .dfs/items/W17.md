# W17 · How to end chat sessions so we don't leak resources on the sever

## Goal

How to end chat sessions so we don't leak resources on the sever

## Tree

### W17.1 · Find how a chat's agent outlives the chat
Status: confirmed
Approach: Reproduce, with scripts/ptyrelay.py's `Relay` and `ChatHost` and a stand-in agent, each way a chat can end (`Relay.close`, `ChatHost.close_all` at screen exit) and look in `pgrep` for what is left. Read scripts/chat.py `turn` (the page's headless turn) for the same.
Determination: Three leaks found: `Relay.close` signals only the agent's pid, so a helper it started in its own session that ignores hangup survives (a `setsid` sleep outlived `close()`); the SIGKILL backstop in `close` is a daemon thread that dies with the screen, so `close_all` at exit leaves an agent that ignores SIGHUP running (`trap '' HUP; sleep` outlived the process); and `Chats.turn` runs `subprocess.run(..., timeout=)`, which on timeout kills only run.sh's pid, not what it started.

### W17.2 · Close a chat by ending everything it started, and wait
Parent: W17.1
Status: confirmed
Approach: In ptyrelay.py, `Relay.close` collects the agent's descendants from /proc (parent links) and its process group, sends SIGTERM to them all, then SIGKILL to what is left after a short grace, `close(wait=True)` blocks until they are gone, and `ChatHost.close_all` uses it so exiting the screen leaves nothing. Tests in test_ptyrelay.py with a stand-in that ignores SIGHUP and one that starts a `setsid` helper.
Hypothesis: Walking /proc parent links finds everything a chat's agent starts. Wrong if a process the agent started has been re-parented to init before close (then it is in no tree walk) and survives.
Evidence:
- for: the two reproductions from W17.1 (a `setsid` helper that ignores HUP and TERM; an agent that ignores HUP, closed at exit) leave no process behind after the change.
- for: the new Leaving tests pass 8 runs in 8 after a race was fixed (SIGKILL is delivered, not instant, so `close(wait=True)` now waits for the processes to be gone).
- against: not tested with a real claude, so what it forks (a tool process that daemonises and is re-parented to init before close) is unobserved; such a process is in no parent-link walk.
Determination: Confirmed: `Relay.close` now ends the agent and everything under it by parent links, and `ChatHost.close_all` waits until they are gone.

### W17.3 · End a page turn's agent on timeout
Parent: W17.2
Status: confirmed
Approach: In chat.py `Chats.turn`, run the turn with `subprocess.Popen(..., start_new_session=True)` and on `TimeoutExpired` kill its whole process group (SIGTERM, then SIGKILL) and reap it, instead of `subprocess.run`'s pid-only kill. Test in test_chat.py with a run.sh stand-in that starts a child and sleeps past a shortened TURN_TIMEOUT.
Determination: Confirmed: `chat.run_turn` starts the turn in its own session and, on timeout, ends it and everything it started with `ptyrelay.stop_tree`; the new TurnTimeout test (a HUP/TERM-ignoring helper in its own session) passes, and the Chat and web tests fail the same 12 and 1 with and without the change because /tmp and /dev/shm here are noexec, so their stub agent cannot run.

### W17.4 · End the screen's chats on SIGTERM and SIGHUP too
Parent: W17.3
Status: open
Approach: In tui.py `main`, make a SIGTERM or SIGHUP to the screen close the chat host as a normal exit does, so a killed screen or a dropped ssh session does not leave background agents. Check with a pty-run screen that is sent SIGTERM and then `pgrep`ed.

### W17.5 · Close a chat nobody is using
Parent: W17.4
Status: open
Approach: Background chats now live until the screen exits or "New chat". Add a reaper to the screen's loop that closes a relay that is not `active`, is not attached, and whose transcript has not moved for an idle limit (default 30 minutes, an env override). Its conversation is not lost: `chat.claim` resumes the saved session id when the page or `c` next opens it. Test in test_ptyrelay.py/test_chat.py with a short limit.
Hypothesis: Resuming a closed chat from its transcript is lossless for the author. Wrong if a resumed chat loses something a live one had (an unanswered permission prompt, a half-typed line, an attached screen's scrollback).

### W17.6 · A button to end a chat and keep the conversation
Parent: W17.4
Status: parked
Approach: Add `Chats.end(scope)` and a web endpoint and button that close the background agent but keep the saved session id (unlike `clear`, which also forgets it).
Determination: Parked: it relies on someone remembering to press it, which is how the leak arises, and adds UI the author has not asked for; W17.5 ends idle chats without them. Unpark if the author wants a manual control as well.
