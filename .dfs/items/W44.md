# W44 · We need a serious review if how artefacts work for assumptions and raises. These key specified artefacts should have the abolity to submit their form and answer a raise or confirm/refute an assumption

## Summary

A page a node's Hypothesis names can now confirm or refute that node: it posts a verdict and a note to the server, which writes the same ruling the web form's Refute/confirm does, and the web form opens that page beside it. A raise's `Answer with:` page already answered through the server; that is unchanged. The assumption template has Confirm and Refute buttons, `check.py` refuses a new Hypothesis whose page cannot post a verdict, and `tree.py log raise` refuses an answering page that cannot post an answer. The server, template and checks are tested; the web form and viewer changes are written and covered by a browser test that could not run here (no node or playwright), so they are read and not seen, and the old pages already committed are left as they were.

## Goal
