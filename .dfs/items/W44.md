## Goal

We need a serious review if how artefacts work for assumptions and raises. These key specified artefacts should have the abolity to submit their form and answer a raise or confirm/refute an assumption

## Tree

### W44.1 · Audit how artefacts answer raises and decide assumptions
Status: confirmed
Approach: Read `web.py` `artefact_state` and `act("correct")`, `tree.answer_page`, `check.check_assumptions`, the web page's answer and refute/confirm forms and artefact viewer, `_TEMPLATE_ASSUMPTION.html` and `docs/artefacts.md`, and list what a page can and cannot submit.
Determination: Confirmed: a raise's `Answer with:` page can post its answer to `/artefact-state/<page>`, but an assumption's page cannot confirm or refute its node (the endpoint only knows raises; the web form for refute/confirm shows no page; the template's one button is "Send as my answer"; `check.py` demands only a control and a handler, so a page that submits nothing passes); the viewer opened from a link ignores the page's `answered` message; and nothing requires an `Answer with:` page to post. The work is W44.2 to W44.6.

### W44.2 · Let an assumption's page confirm or refute its node through `/artefact-state`
Parent: W44.1
Status: confirmed
Approach: In `web.py`, `artefact_state` finds the live node whose Hypothesis names the page (`.dfs/artefacts/<page>`) and accepts `{verdict: "confirmed"|"refuted", answer: "<why>"}`, appending the same `correct` log entry `act("correct")` writes (one shared function); the GET reports that node as `node` so the page can show its buttons only when there is one. Tests in `test_web.py`: verdict recorded, refused for a page no Hypothesis names, a bad verdict or an empty note.
Determination: Confirmed: a page named in a waiting node's Hypothesis posts `{verdict, answer}` and gets the same `correct` entry as the web form, a page no Hypothesis names, a parked or already-ruled node, a bad verdict or an empty note is refused, and `test_web` and `test_tree` pass but for the chat test, which fails here without the change too.

### W44.3 · Show the node's page in the web page's refute/confirm form
Parent: W44.2
Status: open
Approach: `correctForm` in `scripts/web/index.html` opens the node's Hypothesis page in a sandboxed frame beside the form, as `answerForm` does for a raise, closing on the page's `answered` message; the artefact viewer also listens for it and refreshes the task. A `test_ui.py` flow drives it.

### W44.4 · Give the assumption template a confirm/refute submit
Parent: W44.3
Status: open
Approach: `templates/_TEMPLATE_ASSUMPTION.html` replaces "Send as my answer" with Confirm and Refute buttons and a note box that post `{verdict, answer}`, shown only when the GET reports a `node`; the raise-answering part stays for a page that is both. `test_templates.py` keeps it passing the checker.

### W44.5 · Require the pages to submit
Parent: W44.4
Status: open
Approach: `check.check_assumptions` refuses a new Hypothesis whose page does not reach `/artefact-state` with a `verdict`; `tree.append_log` refuses a raise whose `Answer with:` page does not post an `answer` there. Tests in `test_tree.py` and the check's tests.

### W44.6 · Document it and finish
Parent: W44.5
Status: open
Approach: Update `docs/artefacts.md`, `README.md`, `SKILL.md` and `templates/ROADMAP.md` wherever they say what an assumption's page does, write the Summary, and run the suites.
