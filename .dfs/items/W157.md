# W157 · tree.py shelve leaves the task file over its budget on a commit that grows it

## Summary

`tree.py shelve` now checks the task file against the 10,000-token handoff budget when it finishes. If the file is still over, it prints how many tokens (and about how many words) over it is, which determined nodes to shelve next with the command to run, and what only `tree.py compact` or a hand edit can move (old log entries, Evidence, Background). A test shows the case that failed first: a file just over the budget after a shelve has a commit that adds one node refused as growing it. The Goal is met as its second option: `shelve` reports the overage and what to shelve next, and it does not itself force the file under the budget, since nothing shelvable may be left. The probe that could not reproduce the refusal reached a different case, a new or unchanged file.

## Goal

`tree.py shelve <task> [<ids>]` moves a determined node's text to `.dfs/archive/items/<task>.md`, but a commit that also adds a node can still leave the task file over its size budget, and the check then refuses that commit. Found while working W153 (filed there as a draft, not fixed there; seen by earlier sessions of that task, not re-run when filing).

Goal: after `shelve`, either the task file is under its budget for the commit that adds the next node, or `shelve` says by how many words it is still over and which nodes to shelve next. Show the case that goes red first: a task file near the budget plus a node whose commit grows it.

Re-run on 2026-11-08 (W153.51): not reproduced. In a scratch repo, `check.py --staged` accepted a staged 60,000-character task file with no node shelved, so the refusal that W153 met is not the one this probe reached (W153.42 and the raise answered "Raise the budget" saw it on a real task). Left unverified.

## Tree

### W157.1 · Show the red case: a node that grows a file already over budget is refused
Status: confirmed
Approach: **The question**
- Does `check.py --staged` refuse a commit that adds one node to a task file that is already a little over the 10,000-token budget in HEAD, even after a `shelve` shrank it?

**What this node does**
- Adds a test in `scripts/test_tree.py` (class `InARepo`): commit a task file about 300 tokens over the budget, shelve one node so it shrinks but stays over, commit that, then stage a new node and run `check.py --staged`.

**How we will know it worked**
- The test sees exit code 1 and the "GREW it" text. This is the red case the Goal asks to show first.
Determination: Confirmed: with HEAD about 75 tokens over the budget after a shelve, a commit that adds one node is refused as GREW; shelve alone does not prevent it.

### W157.2 · Make `shelve` say how far over the budget the file still is, and what to shelve next
Parent: W157.1
Status: confirmed
Approach: **The question**
- After `shelve`, how does the session know whether the next node's commit will pass?

**What this node does**
- In `scripts/tree.py`, `shelve` returns the moves as before. The CLI then compares the file's size (`len(text) // 4`, the check's own count) with `state.HANDOFF_BUDGET`. If it is still over, it prints how many tokens and words over it is. It lists the determined nodes that still hold shelvable text, biggest saving first, then says what else is left (Evidence, Log via `compact`, Background).
- A file under the budget prints nothing extra.

**How we will know it worked**
- A test on the W157.1 file: output names the remaining overage and the next ids; shelving those ids brings the same staged add-a-node commit to exit code 0.
Determination: Confirmed: after `shelve`, a file still over the budget gets the tokens and words over, the next ids to shelve with the command, and what only `compact` or a hand edit can move; the new test is red without the change and the Goal is met.
