# W98 · Fix viewing run logs

## Summary

A run's log in the web page now shows its console every time it is opened. Before, a run opened a second time from its task (the usual case for a finished run) showed an empty box until a Session tab was tapped and the Console tapped again. The Back button in the bottom bar (and the header's on a wide screen) now returns from any of a run's tabs to the task, instead of stepping back through the tabs. The browser's own back gesture still steps through the tabs one at a time, since the Goal asked only about the Back button.

## Goal

When being run logs, console is initially blank until tapping session then back again, and the bottom back button should return to the item rather than going back to session

## Tree

### W98.1 · A reopened run's console shows its log
Status: confirmed
Approach: In `scripts/web/index.html`, `drawRun` treats a look as fresh only when `RUNLOG.key` differs from the run, and `RUNLOG` outlives leaving the screen: reopening the run last shown (or a second render racing the first) asks `/api/run/<name>?from=<end>`, gets no new text from a finished run, and leaves the newly built `<pre id=runlog>` empty until a Session tab changes the key. Count a look as fresh also when the page does not hold this run's console box, so it asks for the tail and fills the box. Check: the `run_log` flow in `scripts/ui_flows.mjs` goes back to the task and opens the finished run twice, and the console must show its text each time; red on the old code, green on the new.
Determination: A run reopened from its task now draws its console's tail: the `run_log` flow's reopen of the live run failed on the old code ("a run opened again shows its console (9 turns)") and passes with the fix, as does `run_session`. ![a finished run opened a second time, its console drawn](.dfs/artefacts/93a42bc0-1d6b-4cb9-9b58-2b5449cc20d3.png)

### W98.2 · Back from a run's log returns to its task
Status: confirmed
Approach: `up` in `scripts/web/index.html` sends a run screen `history.back()`, so on a Session tab reached from the Console the bottom bar's Back (and the wide screen's) goes back to the Console. For a run, step back through history to the nearest entry that is the task's screen (`t/<task>`, or one of its nodes) when every entry in between is one of this task's run screens, and otherwise replace the run with the task screen. The browser's own back is left stepping through tabs. Check: the `run_session` flow taps Back on a Session tab reached from the Console and must land on `#/t/W9`, and Back once more there must reach the list.
Determination: Back on a run's Session tab now lands on the task (`#/t/W9`) and Back again on the list: the `run_session` flow failed on the old code ("Back on a session goes to its task, not #/r/W9/dfs_run_codex") and passes now, and `test_ui test_web test_webscreen` fail only the four flows that fail on main (walktags, layout, markdown, bar-from-chats), so the Goal is met.
