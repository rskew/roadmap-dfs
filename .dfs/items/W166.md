# W166 · Update the icon to be similar to the background

## Summary

The app icon is now cut from the real background tree: same branches, line weights, colours and marks, shown as a full square around the trunk and the middle of the crown. The phone rounds it into its own bubble, and the manifest offers it as both a plain and a maskable icon, so no white ring shows round it. That fix was checked in tests and pixels, not on a phone. It is drawn by the same script as the background pictures, so the two stay alike, and the background pictures are unchanged. The Goal is met on one reading of "similar": the icon is the background seen closer, in the light colours only. A shrunk whole background and a denser redrawn tree were left out because the whole picture turns to fuzz at small sizes and a redraw is what looked unlike the background.

## Goal

Update the icon to be similar to the background

### W166.3 · It's for an app icon so make it round?
Parent: W166
Status: confirmed
Approach: **The question**
- The author asks whether the icon should be round, since it is an app icon. Should `.dfs/icon` be a disc?

**What this node does**
- In `.dfs/background-src/make_background.py`, `icon()` clips the same cut of the background tree to the circle inside its square (a `clipPath` disc, radius half the side), so the corners are empty.
- In `.dfs/background-src/render.mjs`, the screenshot is taken with `omitBackground: true`, so those corners stay transparent in the png. The background pictures have an opaque ground, so they do not change.
- Re-render `.dfs/icon`.

**How we will know it worked**
- The icon png is RGBA with alpha 0 in all four corners, and the light and dark background pictures are byte for byte as before.
Hypothesis: "Make it round" means the icon picture itself is a disc with transparent corners, in the same tree cut as before. Wrong if the author wants the square kept and left to the phone to mask, with the art held inside a safe zone. .dfs/artefacts/7d2f9c41-8a6e-4b35-9e07-1c4a5b8d3f60.html
Evidence:
- for: decoding the rendered png, the four corners are (0,0,0,0) and the centre is opaque; the file is 1024 x 1024 RGBA.
- for: re-rendering the light and dark backgrounds gives files identical (`cmp`) to `.dfs/background-image-light` and `-dark`.
- against: the icon is served as purpose "any" only; on iOS a transparent corner is painted black, so the home-screen tile there is a black square with a disc on it. I did not run it on a device.
- against: the disc loses the four corners of the square cut, so a little more of the crown is cut off than before.

### W166.4 · The icon still has a white ring inside the app bubble
Parent: W166
Status: confirmed
Approach: **The question**
- The author sees a white ring inside the phone's round app bubble. Where does it come from?

**Why it matters**
- The round cut in the previous node left the icon's four corners transparent. A phone that cuts its own bubble puts a white backing behind transparent pixels, and Android also pads an icon that is not marked maskable onto white. Both would show as a ring round our disc.

**What this node does**
- `icon()` in `.dfs/background-src/make_background.py` no longer clips to a disc: the icon is the same cut of the background tree as a full, opaque square in the background's ground colour. Re-rendered to `.dfs/icon`.
- In `scripts/web.py` the manifest lists a custom icon as "any" (192, 512, 1024) and as maskable (512, 1024), as the built-in icon already is. `scripts/test_web.py` checks a maskable entry is there.

**How we will know it worked**
- `.dfs/icon` has no transparent pixel, the background pictures are unchanged byte for byte, and the icon and manifest web tests pass.
Hypothesis: The white ring is the backing the phone shows behind the icon's transparent corners and Android's padding of a non-maskable icon, so a full opaque square also offered as maskable removes it. Wrong if the ring is still there with this icon, or is something else (for example a ring drawn in the picture itself). .dfs/artefacts/2c1f6093-07c2-4058-9d79-2b07fe8f07c9.html
Evidence:
- for: the old `.dfs/icon` was RGBA with alpha 0 in the four corners and the disc edge at the picture's edge, so a bubble larger than the disc leaves a ring of backing.
- for: the new icon decodes as 1024 x 1024 RGB; the four corners are the ground colour (239, 237, 231) and the centre is the trunk.
- for: the light and dark background pictures re-render identical (`cmp`) to `.dfs/background-image-light` and `-dark`; the icon web test passes, and the installable test fails only on the README `--allow-host` check, with or without the change.
- against: I did not run it on a phone or in an Android launcher, so the ring going away is not seen. The web test failures that remain (README `--allow-host` and others) are the same with the change stashed.
- against: this undoes the round picture of the previous node; where nothing masks the icon (some desktops) it shows as a square.
![the new full-square icon, 1024px](.dfs/artefacts/260105e0-45d8-400e-9def-03e51946d066.png)
Determination: Confirmed on the evidence so far: `.dfs/icon` is now an opaque full square and the manifest offers it as maskable too; the ring going away on a real phone is not yet seen.
