# W10 · Allow customizing the theme so that different projects don't get mixed up

## Goal

Allow customizing the theme so that different projects don't get mixed up

## Tree

### W10.1 · A project colour in `.dfs/theme`, with a default from the project's name
Status: confirmed
Approach: In `scripts/paths.py` add `theme_file()`, `read_theme()`, `write_theme(value)` and `project_colour()`: `.dfs/theme` holds one `#rrggbb` line; when it is missing the colour is a hue taken from a hash of `project_title()` (fixed saturation and lightness, so it reads on paper) and is not written, so renaming a project that has no chosen colour changes its colour with it. Tests in `scripts/test_web.py`'s neighbourhood (a new `test_theme.py`): the same name gives the same colour, two names differ, a bad value is refused, the file round-trips.
Hypothesis: "Theme" in the Goal means a per-project identity colour (a project's own look, so two servers or two installed apps are told apart at a glance), not the light/dark switch. Wrong if the author meant something else, such as light/dark remembered per project (it already is: `localStorage` is per origin and each project has its own port).
Evidence:
- for: `.dfs/items/` and `.dfs/title` already hold per-project identity (the name) and `web.py` already serves one server per project on its own port, so a colour beside the name is the same kind of thing; no existing "theme" setting other than the light/dark switch (`localStorage`, per origin) was found by grep over scripts/ and docs/.
Determination: `scripts/paths.py` now gives each project a colour from `.dfs/theme` or its name, `scripts/test_theme.py` passes (5 tests, including white text holding 4.5:1 over 500 names).

### W10.2 · The web page wears the project colour, and can change it
Parent: W10.1
Status: open
Approach: `web.py` serves the colour in `/api/state` and in the manifest's `theme_color`, and fills it into `index.html`'s `<meta name="theme-color">`. `design.css` gets one identity token, `--project`, kept apart from the three meanings and used for the name only: a solid block beside the project name in the bar and the top rule of the bar. A "Colour" row in the rename dialog posts to `/api/theme`; text on the colour holds 4.5:1 in both themes (checked as `/design` checks the others). `docs/design-system.md` and `/design` say what `--project` is for and that it never stands for status.

### W10.3 · The terminal screen shows the same colour
Parent: W10.2
Status: open
Approach: In `scripts/tui.py` the header's project name is drawn in the project colour (nearest 256-colour pair when the terminal has them, bold otherwise), so the terminal and the page of one project match. A test in `test_screen.py` that the header carries the name.

### W10.4 · Colour by `DFS_PROJECT_COLOUR` alone, no file
Status: parked
Approach: Take the colour only from an environment variable set where each server is started.
Determination: parked; it would need setting for every start of every project, and a colour chosen on the page would not survive a restart, so a file beside `.dfs/title` comes first.
