# W170 · Raise artefacts must have a submit button

## Summary

`tree.py log raise` now refuses an `Answer with:` page that has no submit button (a `<button>` or an `<input type="submit">`), even when it has a text box, a handler and the route. `docs/artefacts.md` says so, and a test covers it. Only the answering page is held to this, since a page a raise merely links to look at is a picture that sends nothing. Four tests in `test_web.py` already failed before this change and still do.

## Goal

Raise artefacts must have a submit button

## Tree

### W170.1 · An answering page must have a submit button
Status: confirmed
Approach:
- **The question**: can a raise name an answering page that has no button to send the answer?
- **Why it matters**: `tree.py can_answer` only looks for a control, a handler, the word "answer" and `/artefact-state/`. A page with a text box and a comment passes, and the author then cannot send anything.
- **What this node does**: `can_answer` also requires a submit button: a `<button>` or an `<input type="submit|button">`. The refusal message and `docs/artefacts.md` say so. A test in `scripts/test_web.py` fails first on a button-less page, then passes.
- **How we will know it worked**: that test, `test_templates.py` (the template still passes) and the seven pages already named by `Answer with:` all pass.
Hypothesis: "Raise artefacts" means the page on the `Answer with:` line, not pages a raise only links to look at. Wrong if the author wants every page a raise names to carry a button. .dfs/artefacts/15a0a018-2dfb-4efd-9f02-9c9dd7ddccf6.html
Evidence:
- for: a probe of `can_answer` on a page with a textarea, a handler and the route in a comment returned True, so the gap is real.
- for: pages linked only to look at are pictures that post nothing, so a button on them would send nothing.
Determination: A raise's answering page is now refused unless it has a submit button, and the template and the seven pages already used still pass, so the Goal is met on reading A.
