# W118 · Chats should read the info for a task from its worktree rather than a stale top level task description

## Summary

A chat about a task now opens with the path of the task's item worktree files (`.dfs/worktrees/<task>/.dfs/items/`) when the worktree exists, on the screen and on the web page, instead of the top-level copy that goes stale once the task is worked on its branch. The prompt also says that whenever the worktree exists it holds the current files, so a chat begun before the worktree was cut, which keeps its first prompt, still looks in the right place. The Goal is met; project chats are unchanged, and the chat still runs at the project root because a session's transcript is tied to that directory and the worktree is removed at merge.

## Goal

Chats should read the info for a task from its worktree rather than a stale top level task description

## Tree

### W118.1 · A task chat's prompts name the task's files in its worktree
Status: confirmed
Approach: run.sh builds the task chat's prompts (the screen's `--chat <task>` default_chat_prompt and `--chat-turn`'s `about` framing) from `$DFS_ITEMS_REL/$ITEM.md`, the main checkout's copy, which is a stale top-level description once the task has an item worktree (the work is committed on `dfs/<task>` there). Add `paths.py --task-items-rel <task>` printing `rel(task_items(task))` (the worktree's `.dfs/items` when `worktree(task)` exists, else the checkout's), and have both prompts use it for the task file and its parts directory. The chat keeps running at the work root. Check: test_chat asserts the prompt sent names `.dfs/worktrees/<task>/.dfs/items/<task>.md` when the worktree exists and `.dfs/items/<task>.md` when it does not.
Determination: Confirmed: both run.sh prompts now name the worktree's task file and parts directory when one exists; the new test_chat test fails on the old run.sh and passes, and all 59 test_chat tests pass.

### W118.2 · Run the task chat with its worktree as the working directory
Parent: W118
Status: parked
Approach: Start the chat (chat.py `Chats.turn`, tui.py `start_chat`, `run.sh --chat`) with cwd at the task's worktree, so relative reads and the code the agent sees are the branch's.
Determination: Not first: claude keys a session's transcript by cwd and the worktree is removed at merge, so a resumed chat would lose its session; naming the worktree's paths in the prompt gets the task info without moving the chat.

### W118.3 · A chat begun before the worktree existed still finds the task in it
Status: confirmed
Approach: A session keeps the first prompt it was given, so a chat opened while the task had no item worktree keeps being told to read the top-level `.dfs/items/<task>.md`, which is stale once the worktree is cut. Rather than record per-session state, make the prompts location-independent: besides the resolved path, run.sh's task prompts (the screen's `--chat <task>` and `--chat-turn`'s framing) say that when `.dfs/worktrees/<task>/.dfs/items/` exists it holds the task's current files and the top-level copy is stale, so the agent checks which exists before relying on what it read earlier. paths.py gains `--task-worktree-items-rel <task>` (the worktree's items path whether or not it exists) so run.sh spells no `.dfs`. Check: test_chat asserts the first prompt of a task with no worktree carries that rule and the worktree path.
Determination: Confirmed: the task chat prompts now carry the rule and the worktree path, so a session begun before the worktree was cut still finds the task; the extended test_chat test and all 59 test_chat tests pass.
