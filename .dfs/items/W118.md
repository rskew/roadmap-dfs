# W118 · Chats should read the info for a task from its worktree rather than a stale top level task description

## Summary

A chat about a task now opens with the path of the task's item worktree files (`.dfs/worktrees/<task>/.dfs/items/`) when the worktree exists, on the screen and on the web page, instead of the top-level copy that goes stale once the task is worked on its branch. The prompt also says that whenever the worktree exists it holds the current files, so a chat begun before the worktree was cut, which keeps its first prompt, still looks in the right place. The Goal is met; project chats are unchanged, and the chat still runs at the project root because a session's transcript is tied to that directory and the worktree is removed at merge.

## Goal

Chats should read the info for a task from its worktree rather than a stale top level task description
