# W137 · Can't left arrow in tui new mode open inputs

## Summary

The prompts that the `o` key opens (`run.sh --open`), and the matching `--review` prompts, now edit the line: left and right arrow, home, end and delete move the cursor instead of typing `^[[D` into the answer. The cause was a bare read from `/dev/tty`; the prompts now go through `scripts/ttyio.py`, which uses Python's `input()` with `readline`. The Goal was read as these prompts, because the TUI's own `/` and `:` line already handled the arrow keys, and a pty test drives the real prompts.

## Goal

Can't left arrow in tui new mode open inputs

## Tree

### W137.1 · Line editing in the prompts of `run.sh --open`
Status: confirmed
Approach: **The question**
- Why does left arrow type `^[[D` into the prompts the `o` key opens?

**What this node does**
- `open_mode` in `scripts/run.sh` reads its answers with a bare `readline()` on `/dev/tty`, so the terminal's arrow escapes arrive as text. `review_mode` in the same file has the same code.
- Add `scripts/ttyio.py`. It points fds 0 and 1 at `/dev/tty`, imports `readline`, and gives `ask` and `block` helpers built on `input()`. Both heredocs use it instead of their own copies.
- Add a test that drives `run.sh --open` on a pty, sends left arrow in the middle of a word, and checks the saved short name.

**How we will know it worked**
- The pty test is red without the change (the name saved as `abd^[[Dc`) and green with it (`abcd`).
Hypothesis: "New mode open inputs" means the prompts of `run.sh --open` (key `o`), not the TUI's own line editor `read_line`, where KEY_LEFT already works. Wrong if the author means another screen or prompt. .dfs/artefacts/7b07fa93-4323-4fe7-9efc-d25c926239fe.html
Evidence:
- for: A pty run of `run.sh --open T1` typing `abd`, left arrow, `c` saved the name `abd[Dc`, so left arrow is broken there.
- for: `read_line` in `scripts/tui.py` handles `curses.KEY_LEFT` and `KEY_RIGHT` by moving the cursor, so the TUI's own prompts are not the fault.
- for: `scripts/test_ttyio.py` (3 pty tests: open name, open goal line with home and delete, review node id) fails 3 of 3 on the old `run.sh` and passes 3 of 3 with `ttyio.py`; the saved name is now `abcd`.
Determination: Confirmed: the prompts of `run.sh --open` and `--review` now edit the line, so left arrow moves the cursor and the Goal is met.
