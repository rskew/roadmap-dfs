# W121 · Option to show archived tasks

## Summary

The web page's task list now has a Show archived button (remembered in the browser) that draws archived tasks after the live ones, marked archived. An archived task opens read-only: its tree, nodes and artefacts can be read, and no answer, accept, edit, add or delete control is offered, including in the right-click node menu, which gives only Open. The server reads archived tasks straight from their archive folder, apart from the live list, so the walk and runner never see them. Only the web page was covered, since the terminal screen has no archive action and still does not list them; a page test for the button was added but could not be run here (no node or playwright), and a page screenshot showed no text here (no fonts), so the layout was checked from the page's contents.

## Goal

Option to show archived tasks

## Tree

### W121.1 · The server lists archived tasks and serves one read-only
Status: confirmed
Approach: In `scripts/tree.py` add `archived_task_ids()` and a `load_archived(task)` that reads a task's parts from `archived_dir()` (`items/<T>.md`, its archive from `archive/<T>.md`). In `scripts/web.py` make `/api/state?archived=1` append those tasks as rows with `archived: true` after the live rows (kept out of `state.full()`, so the walk and runner never see them), and make `/api/task/<id>?archived=1` return `task_json` for an archived task with `archived: true`. Every write endpoint keeps refusing an archived id, since `dfs_tree.exists` is false for it. Tests in `scripts/test_web.py` archive a task, then check the list with and without the flag, the read-only task, and that an answer to it is refused.
Determination: Confirmed: `/api/state?archived=1` appends archived tasks (`archived: true`) after the live rows and `/api/task/<id>?archived=1` serves one, while the plain endpoints and every write still treat it as absent; the new test_web tests pass, and the 2 test_web and 1 test_tree failures also fail without the change.

### W121.2 · The web page has a Show archived option
Parent: W121.1
Status: confirmed

In `scripts/web/index.html` add a Show/Hide archived button under the list (kept in localStorage) that fetches `/api/archived`; archived rows follow the live ones under an `archived` rule and open the task page read-only: an Archived note, and no answer, accept, edit, add, delete, chat or run control. README gets an Archiving section. Checked by test_web and by driving the page in headless chromium over the DevTools protocol.
Determination: Confirmed: with the button on, the list draws live tasks then an archived rule and the archived task, which opens with only a Flagged filter, no Answer on raises and no node actions, while a live task keeps them and an unknown id still says no task; the button toggles and persists, test_web passes bar two chat/login failures that fail without the change, and the screenshot rendered no text here (no fonts), so the layout was judged from the DOM.

### W121.4 · Fix: the right-click node menu still offers write actions on an archived task
Parent: W121.2
Status: confirmed
Approach: In `scripts/web/index.html` the `contextmenu` handler (near "Right-click on a node", ~line 1785) builds its menu from `S.task.rows` and always offers Refute/confirm, Edit, Add under and Delete, with no check of `S.task.archived`. `drawSheet` and `raiseCard` were made read-only for an archived task, and the README's Archiving section says an archived task has "no answer, accept, edit, add or delete control", but on a hover-capable screen right-clicking a node row of an archived task shows these four; choosing one opens its form and the post is refused 404 ("no task"). Fix: when `S.task.archived`, the menu offers only "Open <id>" (or the handler returns and leaves the browser menu). Check by loading an archived task in the page (headless chromium over the DevTools protocol, as W121.2 did), dispatching a `contextmenu` event on a `.row .main[data-act=node]`, and asserting that `#ctx` has no correct/editnode/add/deletenode buttons, while a live task's menu still has all of them.
Determination: Confirmed: driving the page in headless chromium over the DevTools protocol (with `(hover: hover)` forced on), a right-click on a node row of an archived task now gives only `node` (Open), where before the change it gave node, correct, add and deletenode, and a live task's menu still has node, correct, add and deletenode.
