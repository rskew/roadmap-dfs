# W139 · thorough performance review, make the page more responsive

## Summary

The web page now loads and updates much faster. On this repo's 141 tasks the list call fell from 697 ms to 265 ms and the task call from 363 ms to 91 ms, text is gzipped (the task call goes from 277 KB to 67 KB), and in a headless browser the list draws in about 0.5 s and a task in about 0.25 s, from about 1.9 s and 1.3 s. A page load renders once, a change to one task makes an open task page read it again only if it is that task, and a page that reconnects, that was still loading when a change was made, or that failed to load is told what it missed and heals without a Retry; the last two are checked in a headless browser (red without the page change, green with it), and the full browser suite fails fewer tests than main does. The list and walk share one build for up to 2 s, so a change only git shows (a commit made outside the page) can lag a read by that long; every action made from the page shows at once. The Goal was met for the web page; the terminal screen was not touched, and the cache headers were left as they were, since loosening them for private roadmap data is the author's choice.
