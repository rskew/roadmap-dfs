# W132 · Add option to stop walk when agent hits session limit

## Goal

Add option to stop walk when agent hits session limit

## Tree

### W132.1 · Stop-on-limit option in the walk's core
Status: confirmed
Approach: In scripts/walk.py add a per-walk flag `walk_stop_on_limit` (default False, reset by `walk_init`, set by `walk_begin(budget, parallel, stop_on_limit=False)` and `walk_start(...)`, which validates it is a bool). `walk_decide` gets a `stop_on_limit` argument: with it, a `limit` stop returns ("stop", "a usage limit") instead of ("hold", ...); `walk_judge` passes the flag, so `walk_off` names the task and the limit and lowers the other chains' caps. `walk_snapshot` reports `stop_on_limit`. Tests in scripts/test_walk.py: off holds as before, on stops and the walk is off, the flag is cleared on the next walk, a non-bool is refused.
Hypothesis: The option is per walk (a flag beside the budget, off by default, not a remembered setting) and "session limit" means the walk's existing `limit` stop, which `limit.py` cannot split into session, weekly or monthly. Wrong if the author wants only the short session limit to stop the walk, or the option kept between walks. .dfs/artefacts/bb787de1-fa2d-45ce-8ebd-519008a86626.html
Evidence:
- for: `limit.py` returns one `limit=0|1` for claude's session and weekly wording, kiro's monthly wording and any 429, so no kind is available to `walk_decide` to filter on.
- against: none found; the option changes only the `limit` branch of `walk_decide` (a `done` chain still runs on) and a walk begun without it holds as before.
Determination: The flag, `walk_decide`, `walk_judge` and `walk_snapshot` work as the Approach says: test_walk.py, test_walker.py and test_limit.py pass, and the two failures in test_web.py also fail on the untouched tree.
