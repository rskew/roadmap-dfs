# W112 · Background should show through create task modal (and others)

## Summary

When a project has a background picture, the web page's dialogs (adding or editing a task, answering, the chat and the rest) and the node sheet on a phone now show that picture instead of a solid panel: it sits under the same 90% veil the page uses and is pinned to the screen, so it lines up with the picture around the dialog, while the task list behind stays hidden and the form reads as before. The Goal is met for everything laid over the page; the top bar, the bottom tabs and the small right-click menu are left solid. On iPhone Safari, which ignores pinned backgrounds, the picture fills the dialog rather than lining up with the page; this was not seen on a device. The page `.dfs/artefacts/cc6f15a0-c072-49de-9c8e-301a23544195.html` sets this beside a fully translucent dialog, the alternative not taken.

## Goal

Background should show through create task modal (and others)

## Tree

### W112.1 · Paint the project's picture into the dialogs and the node sheet
Status: confirmed
Approach: In `scripts/web/index.html`, under `:root[data-picture]`, give every `dialog` (the forms in `#form`, the chat), the phone's node `#sheet` and the sticky button row `#form .row-btns` the background the page has: the picture under a 90% veil, but a veil of `--panel`, with `background-attachment: fixed` so it lines up with the picture behind the page, and `--panel` beneath for a picture with clear pixels. Fields, quotes and menus keep their solid fill. Check: the `picture` UI flow asserts the open dialog's background names the picture, is fixed and has a solid colour beneath; screenshots of the add-task dialog and the node sheet on a phone, light and dark.
Hypothesis: "Background" is the project's background picture, and "show through" means it is seen in what is laid over the page (every dialog and the phone's node sheet), not that the task list's rows and text are seen through them, and not the top bar or the bottom tabs. Wrong if the author wants the page itself visible through a translucent dialog, or the bars to show the picture too. .dfs/artefacts/cc6f15a0-c072-49de-9c8e-301a23544195.html
Evidence:
- for: the page's only background is the picture W50 added (`body::before` under `:root[data-picture]`); before this change the add-task dialog's computed background was a solid `rgb(252, 251, 248)` over it.
- for: a translucent panel at 85% (the parked alternative), screenshotted on this project, shows the yellow task rows and their titles through the add-task form.
- against: in iOS Safari `background-attachment: fixed` is drawn as `scroll`, so there the picture fills the dialog's own box rather than lining up with the page's (not seen; no WebKit runs here).
Determination: Every dialog and the node sheet now show the project's picture under the same 90% veil, lined up with the page's, and the `picture` flow, red without the CSS, passes; `test_ui test_web test_webscreen` fail only the walktags, layout and markdown flows that fail on main. ![the add-task dialog on a phone, the picture showing through](.dfs/artefacts/dca6facd-4f43-4752-bf87-46f7618636ac.png)

### W112.2 · Make the dialogs and the sheet translucent
Status: parked
Approach: In `scripts/web/design.css` and `scripts/web/index.html`, draw `dialog`, `#sheet` and `#form .row-btns` in `--panel` mixed with transparency (about 85%), so whatever is behind them, the picture and the page's own rows and text, shows through under the scrim.
Determination: Parked because it lets the task list's text and coloured rows bleed into the form being written in, which costs legibility for the picture's sake; it is the way if the author wants the page itself, not only the picture, seen through.
