# W96 · Can't reorder an item above a break

## Summary

In the web page's Reorder mode, dragging a task by its grip can now drop it on either side of a break: just above the rule makes it the last task of the segment above, and just below makes it the first of the segment below. Before, the two gaps beside a break counted as one, so no drag could put a task at the end of a segment, and the task next to a break could not be dragged across it at all. The keyboard arrows, the terminal's `[`/`]` and the server already handled breaks correctly, so only the page's drag code changed. A browser test now covers dragging across a break in both directions.

## Goal

Can't reorder an item above a break

## Tree

### W96.1 · Find which way of reordering cannot put an item above a break
Status: confirmed
Approach: Reproduce each way an item is moved across a break in `.dfs/order.md`: `order.moved`/`order.placed` (what the TUI's `[`/`]` and the web's up/down and place call), the web page's arrow keys on a grip (the `reorderbreak` flow in `scripts/ui_flows.mjs`), and the web page's drag by the grip (`dragUpdate` in `scripts/web/index.html`), and name the one that fails and why.
Determination: Only the web page's drag fails: `order.moved`/`order.placed` put `W3` above the break in `W1 W2 | W3 W4` (by up, and by place after `W2`), the `reorderbreak` flow's arrow keys pass, but a new `reorderbreakdrag` flow holding `W3` just above the break draws no drop line and moves nothing, because `dragUpdate` counts only the task siblings, so the gaps either side of a break are one gap and the slot at the end of a segment cannot be reached.
