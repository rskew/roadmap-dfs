# W198 · Long tasks need a way to let the task file grow larger, or a system for progressive disclosure

## Summary

A task file may now grow past 10,000 tokens. A work session no longer reads the whole file: its briefing ends with a digest, which holds the Goal, every live open node whole and each settled node as one line with its Determination. `tree.py digest <task>` prints the digest, `tree.py show <task> <id>` prints any node whole, and step 2 of the skill says to carry on from the digest. The 10,000-token budget now counts the digest, and the file has its own 40,000-token ceiling. The Goal is met by the digest route; the plain budget raise was left aside because every session would still pay for the whole file. The critic and reviewer still read the file whole, and nothing yet shows how well sessions manage on the digest alone, so the critic should look for a session that needed a settled node's Evidence.

## Goal

Long tasks need a way to let the task file grow larger, or a system for progressive disclosure

## Tree

### W198.1 · Measure what makes long task files long
Status: confirmed
Approach: **The question**
- When a task file nears the 10,000-token budget, which part of it is the weight: determined nodes or the live work?

**Why it matters**
- If determined nodes are most of the weight, a session does not need them in full to carry on, and showing them short fixes the cost without cutting the file.

**What this node does**
- Counts tokens (characters divided by four, as `check.py` does) in every `.dfs/items/W*.md`, and splits the three largest by node status and field.

**How we will know it worked**
- We have the number of files near the ceiling and the share held by determined nodes.
Determination: Confirmed: 2 of 197 task files sit at the ceiling (W173 at 9,893 tokens, W48 at 9,848) and 15 are over 5,000; in the three largest, determined nodes hold over 90% of the tokens, most of it Approach text.

### W198.2 · Render a short digest of a task: live nodes in full, determined nodes in one line each
Parent: W198.1
Status: confirmed
Approach: **The question**
- Can one view of a task give a session what it needs to carry on, at a fraction of the file's size?

**What this node does**
- Adds `digest(task)` to `scripts/tree.py` and a `tree.py digest <task>` command. It prints the Goal, Background, and every live open or started node in full. It prints each determined or parked node as its id, title, status, parent and Determination. A node's full text stays one `tree.py show <task> <id>` away.

**How we will know it worked**
- A test in `scripts/test_tree.py` on a task with determined, parked and open nodes: the digest holds the open node whole and the determined node's Determination but not its Approach. On the real files W173, W48 and W139 it is about a quarter to a third of the size. `tree.py show <task> <id>` prints a node whole, shelved fields put back.
Determination: Confirmed: the digest of W173, W48 and W139 is 25%, 29% and 36% of the file in characters, with live nodes whole and the rest one line each.

### W198.3 · Hand the digest to the session and tell it to read that, not the whole file
Parent: W198.2
Status: confirmed
Approach: **The question**
- Does a session do its work from the digest alone, opening a determined node only when it needs it?

**What this node does**
- `brief` in `scripts/state.py` prints the digest in the briefing and names `tree.py show` for the rest. Step 2 of `SKILL.md` stops saying "read the task file whole" for a work session. The critic and reviewer still read the file whole, since they judge the evidence.

**How we will know it worked**
- A test that the briefing holds the digest and the `show` command, and not a settled node's Approach.
Hypothesis: A work session can choose and do its next node from the digest: the live nodes whole and each settled node's Determination. Wrong if sessions need a settled node's Approach or Evidence often enough to read the whole file anyway, or step wrong for want of it. .dfs/artefacts/112a215f-23ff-415f-9183-416bbcbcf5f1.html
Evidence:
- for: Session 1 of this task chose and built W198.2 from W198.1's Determination alone, with no settled node opened. One session, and the same one that wrote the digest, so weak.
- for: In the three largest files, settled nodes hold over 90% of the tokens, so most of what a session reads today is text it does not edit.
Determination: Confirmed: the briefing now ends with the digest, says to open a settled node with `tree.py show`, and the skill's step 2 says the same; the one piece of evidence that a digest is enough is thin.

### W198.4 · Count what a session reads against the budget, and let the file grow past 10,000 tokens
Parent: W198.3
Status: confirmed
Approach: **The question**
- Once sessions read the digest, what should the 10,000-token budget measure?

**What this node does**
- In `scripts/check.py` and `scripts/state.py`, `handoff_verdict` and the size note count the digest's tokens against `HANDOFF_BUDGET`. The file gets its own ceiling, `FILE_CEILING` of 40,000 tokens, about four times the digest of the longest tasks. The refusal text says whether the digest or the file is over. `shelve` reports against the ceiling.

**How we will know it worked**
- A test: a file over 10,000 tokens whose digest is under it takes a new node; a node that takes the digest past 10,000 is refused. Both go red with the old `check.py`.
Hypothesis: Counting the digest against the 10,000 budget, with a 40,000-token ceiling on the file, lets long tasks grow without making sessions read more. Wrong if a file near 40,000 tokens is too big for a session to edit, or the author wants the budget to stay on the whole file. .dfs/artefacts/112a215f-23ff-415f-9183-416bbcbcf5f1.html
Evidence:
- for: `check.py --staged` accepts a node on a 10,000-token file whose digest is under budget, and refuses one that takes the digest over; both tests fail on the old `check.py`.
- for: with each settled node's Determination cut at 240 characters, the digests of W173, W48 and W139 are about 2,000 tokens, so the digest budget has room for about five times that.
Determination: Confirmed: the check counts the digest against the 10,000 budget and the file against a 40,000 ceiling, and the briefing and `shelve` report the same numbers.
