## Tree

### W52.1 · Delete an item: tree.delete_task retires its files under .dfs/archive/deleted
Status: confirmed
Approach: Add `dfs_tree.delete_task(task)` in scripts/tree.py: refuse an unknown task, one a live session is working, or one already retired; move every part of it (`items/<task>.md`, `items/<task>/`, and the same under `archive/items/`) under `.dfs/archive/deleted/` by a plain rename (the commit's `git add` sees a rename); drop its line from `order.md` (children move up a level); never hand its number out again. `scripts/check.py` follows a staged move of the archive file as it already does the task file, and refuses a plain delete as before. Tests in test_tree.py over a git repo fixture.
Hypothesis: Deleting an item means retiring it to a recoverable copy under `.dfs/archive/deleted/`, not erasing it. Wrong if the author wants the files gone for good, with nothing kept beyond git history. .dfs/artefacts/97626278-ee02-472e-bd94-984a3399eacf.html
Evidence:
- for: test_tree's new Check test stages the move and `check.py --staged` exits 0 with the task file, a branch part and the archive moved; the same test shows `git rm` of the task still exits 1 "was deleted". A move needed one line in check.py (the archive loop), an erase would need a new exception.
- for: order.md loses the line and the children keep their place; `next_task_id` and `create_task` refuse the retired number, so a restore cannot collide.
- against: none found; whether the author wants nothing kept is theirs to say.
Determination: delete_task retires an item under .dfs/archive/deleted and the guard accepts the staged move; test_tree.py passes (91 tests), so retiring stands.

### W52.2 · Delete a node: tree.delete_node removes a node and its subtree, logged by a delete entry
Parent: W52.1
Status: confirmed
Approach: Add `dfs_tree.delete_node(task, nid)` and the `delete` log kind (the author's, body = the removed nodes' text verbatim, so the file still holds what was cut). It removes the node and every descendant from the part that holds it, open, parked or determined alike, and refuses a node named by an unanswered raise. `check.py` accepts a removed node only when a new `delete` entry names it, and still refuses any other removal; log entries and `correct`/`backtrack` args naming a deleted node stay valid; `next_node_id` skips ids a `delete` entry names so a number is never reused. Tests in test_tree.py and the check tests.
Determination: delete_node removes a node and its subtree under a delete entry that keeps their text, check.py accepts only that removal, and test_tree.py passes (94 tests).
