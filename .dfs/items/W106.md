# W106 · Bug: seeing a lot of "W111.4 names Parent W111, which does not exist" in the pre commit hook

## Summary

The guard no longer refuses a top-level node that names its own task as its Parent (`Parent: W111` on W111.4): the tool now reads that as a child of the task, the same as leaving the line out, so the commit passes and the node is drawn under the task instead of hanging under nothing. A Parent that names another task or a node that is not there is still refused. The author's own W111 file was not available here, so the fix assumes those messages came from sessions writing the task's id as the Parent; if you would rather keep that a fault, the alternative is to keep refusing it with a message that says to drop the line.
