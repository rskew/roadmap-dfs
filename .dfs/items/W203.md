# W203 · Progressive disclosure task history

## Summary

A task can now be kept as two files: a small status file that every session loads, with the Goal, the standing decisions, what was not taken and only the live nodes and raises, and a history file that holds every node's whole story and is never trimmed. A session finds a node's story with `tree.py show` or by tag, and the briefing, critic and reviewer are given the history of the nodes they work. `tree.py migrate` moves an old task without losing a line, `check.py` holds the hand-kept lines to the history, and the longest task in the repo (W75) now runs from a status file of under 1,000 tokens instead of about 6,000. The Goal was met. The author ruled to leave §0 of the law as it is and not to build a command that commits a chat session's own part; instead SKILL.md tells every session to check a task file's hash before it writes, so workers and several chat sessions can share the one file without overwriting each other (this narrows the window and does not close it). A review then found the briefings still told a moved task's sessions to run commands that refuse it and to write findings where they are not read, the status file's Raises went stale, and the reviewer's and critic's history had no limit; these are fixed (the digest builds Raises from the log, and the history in those two briefings shares one 6,000-token allowance, oldest cut first). A second review found W75 listed no branch as not taken though the author had refuted one, and that `check.py` read the history's `Status:` line instead of the corrected status; W75 now has its Not taken line, `check.py` uses the corrected status and refuses a Not taken line that cites no refuted node. The hand-kept decision lines were tested again against a derived list on W75 and kept, since the derived list was no smaller and needs marks no existing node carries. A third review asked whether the 6,000-token allowance and the 240-character cut of each Determination in the outline are enough: they are stated as an assumption with an answer page for the author to keep or change, and a fault found on the way (the cut was sized on each node alone, so it cut more than the allowance needed) is fixed. The installed tool must be rebuilt from this branch after the merge, since the old one cannot read a task moved to the new format.
