### W151.1 · Does the model revert to the default after the first session?
Status: confirmed
Approach:
**The question**
- Does a chain stop using the chosen model after its first session?

**What this node does**
- Reads `run.sh` (line 1223) and `walk.py` `start_chain`, and runs `test_chain.py` tests for the model choice.

**How we will know it worked**
- The tests show which model each session ran on, and `start_chain` shows when the choice is read.
Determination: Yes, by design: `run.sh` runs the planning session (a work session on a task with no nodes, the critic, the review) on the plan model and every other work session on the implement model, and `start_chain` reads both once at chain start, so a plan model set alone is followed by sonnet; the form never shows this, and passed.

### W151.2 · Record the model each session runs on and give it to the page
Parent: W151
Status: open
Approach:
**The question**
- Can the page learn which agent and model a walk's chain is on right now?

**Why it matters**
- While walking, the form shows the settings for the next chain, not what the running chain uses.

**What this node does**
- `run.sh` writes `model` into the chain's `meta.json` with `meta_set` for each session ("claude default" when none).
- `runs.py` reads `model` and `kind` into the run record.
- `walk_snapshot` in `walk.py` adds `agent`, `kind` and `model` to each chain.
- Tests in `test_chain.py`, `test_runs.py` and `test_walk.py`.

**How we will know it worked**
- A chain run with PLAN_MODEL and IMPLEMENT_MODEL set shows plan then implement models in the snapshot.
Hypothesis: The reading of the Goal is that the form should show what the running chains run on (agent and model per session), and that the two editable model fields should stay as the settings for the next chain.
