# W54 · Artefacts shouldn't have pointless sliders

## Summary

The page template that every assumption artefact is copied from no longer carries a stock "how many of them" slider, so a new page has only the controls its assumption needs, and docs/artefacts.md says a slider belongs only where the assumption turns on a quantity the page shows. The artefact checker also fails a slider that, dragged from its minimum to its maximum and given time to redraw, changes nothing on the page but its own number; it does not flag sliders whose redraw is deferred or driven by a variable on the root element. The Goal was fully met for new pages. "Pointless" was read as "changes nothing the reader can see", so a slider that only changes a figure inside a sentence still passes and the committed artefacts were left as they are; the author can overrule that reading on the page the last step names.

## Goal

Artefacts shouldn't have pointless sliders

## Tree

### W54.1 · The assumption template carries no slider; the docs say when a slider earns its place
Status: confirmed
Approach: Every assumption page is copied from templates/_TEMPLATE_ASSUMPTION.html, which ships a placeholder "How many of them" range input (id knob, 1 to 10) that the author must delete or leave in as a control that moves nothing real. Remove the slider, its output, its state field and its handler from the template; keep the case buttons, the rule and answer boxes. Add to docs/artefacts.md (An assumption's artefact) a rule: a slider, or any input, belongs on a page only when the assumption turns on a quantity and the result text or a drawing changes with it; otherwise use the case buttons or details. Add a test in scripts/test_templates.py that the template has no range input. Existing artefacts stay as committed.
Determination: Confirmed: the template has no range input, docs/artefacts.md says a control must change something visible and a slider only when the assumption turns on a quantity, test_templates passes, and artefact_check on the template is clean with fonts. ![the template at 360px: case buttons, result, what would show it wrong, no slider](.dfs/artefacts/c6a2f1d0-54b1-4e2a-9d7e-5a0e3b7f1a54-mobile.png)

### W54.2 · artefact_check.mjs fails a slider that changes nothing the reader can see
Parent: W54.1
Status: confirmed
Approach: In scripts/artefact_check.mjs, for each input[type=range] on the page, set it to its min then its max (dispatching input and change events) and compare document.body.innerText and the outerHTML of any svg/canvas between the two; if identical, report `slider: "<name>" changes nothing on the page`. Test with two small pages (one pointless, one live) through artefact_check.sh; mention the check in docs/artefacts.md step 3.
Determination: Confirmed: artefact_check.sh now fails a range input whose min-to-max sweep leaves the page unchanged apart from its own label and output; a dead page fails and a live one is clean (new test_artefact_check.py, both pass), and the four committed slider pages still pass, so the check does not flag a slider that does something. The Goal is met.

### W54.3 · check.py refuses a Hypothesis page whose range input no script reads

### W54.4 · Fix: artefact_check refuses sliders that do change the page (deferred redraw, state outside <body>)
Parent: W54.2
Status: confirmed
Approach: In scripts/artefact_check.mjs (the `dead` page.evaluate in pass()), each slider is set to min and max and the page is snapshotted synchronously, and the snapshot is only a clone of document.body's innerHTML plus canvas data. Two pages that really do change what the reader sees fail with `slider: "k" changes nothing on the page but its own number`: (a) the input handler updates the result inside requestAnimationFrame or a setTimeout (any canvas/animated redraw), so the synchronous snapshot sees nothing; (b) the handler sets a CSS custom property or class on document.documentElement (`--w` driving a bar's width), which a body clone does not include. Both were reproduced by running artefact_check.sh on two small pages (slider id k, min 1, max 10 or 100). Fix: after setting each value, await a frame or two (make the evaluate async, `await new Promise(r => requestAnimationFrame(() => requestAnimationFrame(r)))`), and include document.documentElement's style/class attributes and the computed size of body descendants (or take the two screenshots and compare pixels with the slider and its label masked) in the snapshot. Add tests to scripts/test_artefact_check.py for both pages (no `slider:` in the output); keep the dead-page test failing. Run with FONTCONFIG_FILE set to a fonts.conf for the nix-store dejavu/liberation dirs, inside `nix shell nixpkgs#playwright-test` if playwright is not on PATH.
Determination: Confirmed: artefact_check.mjs now waits two frames and 120ms after each slider value and snapshots the root and body attributes plus each element's size and look, so a deferred redraw and a variable set on <html> both pass (two new tests fail on the old checker, all four pass now), the dead-page test still fails, and the five committed slider pages are clean.

### W54.5 · Minor findings from the review
Parent: W54.2
Status: confirmed
Approach: One line per finding.
- W54.1 and W54.2 carry no Hypothesis though each narrows the Goal: "pointless" is read as "changes nothing visible", so a slider that only changes a number inside a result sentence (the old template's own slider) still passes artefact_check, and existing artefacts were left unchanged; add the Hypothesis (and what would show it wrong) to the node that takes this up, and say in docs/artefacts.md that the check catches only dead sliders, not ones whose effect is trivial.
- scripts/artefact_check.mjs treats an `<output>` as the slider's own readout and strips every `<output>` from the snapshot, so a page whose real result lives in an `<output>` is flagged dead; docs/artefacts.md step 3 should say a result goes in a normal element, not `<output>`.
- scripts/test_artefact_check.py skips (not fails) when no browser renders, so on a machine without fonts or playwright both tests silently pass as skipped.
Hypothesis: "Pointless" in the Goal means a slider that changes nothing the reader sees but its own number, so one that only changes a figure inside a result sentence passes artefact_check and committed pages are left as they are. Wrong if the author counts a number-in-a-sentence slider as pointless, or wants committed pages stripped of such sliders. .dfs/artefacts/352fd81f-e530-4bdb-bbc1-c395bce72ce9.html
Evidence:
- for: the repo template's old slider was read by script yet moved only a number in a sentence, and artefact_check flags none of the five committed slider pages, so no committed page is a dead slider.
- against: no committed page was read to judge whether its slider earns its place beyond the dead-slider check.
Determination: Confirmed: docs/artefacts.md now says a result goes in an ordinary element and not an `<output>` and that the check refuses only a dead slider, the narrowed reading of "pointless" is now a stated assumption with a page to rule on it, and test_artefact_check fails instead of skipping when DFS_REQUIRE_BROWSER is set. The Goal is met. ![the assumption page at 360px](.dfs/artefacts/352fd81f-e530-4bdb-bbc1-c395bce72ce9-mobile.png)
