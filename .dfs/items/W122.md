# W122 · Sometimes pressing archive on the item opens the item instead

## Summary

A press on a task's archive button now archives (opens the confirm) even when the list moves under the finger between press and release, which is when the browser used to aim the tap at the row beneath and open the task. The page remembers which button each press began on and runs that one when the click lands on a different button; keyboard and script clicks are untouched. The Goal is met for the cause reproduced in a real browser (a redraw that changes a row's height); the new browser flow could not be run here because playwright is missing, so it was checked only through the same steps driven by hand over the DevTools protocol. A tap whose click lands on no button at all is still dropped, and whether other causes of "sometimes" exist is left for the author to rule on from the page the last step records.

## Goal
