# W69 · Add small archive button on the left side of each item when complete, reviewed and pushed

## Summary

The web task list now shows a small archive button under the id, on the left of any task that is done, reviewed (or accepted) and has nothing waiting to be pushed or committed. Pressing it and confirming moves the task's files under `.dfs/archive/archived/`, takes it out of the list and the order, and keeps its number from being reused; moving the files back restores it. The Goal was met for the web list; the terminal list has no archive key, and archiving is a file move rather than a flag so it reuses the path that Delete already has.

## Tree

### W69.1 · Archive a finished task by moving its files out of the list
Status: confirmed
Approach: `tree.py` gains `archive_blocker(task)` (empty when archivable) and `archive_task(task)`. A task is archivable when `status_of` is done, a review or an author's accept is in its log, `unpushed()` can compare with origin and shows no commit of the task ahead, `uncommitted()` shows none of its files, and no live run is on it. `archive_task` is `delete_task`'s move with a different target, `.dfs/archive/archived/`, and `retired_ids` counts that directory so the number is not reused. `test_tree.py` covers each refusal and the move.
Hypothesis: "Archive" means the task leaves the list and order and its files move to `.dfs/archive/archived/`, "reviewed" means the finished tree has an implementation review or the author's accept (a done status already needs one of them), and "pushed" means no commit of the task is ahead of origin and no file of it is uncommitted. Wrong if the author wants an archived task to stay in `.dfs/items` or to return by a button rather than by moving files back, or means by "reviewed" the author's accept alone. .dfs/artefacts/bb858ebc-8ef1-4e92-9cfa-215ac52a0ddc.html
Evidence:
- for: `status_of` already returns done only after a review ok or an accept (or for a task that never had a work session), so "complete and reviewed" is `done` plus a review or accept entry in the log; no separate accept is needed.
- for: the new test in `test_tree.py` walks every refusal (not done, no origin, origin lacks the branch, a task commit ahead, uncommitted edit) and the move; `python3 scripts/test_tree.py` ran 99 OK, and with the unpushed check disabled it went red.
- against: `test_web.py` has one failure, the chat test, which fails the same on the commit before this change.
Determination: Confirmed: `archive_task` moves a done, reviewed, pushed and committed task under `.dfs/archive/archived`, drops it from the order, and keeps its number taken.
