# W80 · fix branch task handling in app

## Summary

The web app now opens branch-tagged tasks such as `W1@serve-real-records` correctly. The server decodes each percent-encoded task, chat, run and artefact address segment and checks it against its pattern. Chats accept tagged task names too. In the task list, the rail and the chats list, a tagged task shows its number in the id column and its tag as a small line above the goal, so the row fits from a 320px phone to a wide screen. The Goal was met and is covered by a server test and a browser flow that opens a tagged task and its node, reloads and goes back. Five older browser flows fail with or without this change and were left alone, since they concern other features.

## Goal

Goal: Branch-tagged tasks such as W1@serve-real-records render legibly and open correctly throughout the DFS web app, with the exact task ID preserved across browser routing and HTTP requests so roadmap projects remain usable when work is scoped on a non-default branch.

1. Add a regression proving a percent-encoded branch-tagged task ID opens through the web endpoint.
2. Decode and validate individual dynamic URL segments before resolving task, chat, run, and artefact identifiers.
3. Make tagged task IDs fit the task list cleanly at narrow and desktop widths.
4. Exercise tagged task and node navigation and run the DFS web test suite.
