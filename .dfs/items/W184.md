# W184 · tree.py log waits forever for input whenever an agent runs it from its shell

## Summary

`tree.py log` and `tree.py add` no longer hang when an agent runs them from a shell whose stdin is an open pipe that nothing writes to. They wait up to one second for a body to start, read it to the end if one comes (heredoc, file or pipe), and otherwise carry on with no body. The Goal is fully met. Two older tests in `scripts/test_tree.py` (`AppendLog` review `issues` cases) already failed before this change and were left alone, since they are not about this fault.

## Goal

tree.py log waits forever for input whenever an agent runs it from its shell

## Tree

### W184.1 · tree.py log and add read stdin only when a body is actually sent
Status: confirmed
Approach: **The question** - `tree.py log` and `tree.py add` call `sys.stdin.read()` whenever stdin is not a terminal. An agent's shell gives them a pipe that is open and never written, so the read never ends. How do we read a body that is sent, and skip one that is not? **Why it matters** - Every session logs verdicts and raises through `tree.py log`. A hang there stalls the whole session. **What this node does** - Adds `read_body()` in `scripts/tree.py`. It returns "" for a terminal. Otherwise it waits up to one second for the first bytes with `select`, then reads until end of input, and stops at the end or if the writer goes quiet for a second. - `_main` uses it for `log` and `add`. A heredoc, a file redirect and `echo ... |` all deliver within that time. **How we will know it worked** - New tests in `scripts/test_tree.py` run `tree.py log` as a subprocess with an open, silent stdin pipe: it must return, and without the change it must hang (checked red first). Other tests check a heredoc body and a slow writer still arrive whole. `scripts/test_tree.py` passes.
Determination: `read_body()` makes `tree.py log` and `add` return on a silent open stdin, and the new tests failed without it and pass with it, so the Goal is met.
