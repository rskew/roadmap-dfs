# W131 · Optimise the UX

## Summary

The work measured where the author's time goes from the logs as they stood on 2026-11-05: 50 raises, 21 written by the runner (since stopped) and 29 by sessions. Session raises are long (median 326 words) yet usually answered in a few words, and the 6 that name an answer page were answered faster (median 2.2 hours against 3.4), a hint only. Of 165 artefact pages, 127 can post a ruling and none is empty, but 36 of the 73 Hypothesis pages written since W100 never say what would show their assumption wrong, and the web confirm/refute dialog shows only the page (the accept dialog and the terminal show the test). Two changes were built, and neither changes what any rule refuses: the raise template in `SKILL.md` opens with a "What I need from you" line, and `scripts/check.py` prints a note (not a refusal) when a new or changed Hypothesis's page never says what would show it wrong; the logs cannot show the line helps (the four raises that already opened with the ask were answered in 1.8 hours against 3.2, but they ask different things and the answers are no shorter), and the page for each lets the author reverse it. The tree pane of the terminal screen and the web page's DOM were checked without drawing them: nothing is cut off at the edge, every old finding is carried, but an opened node still fills the 18-row pane at 80x24 and scrolls its title out, the closed web row never shows the "wrong if", and the closed node's "wrong if" is clipped at 80 columns, so those old findings are half fixed; colour, layout and the real footer and side panel stayed unseen because this sandbox cannot draw text. A one-page decision view per task and a link to the code explainer were left unbuilt because the existing views carry the same content.

## Goal

Following from our optimisation of the dfs flow, do some broad research and experimentation into how we can improve the UX around task management. The goals are to enhance user understanding of assumptions and raises, and reducing the time required of the user. In other words, let the user spend less time guiding the process, but enable them to get a deeper understanding of the system in that shorter time.
In focus are things like integration and quality of artefacts, presentation of tasks and nodes, appropriateness and informativeness of raises, and possibly integration if interactive system exploration and design tools, maybe others too (be creative)
