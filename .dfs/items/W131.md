# W131 · Optimise the UX

## Summary

The work measured where the author's time goes from the logs as they stood on 2026-11-05: 50 raises, 21 written by the runner (since stopped) and 29 by sessions. Session raises are long (median 326 words) yet usually answered in a few words. 15 of the first 28 report a roadmap-tooling fault and wait for an answer like any raise (a median 3.2 hours across all raises); asked whether a session with a workaround could note the fault and go on, the author said to keep raising each one, so that rule is unchanged and no such option was built. The 6 that name an answer page were answered a little faster (median 2.2 hours against 4.9 for 18 others; a shuffle gives a gap that large 1 time in 10, so it is a lean and not a finding), and the raise template now asks for a page on a raise that offers options, with a "What I need from you" opening line (the logs cannot show it helps). Of 174 artefact pages, none is empty and 133 posted both a Confirm and a Refute through the real server and were read back from the task file; the 41 that cannot are 38 pages with no server call and 3 with no rule buttons, 13 of them named in a Hypothesis from W7 to W46, before the guard. One of the 133 takes its note in a box called `why`, so its typed note was not written. 38 of the 73 Hypothesis pages written since W100 never say what would show their assumption wrong, so `check.py` now prints a note (never a refusal) when a new Hypothesis page does not.

In the terminal screen and the web page it changed what the author reads. The tree pane's rule keeps the task, status and "12 sessions since you spoke" on screen when an opened node scrolls the title away. A closed node's "wrong if" wraps whole and ends at the test, also under the closed web row. An opened node shows a `Code files` line (cached by commit, saying how many commits it did not read), and its Approach is drawn as labels and bullets, not one run-on paragraph. The Accept dialog shows each assumption's first four evidence lines, with "for" and "against" as coloured words, in a list that scrolls so Cancel and Accept stay in view; the terminal's accept prompt is one short line ("8 assumptions on H, 35 notes in the tree") that points at `H`, which lists the same evidence under a heading per task and opens on the task being accepted. Evidence moved to the archive had been hidden on the node sheet and now shows. A one-page decision view and a link to the code explainer stay unbuilt, because the dialog carries the same words and explainer notes exist for 3 files (8% of node commits).

The web page was driven in headless chromium at 320, 390 and 1280 px for the first time: reading and answering a raise, adding a node, Reorder, the keyboard, every dialog (they now open at their heading), and the walk controls and run log against a stub runner. No sideways scroll, unlabelled control, low-contrast text or console error remains. Faults fixed: Chats on a `--no-walk` server says chat is off, the phone adds a task from a tab (the floating button covered badges), the fold button is 44 px, the Answer dialog no longer squeezes the answer page, the note box is no longer 20 px high, and the runner path no longer widens the walk box. The artefact pages were drawn too: 7 had no viewport meta, 4 W75 pages drew wider than a phone, and one chat page drew both outcomes. The artefact templates now wrap a long unbreakable word in prose (`break-word` on paragraphs, list items, headings and diagram boxes), in the answer form's option and park-box labels (`anywhere`, since their text is a flex item) and in the diagram's row of boxes from 720 px (`min-width: 0`); a first try with `anywhere` on the body split 113 ordinary words on 16 of the 175 existing pages, mostly in tables, so it was dropped, and a long word inside a table cell still widens the page, as it did before.

What was not seen or not fixed: the terminal's colour, real footer and side panel were never drawn; the Stop walk button, a usage-limit hold and two chains at once were not driven; two W1 mock-ups stay 880 px wide; the 13 old Hypothesis pages that cannot post were left because their tasks are finished. In the test suites, `test_web`, `test_chat` and two tests in `test_tree` fail the same without these changes; one `test_web` test (the new-page SSE read) times out in a full run and passes alone, so it is flaky. The web page's link cutter turns any `[x](y)` into `x`, so evidence quoting code such as `a[0](b)` loses its brackets. The dialog scroll reset is pinned by a source check only, and `docs/ux-web-dialogs.py` draws it but needs playwright.

## Goal

Following from our optimisation of the dfs flow, do some broad research and experimentation into how we can improve the UX around task management. The goals are to enhance user understanding of assumptions and raises, and reducing the time required of the user. In other words, let the user spend less time guiding the process, but enable them to get a deeper understanding of the system in that shorter time.
In focus are things like integration and quality of artefacts, presentation of tasks and nodes, appropriateness and informativeness of raises, and possibly integration if interactive system exploration and design tools, maybe others too (be creative)
