# W156 · artefact_check.sh reports every page blank when fontconfig has no default config

## Summary

`artefact_check.sh` no longer calls a text page blank on a box with no fontconfig default config. It now writes a small font config listing the font directories it can find and points the browser at it, so such a box checks clean. If it finds no font directory at all, it reports `no fonts available` instead of `blank`. The Goal is met in full; two tests cover both cases.

## Goal

`scripts/artefact_check.sh` fails every page with `FAIL blank: the page rendered no text and no graphic` on a box with no fontconfig default config, even a page with text. Found while working W153 (filed there as a draft, not fixed there).

Seen on 2026-11-06 on a box where `fc-list` prints `Fontconfig error: Cannot load default config file` and `/etc/fonts` does not exist: `sh scripts/artefact_check.sh templates/_TEMPLATE.html` printed `FAIL blank` at 1200 px and at 360 px and `2 failures`. The same command with `FONTCONFIG_FILE` naming a config that lists the DejaVu font directory printed `clean`. The page is not blank; the browser has no font to draw text with.

Goal: the check does not report a false `blank` when the cause is a missing font config. Either it sets a minimal `FONTCONFIG_FILE` itself when none loads, or it says "no fonts available" instead of "blank". A session on such a box can then trust a `blank` report.

Re-run on 2026-11-08 (W153.51): `artefact_check.sh` on a page of W153 (and on an older artefact) printed "blank" twice with the box's default fontconfig error; with `FONTCONFIG_FILE` pointing at the DejaVu fonts directory the same page checked clean. The case reproduces.

## Tree

### W156.1 · Write a minimal fontconfig file when none loads
Status: confirmed
Approach: **The question**
- Can artefact_check.sh stop the false `blank` by pointing the browser at a font config it writes itself when the box has none?

**What this node does**
- In `scripts/artefact_check.sh`, just before it starts node: if `FONTCONFIG_FILE` is unset and no `/etc/fonts/fonts.conf` exists, write a small fontconfig file to a temp path and export `FONTCONFIG_FILE` to it. It lists font directories found from `fc-list : file`, plus any `*dejavu*` font directory in `/nix/store`.
- If no font directory is found, export `ARTEFACT_NO_FONTS=1`. In `scripts/artefact_check.mjs`, a blank page then reports `no fonts available` rather than `blank`.
- Add a test in `scripts/test_artefact_check.py`: a text page on a box with `FONTCONFIG_FILE` unset and no config does not report `blank`.

**How we will know it worked**
- A text page checked with a fontconfig-less environment prints `blank` before the change and `clean` after.
Determination: A text page that printed `blank` twice now checks clean on this box, and a box with no font directory at all reports `no fonts available`; the two new tests fail without the change and pass with it.

### W156.2 · Only say "no fonts available" instead of "blank"
Parent: W156
Status: parked
Approach: Leave the browser environment alone. When the page is blank but its `textContent` is not, report `no fonts available` instead of `blank`.
Determination: Parked: it only relabels the failure, so a session on such a box still cannot get a clean check. Taken if writing a config proves unreliable.
