# W134 · Fix two faults in the replay tooling (scripts/replay.py)

## Summary

Two of the three faults were already fixed in the repo when this task ran: a cut-off replay now resumes with `run` because the box's docs are rebuilt, and `candidates` finds a checkout recorded under another path when given `--recorded-as PATH`. I reproduced the resume crash with the older file and showed the current one passes, and showed `candidates` listing the task with the flag and printing a hint naming the likely project without it. The Goal reads as if `--repo` alone should be enough, but the recording path cannot be derived from a copy, so I kept the flag and left a name-matching option for the author to choose on the page. For the third fault, the repo's `replay.py` already follows the configured agent; the installed package was built from an older commit, which a task cannot rebuild, so `docs/dfs-optimization.md` now tells a session to use the main checkout's `replay.py` and how to check an installed one.

## Goal

Fix two faults in scripts/replay.py that the optimisation loop (W130) found while running its control arm.

1. `replay.py run DEST TASK` on a replay that was cut off (a 30-minute tool limit killed W36's chain) crashes with FileExistsError in `tool_docs`: `out.mkdir(parents=True)` runs on the box's `docs` directory, which already exists. docs/dfs-optimization.md says a cut-off replay is resumed with `run`, so a resume must work. The workaround is to delete `<DEST>-box/docs` first.
2. `replay.py candidates --repo PATH` matches transcripts to the repo by its path, so a checkout under optimisation-data/ (shop-app, farm-app) finds none even where tasks qualify; the starting-point check is the real filter. The command should find the transcripts of such a checkout.
3. The installed tool's replay.py (the nix store build named in a session's briefing, 45a2fcd-dirty) is older than the repo's scripts/replay.py: it has no `--agent` (its `replay` fails with "too many values to unpack") and its `run.sh` call never passes `--kiro`, so a replay started from it runs claude whatever `.dfs/runs/agent` says, although docs/dfs-optimization.md says it follows the configured agent. W130.4 started two replays that way before noticing (claude hit its usage limit, 1.18 dollars spent, both discarded) and ran the real ones with `python3 /workspace/roadmap-dfs/scripts/replay.py` from the live checkout. A session working from the installed tool should get a replay.py that matches the repo's, or be told which one to use.
