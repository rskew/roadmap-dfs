## Goal

Since we've reversed the lost order, adding a break to an item should place the break above it

## Tree
### W180.1 · Read the goal: "above" is above on the screen
Status: confirmed
Approach: **The question**
- The list is drawn last task first (W162), so a break that `b` adds sits under the task it holds. Which "above" does the Goal mean?

**What this node does**
- Fixes the reading before any code. "Above" is above on the screen. `b` on a task puts the break between it and the task drawn over it, so in `.dfs/order.md` the fence goes right after the task's subtree and the task is on the done side. `b` on a task that already has such a fence takes it away. The top task (last in the file) is refused, since nothing waits behind it. A nested task is still refused. `B` (stop break) follows the same place.
- The order file, the walk and how a fence is drawn do not change.
Hypothesis: "Above it" means above on the screen, so the fence moves from before the task to after it in order.md. Wrong if the author means only a changed word on the screen, or wants the fence kept before the task in the file. .dfs/artefacts/2eedd732-2d4b-41ac-bfa5-2636beefac10.html
Evidence:
- for: `order.py` `break_toggled` puts the fence before the item in the file, and W162 draws the list last first, so the fence is drawn below its item today; "above" asks for the opposite side.
- for: `test_web.py` `test_the_task_list_is_drawn_last_task_first_with_a_break_under_the_task_it_holds` pins the fence under the task it holds, so the break is the thing that stays and the key's side is what the Goal changes.
Determination: Taken as the working reading, since it is the only one that makes the fence land above the selected task on the screen; the author can refute it on the page.
