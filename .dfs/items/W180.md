# W180 · Since we've reversed the lost order, adding a break to an item should place the break above it

## Summary

Pressing `b` (or `B` for a stop break) on a task now puts the break above that task on the screen. Since the list is drawn last task first, the fence goes right after the task in `.dfs/order.md`, so the task and everything below it are on the finished side. The terminal, the web Reorder buttons and the order API follow, and now refuse the top task (nothing above it to hold) and allow the bottom one. "Above" was read as above on the screen, not as a changed word; the order file and the walk are unchanged. The browser flows could not be run here, since there is no playwright.
