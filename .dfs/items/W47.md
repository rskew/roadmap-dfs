# W47 · Tell from the web page whether a node is complete, started or open

## Summary

Each live node on the web page's task tree now shows a mark before its id: a tick for a confirmed node, a filled circle for an open node a session has started, and an empty circle for one not yet begun, each with an aria-label, so state no longer rests on the colour of the left rule. A session marks its node with `tree.py start <task> <node>`, which edits the task file without committing, and the node's closing commit replaces that with its ruling; the work briefing says to run it, and everything else reads a started node as open. The terminal tree draws the same three marks. The Goal was fully met; the circles on the page are drawn in CSS rather than typed, because a fallback font filled the typed empty circle and made the two read alike.

## Goal

On the web page's task tree, every node shows its state in a mark and not only in the colour of its left rule: a tick for a complete (confirmed) node, an empty `o` for an open node not yet started, and a filled-in `o` for an open node whose implementation has started. "Started" is a status the node itself carries: a session marks the node started when it begins to change code for it, and the node's closing commit replaces it with its ruling. From the task page alone, without relying on colour, the author can see which nodes are finished, which are underway and which are not begun.
