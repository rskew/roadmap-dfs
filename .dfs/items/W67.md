# W67 · Reenable the shell tool in chat sessions

## Summary

The web page's chat turn (`run.sh --chat-turn`) now runs with the same permission-skipping flags as the screen's chat, so a page chat has the shell and every other tool, Edit and Write included, and nothing is refused. Its framing no longer tells the agent not to edit files or add to a log, the comments, docstrings and a test say full permissions, and the web server's warnings name the chat beside the walk as what `--no-walk` turns off. The Goal's shell is met, with more than the shell: the author ruled that page chats should have what the screen's chat has, since the exposure is the one the unauthenticated port already has and the chat stays switched off by `--no-walk` with the walk. It was checked against a stub claude, not a real one: the chat test suite passes 26 of 26, and a real claude run was left to the author, since it starts a permission-skipping agent and bills a call. The page's empty-chat text now says the agent has full permissions instead of that it changes nothing, and a browser flow checks it.
