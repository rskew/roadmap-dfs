# W181 · Collapse branches by default in the app

## Summary
The web page's task view now opens with every branch (a node that has children) folded. The author's own folds are kept for the rest of the visit, and a page opened on a node, "Next flagged", or a node just added under a branch unfolds the way to it. A folded row shows how many raises sit below it, so a fold never hides a raise. I took "the app" to mean the web page, not the terminal screen, whose tree is still unfolded at the start; that reading is the open question on the first node.

## Goal

Collapse branches by default in the app

## Tree

### W181.1 · Web task page opens with its branches folded
Status: confirmed
Approach: **The question**
- How does the web page's task tree start folded, without hiding what the author must answer?

**What this node does**
- In `scripts/web/index.html`, the first time a task is read, `S.folded[task]` is set to every node that has children. Later reads keep the author's own folds.
- A node opened by link, or by a new child added under it, has its ancestors unfolded, so the open node is never hidden.
- A folded row keeps its "raises below" chip, so a raise under a fold stays visible.

**How we will know it worked**
- `test_web.py` runs the new fold-default function under node: branches fold, leaves do not, a routed node's ancestors unfold, a second call keeps the author's folds. It is red without the change.
- The existing UI flow test for folding is updated to the new start, and run if a browser is available.
