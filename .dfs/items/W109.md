# W109 · Bug

## Summary

A task file written in the main checkout and never committed now reaches the task's worktree whichever way the walk enters it: on a fresh branch, as before, and now also when the branch or the worktree was left by an earlier attempt, which is where the reported stop came from. The file is moved across uncommitted and the first session commits it on the task's branch; edits to a file the worktree already holds stay in the main checkout, as they did. The Goal is met by moving the file rather than by either fix the report suggests: the walk still never commits on the author's default branch, and the up-front refusal was not added because the file no longer needs a manual commit.

## Goal

Bug report for the dfs tool

> A new task file that isn't committed stops the walk when it reaches that task
>
> *What happened:* The walk reached W117, which had been created in the main checkout but never committed. It created the worktree .dfs/worktrees/W117 from main, then stopped with "walk off — W117: a session could not be briefed: the worktree … has no .dfs/items/W117.md, which the main checkout has: the branch carries only what git tracks" (runs/activity.log, 1792668065). The same applies to W118, W120, W121 and W122, which were untracked at that point.
>
> *Expected:* A task file that exists in the main checkout is briefed without a manual commit, or the problem is caught earlier.
>
> *Suggested fix, either of:*
> 1. The walk commits new or changed .dfs/items/*.md and order.md on the main branch before it cuts a worktree.
> 2. The step that creates a task file (run.sh --open, the TUI's new-task action, a chat session) commits it. Failing that, the walk should refuse before starting and say which files are untracked, not spend a chain launch to find out.
>
> *Repro:* Create .dfs/items/Wn.md without committing it, list it in order.md, and let the walk reach it.

Status: confirmed
Approach: In a scratch repo built like `test_chain.Chain`, write an untracked `.dfs/items/W2.md` and run `run.sh W2 1` three ways: no `dfs/W2` branch yet; a `dfs/W2` branch already cut from main (an earlier attempt that died after the cut); and a `dfs/W2` worktree already added. `branch.enter` calls `carry_uncommitted` only when it cuts a fresh branch.
Determination: The fresh cut moves the file into the worktree and the session runs, but a reused branch ("dfs/W2 existed; reused, and W2's uncommitted edits here are left as they are") and an existing worktree both stop with "the worktree … has no .dfs/items/W2.md, which the main checkout has: the branch carries only what git tracks", the reported failure, before any session starts.
