# W88 · The pre-commit check judges a first-time commit of old files as new damage

## Summary

The pre-commit guard now judges a task file git already holds only on what a commit changes: a rule violation, an unstaged artefact name or a coordinate the file already had at HEAD no longer refuses later commits. The commit that first brings a roadmap's task files into git, made on `main`, is grandfathered: its findings, including oversized files and artefact pages it does not stage, are printed as notes and none refuses it, and the README and `init.py` explain this as the way to adopt an existing `.dfs`. Two things differ from the Goal's wording: a task file added after git already holds others, and any commit on a `dfs/<task>` branch, is judged in full, because a new roadmap's first node is committed there and grandfathering it would let that node skip the guard, so adopting a roadmap a few files at a time is not covered (a baseline file of known findings was the alternative considered, `.dfs/artefacts/ba5e1eae-d498-46ab-af48-190d669ee191.html` shows the options). A file adopted over the size budget is still refused when a later commit adds to it, until it is shelved; the README says so.

## Goal

The pre-commit check judges only what a commit changes, and treats files with no history as grandfathered, so adopting an existing roadmap directory does not mean rewriting old tasks or bypassing the hook.

When previously untracked task files are staged, the check treats every existing violation as introduced by that commit. The size check reports "GREW it (~0 before)" for files with no earlier version to compare with. Rules added after a task was written fail it retroactively; in one project that was 92 findings across about 40 tasks: a Hypothesis with no artefact page named (29), a Parent that is a task id rather than a node (about 40), artefact pages referenced but not staged or not found (6), and two files over the token budget. The check also requires every referenced artefact to be staged, which pulls in a project's whole artefact directory (about 200 files, 17 MB in that project). The only ways through are rewriting old tasks to satisfy newer rules or bypassing the hook, and bypassing disables the guard for that commit.

Done looks like:
- A commit is judged only on what it changes; files with no history are grandfathered (no "GREW it (~0 before)", no retroactive rule findings).
- Referenced artefacts are not all required to be staged with a first-time commit.
- There is a documented way to adopt an existing roadmap directory, or a stated way to baseline known findings.

Worth doing: the guard is only worth having if people can leave it on; today the first commit of an existing roadmap pushes them to bypass it.

## Tree

### W88.1 · Judge a tracked task file only on what the commit changes
Status: confirmed
Approach: In `scripts/check.py` `main`, for a task file HEAD holds, refuse only what this commit introduced: a `check_shape` finding is refused when HEAD's copy (with HEAD's archive) does not already produce it, `check_attachments` judges only the artefact names the commit adds to the text and archive, and the coordinate warning skips a file the commit leaves unchanged. Tests in `scripts/test_tree.py`: an old shape fault (a Parent naming the task id) and an old unstaged artefact name at HEAD no longer refuse an unrelated commit; the same fault or name added by the commit still does.
Determination: Confirmed: `check.py` now refuses only the shape faults and unstaged artefact names a commit adds to a file HEAD holds; the two new tests fail on the old guard and pass on the new, and `test_tree`, `test_ignored` and `test_walk` pass (`test_init`'s outside-git case fails only because the test temp dir had to sit inside this repo, /tmp being noexec).

### W88.2 · Grandfather the commit that first brings a roadmap's task files into git
Parent: W88.1
Status: confirmed
Approach: In `scripts/check.py`, when `.dfs` is committed (not gitignored) and HEAD holds no task file under `.dfs/items`, the commit is the roadmap's adoption: every file is judged with no history, so each finding (shape, Hypothesis artefact, Ask, writer, unstaged artefact, size) is printed as a grandfathered note and none refuses; the size check never reports "GREW it (~0 before)". A task file new to an already-tracked roadmap is still judged in full. Tests in `scripts/test_tree.py` for both.
Hypothesis: "Files with no history are grandfathered" means the files of a roadmap git has never held, so the adoption commit is told apart by HEAD holding no task file, and a task file new to a roadmap git already holds (a task written from the screen, a branch's part) is new work, judged in full. Wrong if the author wants task files added to an already-tracked roadmap grandfathered too, for adopting one piece at a time. .dfs/artefacts/ba5e1eae-d498-46ab-af48-190d669ee191.html
Evidence:
- for: `branch.py` `carry_uncommitted` says a task written from the screen is left uncommitted for "the branch's first session" to commit, so a new task's first node lands in a file with no history; `test_tree` `test_a_plain_commit_adding_the_same_hypothesis_is_still_refused` refuses a Hypothesis in a new branch part, and still passes.
- for: `test_the_commit_that_adopts_a_roadmap_grandfathers_what_its_files_hold` (a Parent naming the task, a Hypothesis with no page, an unstaged artefact, over the budget) fails on the guard before this node and passes after; `test_a_task_file_new_to_a_tracked_roadmap_is_judged_in_full` refuses the same file once HEAD holds another task.
Determination: Confirmed: the commit that first brings a roadmap's task files into git has its findings printed as grandfathered and passes, while a task file new to a tracked roadmap is judged in full and a new file over the budget reads "ADDS it" rather than "GREW it (~0 before)"; `test_tree`, `test_ignored` and `test_walk` pass.

### W88.6 · Fix: a new roadmap's first task commits are taken for an adoption and pass unjudged
Parent: W88.2
Status: confirmed

Determination: Confirmed: `check.py` adopts a roadmap only off an item branch `dfs/<task>`, so a new roadmap's first node there is judged in full; the new test fails on the old guard and passes now, the adoption test still passes, and `test_tree`, `test_ignored`, `test_walk` and `test_templates` pass (`test_init`'s outside-git case still fails only because the test temp dir sits inside this repo).
