# W41 · Show at least one line of item name

## Summary

A finished task collapsed in the web app's list now always keeps its name on one line, cut with an ellipsis; when its status and tags (not on main, uncommitted) would leave the name under about ten rem, they wrap to a second line under it instead of squeezing it out. A task's own screen already shows the name in full in its heading, so the bar change tried first was taken back out. The wrapping was checked in a browser flow that is written but could not be run here (no playwright), so it is unverified in a rendered page.

## Goal

Show at least one line of item name

Status: confirmed

Evidence:
- for: before the change chrome() set the task bar to `id` over `status` only, and the new test fails on that markup ("'W1<small>open</small>' != '<span class=\"tname\">W1 · ..."") and passes with the change.

- against: tui.py puts the goal last on each list row, after the id, status, review, ahead and tag cells, so on a narrow terminal it may be cut to nothing; not measured, and that reading is not what was done (W41.2).
- against: no screenshot of the bar: the browser here draws no text (artefact_check.sh fails "blank" on an old artefact too) and 13 of test_ui.py's flows fail in it, the artefacts flow included, with or without the change, so the flow assertion was written but not run.
Determination: Confirmed as far as the page's code shows: a task's bar now carries its name on one line, pinned by a test that is red without it; the Goal is met on this reading, unverified in a rendered browser here.
