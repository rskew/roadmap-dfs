## Goal

Raise and hypothesis artefacts must always have a submit button, otherwise they can't stand alone

## Tree

### W187.1 · A Hypothesis page must have a submit button, as a raise page already must
Status: confirmed
Approach: **The question**
- A raise's answer page is refused unless it has a submit button (`tree.py` `can_answer` calls `has_submit_button`, which ignores buttons in HTML comments). A Hypothesis page is checked by `check.py` `check_assumptions` only for a control, a handler and a verdict post to `/artefact-state/`. So a page with a text box, a handler and a `verdict` in a script, but no button, passes. Should it?

**Why it matters**
- The author rules on the page alone. With nothing to press, the page cannot send the ruling and does not stand alone.

**What this node does**
- In `check_assumptions`, refuse a page that can be operated and can rule but has no submit button (reuse `dfs_tree.has_submit_button`), with a message naming the page and what is missing. Keep the order of the other refusals. Update the `check.py` docstring and `docs/artefacts.md` ("An answer page") to say a Hypothesis page needs the button too.
- Add a case to `test_a_hypothesis_must_name_an_interactive_artefact` in `scripts/test_tree.py`: a page with a `<textarea>`, a handler and a verdict post but no button is refused, and a button only inside an HTML comment is refused.

**How we will know it worked**
- The new case fails before the change and passes after. `scripts/test_tree.py`, `scripts/test_templates.py` and `scripts/test_web.py` pass, and `_TEMPLATE_ANSWER.html` still passes the check.
Determination: The commit guard now refuses a Hypothesis page with no submit button, and the new test failed before the change and passes after it.
