# W193 · Allow adding a title to chats so that chat sessions are easier to find based on the goal

## Goal

Allow adding a title to chats so that chat sessions are easier to find based on the goal

## Tree

### W193.1 · Keep a chat's title in its record and serve it
Status: confirmed
Approach: **The question**
- A chat is one conversation per scope (a task id, or `project`), kept as `<run root>/chat/<scope>.json` with `sid`, `agent`, `ended` and `backend`. Where does a title go, and how do the page and the screen set and read it?

**What this node does**
- `scripts/chat.py`: add a `title` field to that record. `Chats.title(scope)` reads it. `Chats.set_title(scope, text)` trims and collapses whitespace, allows at most `MAX_TITLE` (80) characters, and writes it (an empty text removes it). It is allowed before the first message, so a chat can be named as it is opened; the record then has no `sid`, and `agent()`, `sid()` and `list()` must still cope.
- `save_sid` keeps `title` when it rewrites the record, like `ended` and `backend`. `clear` ("New chat") deletes the record, so the title goes with the old conversation: a new chat has a new goal.
- `state()` and `list()` return `title`. `list()` also lists a titled chat with no messages yet, so a named chat is not lost.
- `scripts/web.py` `chat_act`: a `chat/title` action taking `scope` and `title`, answering with the chat's state.

**How we will know it worked**
- New cases in `scripts/test_chat.py` and `scripts/test_web.py`: set, read back in `state` and `list`, survives `save_sid` and `end`, goes on `clear`, too-long and blank texts, an unknown scope is refused. Run them red without the change.
Determination: A chat's title is kept in its record and comes back in `state`, `list` and the new `chat/title` action; the new tests are red without the change and green with it, and the other failures in `test_chat.py` and `test_web.py` are the same with and without it.

### W193.2 · Web page: show the title in the Chats list and the chat, and edit it
Parent: W193.1
Status: confirmed
Approach: **What this node does**
- `scripts/web/index.html`: in `drawChats` a row shows the title as its main line, with the last message under it as now. The chat dialog header (`#chat-title`) shows the title beside the scope. A "Title" button in the chat's nav asks for a title and posts it to `/api/chat/title`, then redraws. A filter box on the Chats view narrows the list by title, scope or last message, so a chat is found by its goal.
- `scripts/ui_flows.mjs`: a flow that sets a title and sees it in the list and the header.

**How we will know it worked**
- The flow passes; a screenshot of the Chats list and the chat header is kept. If no browser starts here, say so in the Determination.
Determination: The chat header now has a title box that saves on Enter, and the Chats list leads each row with the title and has a filter box, but the new `chat_title` browser flow and a screenshot could not be made here (no node or playwright, and the headless chromium hung), so the page code is read through and not run.

### W193.3 · Terminal screen: show the title in the chats pane and set it
Parent: W193.2
Status: open

- `scripts/tui.py`: `lines_chats` prints the title in each row ahead of the last message. A key in the chats pane (`t`, if free there; else another) prompts for a title and calls `Chats.set_title`. Add the key to the key table next to `archive-chat`, and to the pane's action line.
- Check with `scripts/test_screen.py`: a row with a title shows it, and the key sets it.

**How we will know it worked**
