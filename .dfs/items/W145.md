# W145 · We should be able to end chats, that way it's easier to keep track of in-progress chats

## Summary

A chat can now be ended, from the web page or the terminal screen. The chat dialog has an End button and the screen has an `E` key (it asks first); either stops the chat's background agent and marks the conversation ended. The Chats tab lists the chats still in progress first, with the ended ones in a collapsed Ended group. An ended chat keeps its conversation and goes back to in progress when someone sends it a message from the page or the terminal. The Goal is met; I read "end" as mark done, not delete, since New chat already deletes.

## Tree

### W145.1 · Ending a chat marks it ended and keeps the conversation
Status: confirmed
Approach: **The question**
- What should "end a chat" do, so that the Chats list shows only what is still in progress?

**What this node does**
- In `scripts/chat.py`, `Chats.end(scope)` stops the chat's background agent (`walker.chat_close`) and writes `ended: <time>` into the scope's record (`<run root>/chat/<scope>.json`), keeping `sid` and `agent`. It refuses while a headless turn is answering.
- `Chats.list()` and `state()` return `ended`, true only while the transcript is no newer than the mark and the chat is not running or answering, so a later message (from the page or the screen) makes it in progress again with no extra write.
- `scripts/web.py`: a `chat/end` action beside `chat/clear`.
- `scripts/test_web.py` covers `/api/chat/end` and the `ended` field of `/api/chats`.

**How we will know it worked**
- New tests in `scripts/test_chat.py`: end sets the mark and keeps the sid, the transcript still reads, a later message makes it in progress again, end during a turn is refused, the screen's agent is closed. The existing chat tests still pass.
Hypothesis: "End" means mark the chat done, stop its agent and keep the conversation readable and resumable, not delete it. Wrong if the author wants an ended chat gone from the list, or wants it to stay for good once ended. .dfs/artefacts/2a198222-e7ff-41ab-a2f1-e0bf04e91a02.html
Evidence:
- for: `Chats.clear` (the "New chat" button) already deletes the record, so an end that also deleted would add nothing the page lacks (read in scripts/chat.py).
Determination: `Chats.end` and `/api/chat/end` work: the mark is kept, the conversation stays, a later message reopens it; the new chat and web tests pass.

### W145.4 · The terminal screen ends a chat with E, as the page does
Parent: W145.2
Status: confirmed
Approach: **The question**
- The terminal screen opens and keeps chats (`c`, `C`; ctrl-] leaves them running) but had no way to end one. Should it?

**What this node does**
- `scripts/tui.py`: key `E` (listed in `KEYS`) calls `UI.end_chat(scope)`. It says so if the scope has no conversation, asks `[y/N]`, then calls `Chats.end` with the screen's own side (`UiWalker`), which refuses while the agent is answering, stops the background agent and writes the `ended` mark the page reads.
- `scripts/test_review_tree.py`: `E` reaches `end_chat`; `end_chat` asks first, refuses a scope with no chat, and ends on yes.

**How we will know it worked**
- `test_review_tree` and `test_screen` (whose drift guard checks every key `act` takes is listed in `KEYS`) pass.
Hypothesis: The author expects to end a chat from the terminal screen as well as the web page, since a chat can be begun and kept there. Wrong if the web page alone is wanted: then remove `E`. .dfs/artefacts/d894d81f-cb73-40c5-9e67-d10b445cfcb7.html
Evidence:
- for: `UI.open_chat`/`start_chat` in scripts/tui.py run and keep chats on the screen, and before this node no screen key called `Chats.end` or `clear`, so a chat begun there could only be ended on the page (read in tui.py).
- for: `UiWalker.chat_close` already closes the screen's relay for the page, so `Chats.end` with `UiWalker` needs no new plumbing (read in tui.py).
- against: the briefing for the first node's Summary said the screen has no chat list; true, and `E` acts on the item under the cursor, not a list.
Determination: The screen now ends a chat with `E` the same way the page does; the screen tests pass. The artefact checker's "blank" failure is the sandbox lacking fonts (an earlier page fails the same).
