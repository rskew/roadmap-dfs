# W161 · Raise artefacts should replace the raise/answer UIs. Clicking a raise node should open the artefact fully, and the artefact should have the buttons to submit an answer. Raise nodes with an artefact should be marked so it's not a surprise.

## Summary

A raise whose text names an `Answer with:` page is now marked "answer page" on its node, on the web page and in the terminal screen. Tapping the node on the web page opens that page in full with its own buttons, and `a` on the row in the terminal screen opens it in the browser instead of the editor; sending the answer returns to the task with the raise closed. A raise with no page keeps the text dialog and the editor, since it has nothing else to answer with. The docs say so. The Playwright flows were updated but not run here, as no node was available.

## Goal

Raise artefacts should replace the raise/answer UIs. Clicking a raise node should open the artefact fully, and the artefact should have the buttons to submit an answer. Raise nodes with an artefact should be marked so it's not a surprise.

### W161.2 · The web page opens the artefact in full when a raise node is tapped
Parent: W161.1
Status: confirmed
Approach: **The question**
- Does tapping a raise node open the artefact itself, with its own buttons to send the answer, in place of the raise/answer dialog?

**What this node does**
- In `index.html`, a tap on a row (or the card's button) whose first open raise has a page goes to the full-screen viewer `#/a/<task>/<page>`, not the node card. The page's `answered` message returns to the task and redraws it.
- A raise with no page keeps the node card and the text dialog, since it has nothing else to answer with. The page-in-a-dialog branch of `answerForm` goes, since the full page replaces it.
- The viewer gets a link to the node card, so the node's own text is a tap away.

**How we will know it worked**
- `ui_flows.mjs` `answer_page` and `template_answer` flows are changed to the new path and check: tap opens the viewer, the page's send records the answer, the task shows no open raise.

Determination: Tapping a raise node with an answer page opens the page in full and sending from the real frame records the answer and returns to the task with the raise closed; a raise without a page still opens the node card and the text dialog (checked in chromium over CDP; the Playwright flows were updated but not run, as there is no node here).

### W161.5 · Fix: `a` in the terminal screen opens a page that cannot record the answer when the screen's web server is not up
Parent: W161.3
Status: confirmed
Approach: In `scripts/tui.py` `tree_answer`, a raise with an `Answer with:` page now always goes to `open_artefact` and never to the editor. `open_artefact` serves the page from the screen's own web server only when `self.web` is set; otherwise (`DFS_WEB=0`, or `start_web` failing to bind or import, which it does quietly) it gives `http://localhost:3016/<name>` (a plain static server, if up) or a `file://` URI. On either of those the page's POST to `/artefact-state/<name>` goes nowhere, so the author gets a page whose send button fails and the editor is gone: the raise cannot be answered from that screen. Likewise, when the named page file no longer exists, `open_artefact` only sets a message and the raise cannot be answered. Fix: in `tree_answer`, open the page only when `self.web` is set and the file exists; otherwise fall back to the editor flow below it (and say why on the status line, e.g. "web page off, answering in the editor"). Add `test_screen.py` cases: with `ui.web = None` and with the page file missing, `a` on a page raise opens `$EDITOR` and `open_artefact` is not called. Run `python3 -m unittest test_screen`.
Determination: `a` on a page raise now opens the page only when the screen's web server is up and the page file exists, and otherwise opens the editor with a line saying why; two new `test_screen.py` cases are red without the change and the screen tests pass.

### W161.6 · Hypothesis: a raise without an answer page keeps the text dialog and editor, and a page raise has no answer-in-words route
Parent: W161.2
Status: open
Approach: W161.2 (and W161.3, W161.4 which repeat it) decided, without a Hypothesis, two readings of the Goal ("Raise artefacts should replace the raise/answer UIs"): (1) the dialog and `$EDITOR` stay for a raise that names no page, so the replacement is only for raises with a page; (2) for a raise with a page, `answerForm` no longer offers the textarea "Or in your own words, instead of the page", so on the web page a reader whose page does not fit the answer can only use the page (the page keeps its own note box, per `docs/artefacts.md`) or the node card's Answer, which now also redirects to the page. Either could be what the author wants differently (for example every raise getting a generated page, or a way to answer in words kept). State both as a Hypothesis on W161.2 with its page, saying what would show each wrong: the author asking for a pageless raise to open a generated answer page, or for a words-only route on a page raise.
