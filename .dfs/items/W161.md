# W161 · Raise artefacts should replace the raise/answer UIs. Clicking a raise node should open the artefact fully, and the artefact should have the buttons to submit an answer. Raise nodes with an artefact should be marked so it's not a surprise.

## Goal

Raise artefacts should replace the raise/answer UIs. Clicking a raise node should open the artefact fully, and the artefact should have the buttons to submit an answer. Raise nodes with an artefact should be marked so it's not a surprise.

## Tree

### W161.1 · The web page marks a raise node that has an artefact
Status: confirmed
Approach: **The question**
- Can the author tell from the tree, before tapping, that a raise node opens a page?

**What this node does**
- In `scripts/web/index.html` the row of a raise node whose open raise names an answer page gets an "answer page" chip beside "raise, <age>", and the raise card heading carries the same tag. The page is found by the existing `answerPage()`, so the server needs no change.
- `test_web.py` checks the page source for both marks.

**How we will know it worked**
- A real chromium loads the page against a fixture: the page-raise row's chips read "raise, 37d ago / answer page / assumption" and a plain raise's read "raise, 37d ago / assumption".

Determination: The row chip and the raise card both show "answer page" only when the raise names a page; the new source test passes, and chromium's DOM showed the chip on the page raise and not on the plain one (its screenshot draws no text in this sandbox).

### W161.2 · The web page opens the artefact in full when a raise node is tapped
Parent: W161.1
Status: open
Approach: **The question**
- Does tapping a raise node open the artefact itself, with its own buttons to send the answer, in place of the raise/answer dialog?

**What this node does**
- In `index.html`, a tap on a row (or the card's button) whose first open raise has a page goes to the full-screen viewer `#/a/<task>/<page>`, not the node card. The page's `answered` message returns to the task and redraws it.
- A raise with no page keeps the node card and the text dialog, since it has nothing else to answer with. The page-in-a-dialog branch of `answerForm` goes, since the full page replaces it.
- The viewer gets a link to the node card, so the node's own text is a tap away.

**How we will know it worked**
- `ui_flows.mjs` `answer_page` and `template_answer` flows are changed to the new path and check: tap opens the viewer, the page's send records the answer, the task shows no open raise.

### W161.3 · The terminal screen marks and opens it too
Parent: W161.2
Status: open
Approach: **The question**
- Does the terminal screen mark a raise node with an artefact and open it, as the web page does?

**What this node does**
- In `tui.py`, a raise row with an answer page shows a mark, and `a` on it opens the page in the browser (as `v` does for artefacts) instead of `$EDITOR`. A raise with no page keeps the editor.

**How we will know it worked**
- A `test_screen.py` case draws the mark and checks `a` opens the page.

### W161.4 · Docs say the page replaces the dialog
Parent: W161.3
Status: open
Approach: **What this node does**
- `docs/artefacts.md` and the README text on raises say a raise with an `Answer with:` page is answered on that page, opened in full.

**How we will know it worked**
- The unit tests that read these docs pass; the goal is met if all four behaviours above hold.
