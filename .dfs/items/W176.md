# W176 · in the app chat window, up and down arrowkeys should step through previous messages

## Summary

In the web chat box, Up recalls the messages you sent in that chat, newest first. Down steps back toward the newest and then returns the text you were typing. Up steps only when the box is empty, the caret is at the very start, or a recalled message is showing, so moving the caret in a multi-line draft still works. A new message arriving while one is recalled does not shift your place. Shift, Alt, Ctrl and Cmd with the arrows are left alone. I read "previous messages" as the user's own sent messages, as a shell history does, not the agent's, and left the terminal chat alone, because it hands the keyboard to the agent's own program. The new `chat_recall` browser flow passes with the change and fails without it. Seven older chat flows fail in this environment with or without the change.

## Goal

in the app chat window, up and down arrowkeys should step through previous messages

## Tree

### W176.1 · Step through sent messages with Up and Down in the web chat box
Status: confirmed
Approach:
- **The question**: how does the chat box in `scripts/web/index.html` let Up and Down recall what the user sent before, as a shell does, without breaking caret movement in a multi-line draft?
- **Why it matters**: today Up and Down only move the caret, so resending or fixing an earlier message means retyping it.
- **What this node does**: `chatDraw` keeps the `you` messages of the open chat. A keydown handler on `#chat-input` (plain Up or Down, not while an input method is composing) steps through them. Up steps back when the caret is on the first line and the box is empty or the caret is at 0, or when the box still shows a recalled message; Down steps forward only while a recalled message is showing and the caret is on its last line, and past the newest it restores what was being typed. Editing the text, sending, or opening another chat ends the stepping. Recalled text is put in with the caret at its end. A new `chat_recall` flow in `scripts/ui_flows.mjs` covers it.
- **How we will know it worked**: the flow types a draft, presses Up and Down and sees the last message sent, then the one before, and Down brings back the newest and then the draft. The new `chat_recall` flow does this, and the same flow must go red on the old page.
Determination: Confirmed: Up and Down in `#chat-input` now step through the chat's sent messages and give the draft back, and the new `chat_recall` flow passes with the change and fails at its first step on the old page.
