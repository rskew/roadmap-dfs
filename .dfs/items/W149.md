# W149 · Allow customising the installed icon similar to the background

## Summary

The project dialog now has an "Installed app icon" picker beside the background pictures. The picture is cut square, kept in `.dfs/icon`, and served as the app icon in the manifest and the home-screen link, and a checkbox goes back to the built-in icon. There is one icon for the project, not one for each light and dark mode. The server side is tested; the dialog script and its browser flow are written but were not run, because no node or browser is installed in this session.

## Goal

### W149.4 · Hypothesis: one icon for the project, not one for each mode, and the manifest lists it as a single `any` icon
Parent: W149.1
Status: confirmed
Approach: **The question**
- The first node read "similar to the background" as one `.dfs/icon`, not a light and a dark one as the background has. In `scripts/web.py` the `/manifest.json` route also swapped the five built-in entries (two of them `maskable`) for three `any` entries that all point at the one picture, at sizes 192, 512 and 1024. Is that the right reading?

**What this node does**
- States the assumption once, with an answer page (`.dfs/artefacts/c2f4f676-9e5c-450c-a034-8cd2febf4d56.html`) that sets three options side by side: one icon, an icon per mode, one icon plus a padded maskable one. It gathers evidence and changes no code.
Hypothesis: An installed app has one icon, and the system fetches the manifest and the apple-touch-icon without knowing the page's light or dark mode, so one `any` icon is enough. Wrong if the author wants an icon per mode, or if Android shows a custom icon badly without a maskable entry. .dfs/artefacts/c2f4f676-9e5c-450c-a034-8cd2febf4d56.html
Evidence:
- for: a web search says Chromium installs with a 192 and a 512 icon, and iOS ignores the manifest icons and reads only the apple-touch-icon link. Both are met by the one picture.
- for: `/manifest.json` and `/apple-touch-icon.png` are fetched by the system with no theme sent. Only `index.html` reads `prefers-color-scheme`, so two icons could not be told apart there.
- for: `python3 -m unittest scripts.test_web -k installed_icon` passed with this manifest.
- against: the existing installability test (`test_it_is_installable_a_manifest_icons_and_a_worker`) asks for a large maskable icon because Android 12 builds its launch icon from it. A custom icon has none, so Android would draw it smaller on a plain backdrop. That test cannot reach this check here: it fails first on the README line (`--allow-host`), which failed before this change.
- against: the artefact checker reports the page blank here, and so does the shipped `_TEMPLATE.html`, so this box has no usable browser fonts. The overlap, error and width checks passed, but the page's text could not be seen.
Determination: One icon listed as `any` holds up for installing and for iOS, while the missing maskable entry is a known cost the author can ask to add, so the node is confirmed.

### W149.6 · Minor findings from the review
Parent: W149.2
Status: open
Approach: Fix these beside the two Hypotheses above; each is small.
- `scripts/paths.py` `icon_version()`: `read_icon()` then `icon_file().stat()` is racy; if the file is removed between them it raises FileNotFoundError (a 500 from `/api/state` or the page). Read the stat once in a try.
- `scripts/web.py` `index_html()`: `{{icon_json}}` and `{{icon_query}}` are replaced after `{{project_json}}`, so a project title containing that text is replaced inside the page; same weakness as the existing background placeholders, put `{{project}}`/`{{project_json}}` last or substitute in one pass.
- `squarePng` draws onto a transparent canvas, so a transparent picture gives a transparent icon, which a home screen shows black on iOS; consider filling with the paper colour.
- The manifest names the same picture at three sizes, so the declared sizes are not the picture's own; the tests do not check this.
- Four tests in `test_web.py` fail in this workspace and are not caused by this change (README text `--allow-host` and `**Runs**` missing, two chat tests); none involve the icon.
