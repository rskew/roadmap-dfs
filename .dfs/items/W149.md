# W149 · Allow customising the installed icon similar to the background

## Goal

Allow customising the installed icon similar to the background

## Tree

### W149.1 · The server keeps and serves a custom installed icon
Status: confirmed
Approach: **The question**
- Can the server keep one picture as the project's installed icon, the way it keeps the background picture, and serve it where the app icon is asked for?

**What this node does**
- `paths.py`: `icon_file()` (`.dfs/icon`), `read_icon()`, `write_icon(data)` (same png/jpeg/webp/gif check and 8 MB limit as the background picture; empty clears it) and `icon_version()`.
- `web.py`: `POST /api/icon` (same body limit and guards as `/api/background-image`), `GET /icon` for the picture; the `/icon-*.png` and `/apple-touch-icon.png` routes serve it when one is set, else the built-in files; `/manifest.json` lists it as one `any` icon with its real type and a `?v=` version; `icon` version added to the page and `/api/state`.

**How we will know it worked**
- New tests in `test_web.py`: set, serve at every icon path and in the manifest, replace, reject bad data and cross-site writes, clear back to the built-in icons.
Determination: The server keeps `.dfs/icon`, serves it at every icon path and in the manifest, and goes back to the built-in icons when it is cleared; the new test passed.

### W149.2 · The project dialog sets and clears the icon
Parent: W149.1
Status: confirmed
Approach: **What this node does**
- `index.html`: an "Installed app icon" file picker and a "Use the built-in icon" checkbox in the project dialog. The page centre-crops the chosen picture to a square and re-encodes it as a 1024 px png (a phone's home screen needs a square png), then posts it to `/api/icon`. `apple-touch-icon` and manifest links carry the version so a new icon is fetched.

**How we will know it worked**
- A browser flow in `ui_flows.mjs` (if a browser runs here) picks a picture, saves, and sees the link and manifest change; else say so.
Determination: The dialog, the versioned links and the browser flow are written and the server renders the links (test passed), but no node or browser is installed here, so the page script and the flow have not been run.
