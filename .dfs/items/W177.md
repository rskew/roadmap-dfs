# W177 · tui should start scrolled to the top, not the bottom

## Summary

The TUI now opens with the item list scrolled to its top. The list is drawn upside down, so the cursor used to start on the first item at the bottom and pushed a long list's window down with it. It now starts on the top row, which is the last item in the work order. I took "the top" to mean the item list, and left the log panes opening at their end, since they do that on purpose.

## Goal

tui should start scrolled to the top, not the bottom

## Tree

### W177.1 · Find which TUI view opens at the bottom
Status: confirmed
Approach: **The question**
- At launch, which view of `scripts/tui.py` shows its bottom: the item list, the item detail, or a log pane?

**What this node does**
- Reads `UI.__init__`, `draw_list` and `list_rows`. Draws a screen of 40 items in a 24-row window from a fresh start (`a_screen` in `test_screen.py`) and prints `list_scroll`, the selected row and the first row shown.

**How we will know it worked**
- The printout says which view starts at the bottom, in numbers.
Determination: The item list starts at the bottom: with 40 items in a 10-row window a fresh screen has the cursor on row 39 and `list_scroll` 30, while the detail pane (`scroll` 0) opens at its top.

### W177.2 · Open the item list at its top
Parent: W177.1
Status: confirmed
Hypothesis: "Start scrolled to the top" means the item list, the one view that opens at the bottom, and the author accepts the cursor starting on the top row (the last item in the work order) instead of the first item. Wrong if the author meant the log panes (agent log, activity), which also open at their end on purpose, or wants the cursor kept on the first item. .dfs/artefacts/dad82b9d-c2f3-42cc-a920-a29c791fee27.html
Approach: **The question**
- If the item list is what starts at the bottom, how does it start at the top?

**What this node does**
- The list is drawn upside down (`list_rows`: last item in the work order on top). A fresh start selects item 0, the first in the work order, which is the bottom row, so `draw_list` scrolls the window down to keep it in view. Start with the cursor on the top row (the last item) instead, so the window stays at the top. A test in `test_screen.py` draws a fresh long list and checks the first row shown is the top one.

**How we will know it worked**
- The new test fails before the change and passes after; `scripts/test_screen.py` passes.
Evidence:
- for: with 40 items in a 10-row window the list started with `list_scroll` 30 before the change, so the item list is the view that opened at the bottom; the detail pane already opened at its top.
- against: the agent log and activity panes also open at their end, but `read_run` and the `h` key say so on purpose (the newest line is the one worth reading), so they are not a start-at-the-bottom fault.
Determination: A fresh screen now puts the cursor on the top row and keeps the list window at the top (new test red before, green after; test_screen, test_runs and test_webscreen pass), so the Goal is met for the item list.
