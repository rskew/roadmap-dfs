# W177 · tui should start scrolled to the top, not the bottom

## Goal

tui should start scrolled to the top, not the bottom

## Tree

### W177.1 · Find which TUI view opens at the bottom
Status: confirmed
Approach: **The question**
- At launch, which view of `scripts/tui.py` shows its bottom: the item list, the item detail, or a log pane?

**What this node does**
- Reads `UI.__init__`, `draw_list` and `list_rows`. Draws a screen of 40 items in a 24-row window from a fresh start (`a_screen` in `test_screen.py`) and prints `list_scroll`, the selected row and the first row shown.

**How we will know it worked**
- The printout says which view starts at the bottom, in numbers.
Determination: The item list starts at the bottom: with 40 items in a 10-row window a fresh screen has the cursor on row 39 and `list_scroll` 30, while the detail pane (`scroll` 0) opens at its top.

### W177.2 · Open the item list at its top
Parent: W177.1
Status: open
Approach: **The question**
- If the item list is what starts at the bottom, how does it start at the top?

**What this node does**
- The list is drawn upside down (`list_rows`: last item in the work order on top). A fresh start selects item 0, the first in the work order, which is the bottom row, so `draw_list` scrolls the window down to keep it in view. Start with the cursor on the top row (the last item) instead, so the window stays at the top. A test in `test_screen.py` draws a fresh long list and checks the first row shown is the top one.

**How we will know it worked**
- The new test fails before the change and passes after; `scripts/test_screen.py` passes.
