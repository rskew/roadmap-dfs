# W107 · Pre commit hook issue

## Summary

When a finished task is merged, the runner now commits only that task's own files, so a file of another task left staged in its worktree is neither committed nor judged by the guard; the item is reopened asking for that stray file to be committed or dropped, which a session can do. When the runner's commit is still refused, the node it opens holds a short one-line gist of the guard's message: line numbers are stripped from file references and the guard's notes about other tasks' over-budget files are dropped, so the gist reaches the fault, does not bloat the task file and does not carry the warnings that got the next commit refused. The cause was found by reproduction in a scratch repo (another task's faulty file staged in the worktree), not checked against the reporter's repo; the report's guess that other tasks' unchanged files were to blame does not hold for the current guard, which already ignores faults a commit did not add. The runner's commits still go through the guard rather than skipping it with --no-verify, since the author has ruled against that bypass before.
