# W116 · Github mode

## Summary

With `.dfs/github` written, a finished task is held on its branch, and the author's Open PR mark (screen `P`, the web button, or `github.py pr`) rebases, pushes and opens its pull request with `gh`. The walk polls each open pull request: every conversation comment, review and line comment becomes an open node worked and raised on as usual (deleting a node, shelved or not, dismisses its comment, and editing one keeps its mark), reviewed fixes are pushed to the branch (a push that fails for the network or a credential says so), and a pull request merged on GitHub is landed locally by fast-forwarding the default branch, which is never committed to, and removing the worktree and branch; one closed unmerged is a raise, and a raise whose cause is put right is settled without an answer. Comments left open at a merge are fixed on a fresh branch for a new pull request, a held task holds the tasks under it, and git and `gh` calls made under the chains' lock never wait on a prompt, and fail after a time limit instead of holding every chain on a stalled network; a hand-run watch passes over a task a chain is working, and an Open PR click on the web page does not hold up other web edits. The Goal is fully met. Left out: further hardening of the locked network calls beyond the time limit (the author closed the task there), nothing is posted back to GitHub, and the mode was tested against a fake `gh` and a bare remote because `gh` is not logged in here. The README's "GitHub mode" section describes it.

## Goal

Tasks aren't merged when complete but instead created as pull requests once marked as ready by the user. Watch PRs for comment and review, creating review items as nodes and actioning and raising as normal.
