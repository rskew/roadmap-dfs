# W116 · Github mode

## Summary

With `.dfs/github` written, a finished task is held on its branch instead of merged. The author's Open PR mark (screen `P`, the web button, or `github.py pr`) rebases, pushes and opens its pull request with `gh`. The walk then polls the pull request, every page of its line comments included: each comment or review becomes an open node worked and raised on as usual, reviewed fixes are pushed to the branch, and a pull request merged on GitHub is landed locally and its worktree and branch removed; one closed unmerged is a raise. Landing replays commits only here (an earlier landing's log, the author's unpushed work) on the fetched default branch and pushes nothing; it settles a clash only in an earlier landing's own log, and any other clash is a raise with the author's commits untouched. Comments still open at a merge are fixed on a fresh branch and held for a new pull request, which pushes even when GitHub deleted the merged branch, and a task held for its pull request holds the tasks under it. The Goal is fully met; nothing is posted back to GitHub, and the mode was tested against a fake `gh` and a bare remote because `gh` is not logged in here. The README's "GitHub mode" section describes it.

## Goal

Tasks aren't merged when complete but instead created as pull requests once marked as ready by the user. Watch PRs for comment and review, creating review items as nodes and actioning and raising as normal.
