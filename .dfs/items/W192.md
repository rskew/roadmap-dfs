# W192 · Collapsed nodes should show when there are raises, incomplete nodes or assumptions underneath them

## Summary

A folded node now shows how many open raises, unfinished nodes and assumptions are hidden below it, in both the terminal screen (`scripts/tui.py`) and the web page. The counts are worked out by the shared `tree_entries` and sent to the page by `scripts/web.py`, so the two agree. Unfinished means open or started and still in play; parked, refuted and pruned nodes are not counted, and an assumption the author has already ruled on is not counted either. The Goal is met. The page's chip code was not run in a browser or under node, since neither is available here; the server side that feeds it is tested.

## Goal

Collapsed nodes should show when there are raises, incomplete nodes or assumptions underneath them

## Tree

### W192.1 · Count raises, unfinished nodes and assumptions under a node, and show the counts on a collapsed row in the terminal screen and the web page
Status: confirmed
Approach: **The question**
- A folded node hides its descendants. Today its row says only how many open raises are hidden. How does it also say how many unfinished nodes and assumptions are hidden?

**What this node does**
- In `tree_entries` (`scripts/tui.py`) give every node that has children `under`: the number of open raises, of live unfinished nodes (status open or started, not dormant, parked, refuted or pruned) and of live nodes that state a Hypothesis (`dfs_tree.assumed`), counted over all its descendants whether or not it is folded.
- The terminal screen shows `under` on a folded row, red for raises and amber for the rest (`● 2 raises below  ○ 3 unfinished below  ⚑ 1 assumption below`). The row's colour follows: red if raises, amber if only assumptions.
- `task_json` (`scripts/web.py`) sends `under`; the web page (`scripts/web/index.html`) draws the same chips on a folded row, replacing its own raise counter.

**How we will know it worked**
- New tests in `scripts/test_review_tree.py` and `scripts/test_web.py` build a tree with an open raise, an unfinished node and an assumption three levels down, and check the counts on the folded and unfolded root. They fail on the old code.
Determination: Done: a folded row now counts the open raises, unfinished nodes and assumptions below it in the terminal screen and the web page; the new tests pass and the terminal ones fail on the old code. The page's own JavaScript could not be run, as no node is installed here.

### W192.2 · Hypothesis: what "incomplete nodes" and "assumptions" mean in the fold counts
Parent: W192.1
Status: confirmed
Approach: **The question**
- The Goal says a folded node shows "incomplete nodes" and "assumptions" below it, and does not say which nodes those are. Which did the first node count?

**What this node does**
- States the reading the folded-row counts in `tree_entries` (`scripts/tui.py`) already use, so the author can rule on it. Nothing in the code changes.
- Unfinished is a live node that is open or started and not parked or planned under a parked node. Assumption is a live node that states a Hypothesis the author has not yet confirmed or refuted (`assumed` in `scripts/tree.py`).

**How we will know it worked**
- The author confirms or refutes the reading on the answer page. A probe over this repo's task trees shows how often each reading would change a row.
Hypothesis: A folded row counts an unfinished node only if it is open or started and not parked, and counts an assumption only if its Hypothesis is not yet ruled on by the author. Wrong if the author wants parked nodes counted as unfinished, or wants an assumption they already ruled on still counted. .dfs/artefacts/e7146348-9041-42ef-b85a-7300665215e8.html
Evidence:
- for: `assumed` in `scripts/tree.py` drops refuted, pruned and author-ruled nodes, and the node's ⚑ mark and the flagged view use the same set, so the chip never disagrees with the marks.
- for: A probe over every task tree here (524 rows with children) found 42 rows with a parked node below that the count leaves out and 3 with a ruled-on assumption it leaves out, so the other readings would change few rows.
- against: In the same probe only 1 row has an unfinished node below, while 163 rows show an assumption, since a session's own confirmed Hypothesis counts until the author rules. The assumption chip may be noisy on finished work.
- against: A parked node is a real alternative the author may want to see below a fold; the 42 rows would show it under the other reading.
Determination: The reading is stated with its page and holds on what was read, since the counts match the ⚑ marks and differ from the other readings on few rows; the author may still rule otherwise.
