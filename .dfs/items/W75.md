# W75 · Items should be completed in git branches, passing review merges the branch into main/master

## Summary

Each item is worked on its own branch, `dfs/<task>`, in its own git worktree under `.dfs/worktrees/<task>`, cut from the default branch on the first run, so a walk never switches the author's checkout; the screen, the web page and the author's attachments read and move through that worktree. When the roadmap is gitignored the worktree is cut all the same and links to the author's checkout for the ignored planning files, so both read and write one copy. A passing review, or the author's accept, rebases the branch onto `main` or `master` and merges it with `--no-ff` (local, never pushed), then removes the worktree and branch. A conflict, a dirty worktree or a hook's refusal reopens the item with a node, while the author's overlapping edits, an unfinished merge, cherry-pick, revert or rebase of theirs (a detached HEAD included), or an accept from the wrong branch are a logged raise that touches nothing of theirs, so no unmerged item ends the chain done. The Goal was met in full; an item is still worked in place with no branch when the checkout is off main or master or no commit exists yet, an untracked file left in a worktree still stops its merge, and the one test of a pre-merge hook's refusal skips where the temp directory is mounted noexec.

## Goal
