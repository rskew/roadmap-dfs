# W75 · Items should be completed in git branches, passing review merges the branch into main/master

## Summary

Each item is worked on its own branch, `dfs/<task>`, in a worktree under `.dfs/worktrees/<task>`, and a passing review or the author's accept rebases it onto `main` or `master`, merges it with `--no-ff` and removes the worktree and branch. The Goal was met, and the branch now sits on current main with its merge and the size rule both working. Off main or master, or with no commit yet, an item is still worked in place, since there is nothing to cut a branch from.

## Goal

Items should be completed in got branches, passing review merges the branch into main/master

## Decisions in force

- each item is worked on branch `dfs/<task>` in worktree `.dfs/worktrees/<task>`, cut on the chain's first run; the author's checkout stays on main (W75.1, W75.5, 2026-10-15)
- item branches write untagged ids, and the main checkout reads a worked task from its worktree (W75.4, 2026-10-15)
- `hook.sh` exports `GIT_WORK_TREE`, so the guard judges task files inside a worktree (W75.3, 2026-10-15)
- a passing review or an accept rebases `dfs/<task>` onto main/master, merges it `--no-ff` from the main checkout, locally with no push, then removes the worktree and branch (W75.6, W75.9, 2026-10-15)
- a merge or rebase that conflicts is aborted and reopened as an open node, never left half done (W75.7, W75.9, 2026-10-15)
- a merge that fails for another reason exits 3 with an open node (dirty worktree, hook refusal), or 4 with a raise (the author's own unfinished merge, rebase, cherry-pick or revert, a detached HEAD, or the checkout off the default branch) (W75.11, W75.23, W75.27, W75.34, 2026-10-17)
- the author's tracked edits that stop the merge are stashed by sha and put back; a put-back that no longer applies keeps the stash and raises; an untracked file of theirs that the branch adds is raised for and left in place (W75.47, W75.48, W75.55, W75.56, 2026-10-24)
- with no commit yet, or the checkout off main/master, an item is worked in place with no branch and no merge, but a task that already has a worktree stays in it (W75.24, W75.33, W75.34, 2026-10-17)
- a gitignored roadmap still gets the worktree, with the ignored `.dfs` entries linked from main (W75.29, W75.30, W75.31, 2026-10-17)
- the author's accept merges at once; while a chain is working the task it is only recorded, the chain's exit trap merges it however the chain stops, and a chain killed outright needs a second accept (W75.22, W75.37, W75.40, W75.42, W75.66, W75.67, 2026-10-28)
- an accepted GitHub-mode task is held for its pull request and is not acceptable again (W75.68, 2026-10-28)
- a session in a worktree is briefed with main's current `ROADMAP.md`, not the copy from when the branch was cut (W75.38, W75.65, 2026-10-28)
- a file the author attaches, or a task's text names, moves from main's `.dfs/artefacts` into the worktree (W75.13, W75.16, W75.19, 2026-10-16)
- deleting or archiving a worked task keeps its leftover work and sets the branch aside as `dfs-deleted/<task>` or `dfs-archived/<task>` (W75.17, W75.20, W75.21, 2026-10-16)
- a task id made in a worktree avoids the ids main, retired tasks and sibling worktrees hold, and `task_ids()` lists each worktree's own task (W75.10, W75.50, W75.51, 2026-10-21)
