# W75 · Items should be completed in git branches, passing review merges the branch into main/master

## Summary

Each item is worked on its own branch, `dfs/<task>`, in a worktree under `.dfs/worktrees/<task>`, so a walk never switches the author's checkout. A passing review, or the author's accept (merged as the running chain stops, or by a second accept, which the list, screen and web page offer, if it was killed), rebases the branch onto `main` or `master` and merges it with `--no-ff`, locally, then removes the worktree and branch; a conflict, dirty worktree or hook refusal reopens the item, and the author's overlapping edits or unfinished git operation raise. The Goal was met; an item is still worked in place when the checkout is off main or master or no commit exists, and an untracked file in a worktree still stops its merge.

## Goal

Items should be completed in got branches, passing review merges the branch into main/master
