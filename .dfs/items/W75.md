# W75 · Items should be completed in git branches, passing review merges the branch into main/master

## Summary

Each item is worked on its own branch, `dfs/<task>`, in its own git worktree under `.dfs/worktrees/<task>`, cut from the default branch on the first run, so a walk never switches the author's checkout; the screen, the web page and the author's attachments read and move through that worktree, a gitignored roadmap shares its planning files with it, and sessions there are briefed with the main checkout's current ROADMAP.md. A passing review, or the author's accept, rebases the branch onto `main` or `master` and merges it with `--no-ff` (local, never pushed), then removes the worktree and branch; an accept made while a chain is still working the task is recorded and the chain merges when its session ends or, if it stops any other way, as it exits, so the worktree is never removed under it. A conflict, a dirty worktree or a hook's refusal reopens the item with a node, while the author's overlapping edits, an unfinished merge, cherry-pick, revert or rebase of theirs (a detached HEAD included), or a merge from off the default branch are a logged raise that touches nothing of theirs, so no unmerged item ends the chain done, a branch whose worktree was removed by hand included. The Goal was met in full; an item is still worked in place with no branch when the checkout is off main or master or no commit exists yet (a task that already has a worktree stays in it), an untracked file left in a worktree still stops its merge, and the one test of a pre-merge hook's refusal skips where the temp directory is mounted noexec.

## Goal

Items should be completed in got branches, passing review merges the branch into main/master
