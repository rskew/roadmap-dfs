# W75 · Items should be completed in git branches, passing review merges the branch into main/master

## Summary

Each item is now worked on its own branch, `dfs/<task>`, in its own git worktree under `.dfs/worktrees/<task>`, cut from the default branch on the first run, so a walk never switches the checkout the author has open. Every work, critic and review session runs in that worktree, and the screen and web page read the task, list a task never yet committed, show its edits and commits in their marks, and open its pages and the author's attachments through it; an attachment the author names in an answer, a correction, a Goal or a node moves into the worktree with the words, or when the worktree is first cut. A passing review, or the author's accept, rebases the branch onto `main` or `master` and merges it in with `--no-ff` (local, never pushed) and removes the worktree and branch; a rebase or merge that conflicts, a dirty worktree and a hook's refusal reopen the item with a node naming the cause, and the author's uncommitted or staged edits in the way, an unfinished merge, cherry-pick, revert or rebase of their own, or an accept from a checkout off the default branch, are a raise that touches nothing of theirs, so no unmerged item ends the chain done. A branch whose worktree was deleted by hand is checked out again. An item is worked in place, with no branch and no merge, when the roadmap is gitignored, the checkout is off main or master, or the repo has no commit yet; that narrowing is left for the author to rule on. Deleting a worked task takes its worktree's files, copies its attachments back, commits whatever else the worktree held onto its branch, removes the worktree and sets that branch aside as `dfs-deleted/<task>` (`dfs-archived/<task>` for an archive), and is refused if that commit cannot be made. The Goal was met in full; the in-place case off main or master has no chain test of its own, an untracked file left in a worktree still stops its merge, and the one test that covers a pre-merge hook's refusal skips where the temp directory is mounted noexec.

### W75.23 · Fix: a merge started while the author's own checkout is mid-merge aborts their merge and throws away their conflict resolutions
Parent: W75.7
Status: confirmed
Approach: `branch.py` `merge` never checks the main checkout's state before `git merge --no-ff dfs/<task>`. When the author is in the middle of their own merge on main (a `git pull` or `git merge` that conflicted, MERGE_HEAD present), git refuses ours with "You have not concluded your merge", and `_unmerged` sees MERGE_HEAD, takes the author's unmerged paths for the branch's, runs `git merge --abort` (losing the author's merge and every resolution they had made) and adds a bogus "Rebase dfs/<task> onto main and resolve the conflicts" node naming the author's file. Reproduced in a scratch repo with the current scripts: after `branch.py enter W1` and a commit on dfs/W1, main had a conflicted `git merge side` with mine.txt hand-resolved but not yet added; `branch.py merge W1` exited 3, MERGE_HEAD was gone, mine.txt was back to main's side, and W1's tree had the rebase node naming mine.txt. The hook-refusal path of `_unmerged` (MERGE_HEAD, no unmerged paths) aborts a clean `git merge --no-commit` of the author's the same way, and the author's accept (`tree.append_log` accept) reaches it too. Fix: before merging (and before the rebase), if the main checkout has a MERGE_HEAD (or any operation in progress: rebase, cherry-pick, revert), do not merge: log the raise path (`_raise_blocked`, exit 4) saying the author's own merge is unfinished, and only abort a merge this call started. Settle it with a test_chain test that sets up the author's conflicted merge with a hand-resolved file, runs `branch.py merge W1`, and asserts exit 4, a raise logged, MERGE_HEAD still present and the resolved file unchanged.
Determination: Confirmed: `branch.merge` now raises `BranchError` (the exit-4 raise `run.sh` stops on, and the one the author's accept logs) when the main checkout has its own merge, cherry-pick, revert or rebase unfinished, before it rebases or merges, so `_unmerged` never takes the author's MERGE_HEAD for its own; two new test_chain tests, red without the change (no raise logged), show a hand-resolved conflicted merge left with MERGE_HEAD and its file intact and no bogus rebase node, through `branch.py merge` and through the accept, with test_chain (58), test_tree, test_live and test_walk green.
