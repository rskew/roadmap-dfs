# W75 · Items should be completed in git branches, passing review merges the branch into main/master

## Summary

Each item is now worked on its own branch, `dfs/<task>`, in its own git worktree under `.dfs/worktrees/<task>`, cut from the default branch on the first run, so a walk never switches the checkout the author has open. Every work, critic and review session runs in that worktree, and the screen and web page read the task, list a task never yet committed, show its edits and commits in their marks, and open its pages and the author's attachments through it; an attachment the author names in an answer, a correction, a Goal or a node moves into the worktree with the words, or when the worktree is first cut. A passing review, or the author's accept, rebases the branch onto `main` or `master` and merges it in with `--no-ff` (local, never pushed) and removes the worktree and branch; a rebase or merge that conflicts, a dirty worktree and a hook's refusal reopen the item with a node naming the cause, and the author's uncommitted or staged edits in the way, or an accept from a checkout off the default branch, are a raise, so no unmerged item ends the chain done. Deleting a worked task takes its worktree's files, copies its attachments back, commits whatever else the worktree held onto its branch, removes the worktree and sets that branch aside as `dfs-deleted/<task>` (`dfs-archived/<task>` for an archive), and is refused if that commit cannot be made. The Goal was met in full; the one test that covers a pre-merge hook's refusal skips where the temp directory is mounted noexec.

## Goal
