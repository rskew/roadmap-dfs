# W127 · Fix the bug raised in W122.5

## Summary

The commit-time check no longer refuses a commit made by hand during a rebase. Such a commit sits on a detached HEAD, and the check read every node it replays as newly added there, so it failed the rule that a branch writes only its own part. While a rebase is in progress the check now treats the nodes and log entries of the commit being replayed as already judged, and still refuses any node the hand-made commit adds beyond them; a merge is exempt as before, and the shape, history, attachment and size rules always apply. The Goal is met: tests cover a conflicted rebase under both rebase backends, an added node still refused, and a plain commit on a detached HEAD still refused. The missing git identity the raise also mentioned is a property of the sandbox, not of the tooling, so it was left alone; and `git rebase` itself never ran the hook, so nothing changed there.

## Goal

Fix the bug raised in W122.5

## Tree

### W127.1 · A commit made while a rebase is in progress is not judged by the writer, Hypothesis or Ask rules
Status: confirmed
Approach: In `scripts/check.py` add `rebasing()` (true when `git rev-parse --git-path rebase-merge` or `rebase-apply` exists, run in the state dir like `merging()`), and make `judge_writer = not (merging() or rebasing())`, so a rebase's replayed commits skip `check_writer`, `check_assumptions` and `check_no_new_ask` as a merge's do: each was judged when first committed, and on a detached HEAD whose base lacks the task file the whole file reads as new nodes. The shape, history, attachment and size rules still run. Update the module docstring. Test in `scripts/test_tree.py` (class Branches): with the guard hooked as pre-commit, a branch that adds a task file's nodes rebased onto a master without them completes (`git rebase master`, then a conflicting variant finished with `git rebase --continue`), while a plain commit adding the same node on a detached HEAD is still refused. Run `python3 -m unittest scripts.test_tree`.
Determination: Confirmed: a `git commit` made by hand during a rebase's stop is now judged without the writer, Hypothesis and Ask rules (`rebasing()` in `scripts/check.py`); the new test fails without the change with "adds W1.3 on a detached HEAD" and passes with it, a plain commit on a detached HEAD is still refused, and `scripts.test_tree` otherwise passes except one noexec-/tmp error that fails the same without the change. `git rebase` and `--continue` commit with `-n` and never ran the hook, so only a hand-made commit during the stop was refused.

### W127.2 · A commit made during a rebase is judged for what it adds beyond the commit being replayed
Parent: W127.1
Status: confirmed
Approach: The review found that `rebasing()` exempts a hand-made commit at a rebase stop from the writer, Hypothesis and Ask rules wholesale, so nodes it genuinely adds (not the replayed commit's) escape them. In `scripts/check.py` replace the wholesale exemption by a narrower base: when `rebasing()`, judge `check_assumptions`, `check_no_new_ask` and `check_writer` against `head` plus the nodes and log entries of `REBASE_HEAD` (the commit being replayed, when git sets it at a conflict stop) that `head` lacks, built with `dfs_tree.parse`/`render` in a helper `replayed_base(task, head, rebase_head_text)`. A node the replay brings is then not new, and one added by hand still is; with no `REBASE_HEAD` (an `edit` stop) nothing is exempt. Keep `merging()` skipping them as before. Tests in `scripts/test_tree.py` class Branches: the existing conflicted-rebase commit still passes; the same conflicted rebase run with `git rebase --apply master` (the `rebase-apply` marker) passes; a hand-made commit at the conflict stop that also adds a new node is refused. Run `python3 -m unittest scripts.test_tree` with TMPDIR on an exec mount (the sandbox /tmp is noexec).
Determination: Confirmed: a hand-made commit at a rebase stop is now judged against HEAD plus the replayed commit (`replayed_base` in `scripts/check.py`), so the replay's nodes pass and a node it adds by hand is still refused; the conflicted `rebase-merge` and `--apply` (`rebase-apply`) stops both pass, the added-node case is refused, and `scripts.test_tree` passes (148 tests) with TMPDIR on an exec mount.
