# W178 · Raise artefacts should always have a submit button

## Summary

`tree.py log raise` now refuses a raise that names an HTML page other than the one on its `Answer with:` line, so every page a raise shows the author has the submit button. A button inside an HTML comment no longer counts as one. SKILL.md and docs/artefacts.md say so, and tests in scripts/test_web.py cover both. Pictures are still allowed as .png screenshots. The Goal was read as covering every page a raise names, not only the answer page; the earlier reading did not satisfy it.

## Goal

Raise artefacts should always have a submit button

## Tree

### W178.1 · A raise may name only one HTML page, and it has the submit button
Status: started
Approach:
- **The question**: can a raise still put a page in front of the author that has no submit button?
- **Why it matters**: `tree.py log raise` checks only the page on the `Answer with:` line. A raise may also link other pages "to look at", and those can be pictures with nothing to press. An earlier task made the answer page need a button and left those out; the Goal is filed again with "always".
- **What this node does**: in `append_log` (scripts/tree.py), a raise that names any `.dfs/artefacts/<name>.html` other than its `Answer with:` page is refused, with a message to draw that page into the answer page. A page named with no `Answer with:` line is refused too. The submit-button test ignores HTML comments, so a `<button>` inside a comment no longer counts. SKILL.md and docs/artefacts.md say so. Tests in scripts/test_web.py cover each refusal.
- **How we will know it worked**: the new tests fail without the change and pass with it, and scripts/test_web.py, scripts/test_templates.py and scripts/test_tree.py show no new failure.
Hypothesis: "Raise artefacts" means every HTML page a raise names, not only the page on its `Answer with:` line. Wrong if the author wants a raise to keep linking pictures that send nothing. .dfs/artefacts/174572e4-8178-489f-815a-6416b1fe6ef8.html
Evidence:
- for: the earlier task read the Goal as the answer page only, and the author filed the same Goal again with "always", so that reading did not satisfy them.
- against: docs/artefacts.md says a raise "may link several pages to look at", and 0 of the 33 raises in the task logs name a page without `Answer with:`, so the change closes a hole no raise has used yet.
- for: with the change reverted, the two new tests in scripts/test_web.py (a second page is refused; a button in a comment does not count) fail; with it they pass.
Determination: A raise now names only its answer page as an HTML page, and a button in a comment no longer counts, so every page a raise puts before the author has a submit button; the Goal is met on this reading.
