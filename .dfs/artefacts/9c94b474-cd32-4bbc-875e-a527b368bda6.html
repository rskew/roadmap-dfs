Should a repeat visit cost a 304 instead of 67 KB?

Every response from the roadmap server says Cache-Control: no-store, so the browser asks for the page and its files in full on every visit. This task gzips text (see below) but left validators (ETag, 304 Not Modified) out, because loosening the cache policy for private roadmap data is a choice for the author. Pick a policy to see what a repeat visit sends.

What was measured

Sizes of the static files as served, gzip level 1: index.html 183,659 B raw and 67,355 B gzipped; design.css 14,572 B raw and 4,835 B gzipped; sw.js 496 B raw and 313 B gzipped. The service worker is a no-op that caches nothing. The API calls (/api/state, /api/task) are data that changes, so they stay no-store under either choice.

The assumption is wrong if you want a repeat visit, for example from a phone on a weak link, to cost a 304 instead of about 72 KB.
