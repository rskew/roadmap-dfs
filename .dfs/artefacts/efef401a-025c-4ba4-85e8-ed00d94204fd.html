A parallel walk takes a nested task only once its parent is done

An example order, with every task open. Pick how many chains run at once and which rule the walk follows; the tasks it starts together turn green.

    Why this rule

    One chain at a time already works a child only after its parent: the walk keeps on the task it started until that task is done, and a parent's raise blocks its whole subtree. Taking a child beside an open parent would build on a tree that is not finished. Separate branches (W1's and W4's) share nothing, so those run together.

    Wrong if nesting in order.md only groups tasks for raises, and you want a child worked while its parent is.
