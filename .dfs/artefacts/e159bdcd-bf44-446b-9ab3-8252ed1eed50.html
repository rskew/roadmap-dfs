W75: does your accept merge the item branch?

When a review passes, the runner rebases dfs/<task> onto main/master and merges it with --no-ff. The work took your accept (screen, web page or --review) to do the same, so an accepted item is never left unmerged. Nothing is ever pushed.

If it holds, or if it does not

Rule on this node: what the work takes to be true is settled by the choice above.

This page is also the answer to a raise. Choose above, then send it.

What would show it wrong

You want to look at an accepted item's branch before it reaches main/master, or want accept to mean “the tree is fine” without touching the default branch.

The evidence so far

For: an accept that did not merge would leave a done task whose branch and worktree stay live, and the first review of this task (a passing review that failed to merge) found exactly that kind of gap. For: a merge is local and a plain git reset on main undoes it. Against: nothing observed; this is a preference.
