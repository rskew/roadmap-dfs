Is "idle CPU" the screen and the web server?

The Goal says only "Reduce idle CPU usage". This work read it as the two roadmap processes that sit running while nobody works: the terminal screen (tui.py, which also runs the web watcher) and the web server (web.py). Wrong if another idle process or timer costs more than the screen's watch now does.

Cost of one once-a-second tick, in ms (this repo's real checkout: 431 run folders)

Screen: tui.watch_signature (after the W202.2 fix)42.6 ms
Screen: reading every run folder once (runs.run_dirs)45.9 ms
Web watcher: web.roadmap_signature10.5 ms
Left out: the task-folder walk inside that watcher (423 files)1.6 ms
Left out: other roadmap processes while idleno CPU seen in ps
Left out: the browser page's timersnot measured in a browser

The page's two timers (index.html, every 2 s and every 4 s) only act while a live run's log or the chats list is on screen and the tab is visible, so they are never an idle cost. The first row is far above the 4.1 ms measured in the scratch copy: this checkout has many more run folders.

Cross-check on the live screen process (the installed build, a chain running): its main thread used 98 ticks in 10 s, its web watcher thread 10 ticks, its two other threads none. That is about 98 ms and 10 ms a second, the same size as the rows above.
