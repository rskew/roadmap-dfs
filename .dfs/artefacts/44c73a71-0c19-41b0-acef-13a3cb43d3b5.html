Is a ten-second-late ignore-file location acceptable?

The screen asks git where the ignore files are once per 10 s, not every second. Pick what changes on disk to see when the screen follows.

change+10 s

ChangeSeen afterWho sees it late
Edit .gitignore, info/exclude or the global file git already readsnext tick (1 s)nobody: their mtimes are in the signature
New core.excludesFile, or a different checkoutup to 10 sthe header's "git hides .dfs" warning, and only that

Measured in a scratch git repo against this branch's tui.watch_signature: an edit of .gitignore changed the signature at once; a new core.excludesFile did not change it until the 10 s were up. No test in the repo waits less than 10 s for the screen to follow a config change.

Wrong if a user step or test changes git's config and expects the screen to follow in under 10 s. Confirm to accept 10 s late; refute to ask git every tick again (about 7 ms a tick more, two git processes a second).
