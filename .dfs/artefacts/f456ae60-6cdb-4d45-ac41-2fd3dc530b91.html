    The assumption, and what would show it wrong

    A walk needs no second, deliberate step once every field sits in the box: the box is opened on purpose, the button says what it does, and the permission-prompts warning sits under it. Wrong if you want a confirm between the tap and agent sessions starting with their prompts off; then the parked layout keeps the fields in the box and brings back a dialog holding only the warning.

    • The web page's own walk flow (ui_flows.mjs walk) now fills Budget 7 and Chains 2 in the box and starts with no dialog; the walker receives both.
    • Against: the terminal's walk_toggle says its budget prompt is also the confirmation, since "a bare keypress is not enough of a decision"; the web box stays open between visits, so here Start walk would be one tap.
    • The terminal screen's w still asks for its budget at a prompt, so it keeps a step there; this changes only the web page.
