Deleting an item: retire it, or erase it?

W52.1 deletes a whole item (a task file with its parts and archive). The work assumes retire: move the files to .dfs/archive/deleted/ so the item can be put back. The alternative is to erase them, leaving only git history.

If it holds, or if it does not

Rule on W52.1: confirm retiring, or refute it and the work erases instead.

This page is also the answer to a raise. Choose above, then send it.

What would show it wrong

The author wants a deleted item gone for good, with nothing kept beyond git history.

The evidence so far

for: check.py already refuses a deleted task file and follows a staged rename, so a move passes the commit guard with no new exception; an erase would need one.

for: a mistaken delete from a button is undone by moving the files back.

against: none yet.
