What would show it wrong

You meant attaching from the terminal screen as well, a list of attachments kept apart from the node's text, or attaching to a node that is already confirmed or refuted (which is history, and its text cannot change).

The evidence so far

The page already draws ![alt](.dfs/artefacts/<name>.png) in place in any node's or log entry's text (rich() in index.html), and sessions already put screenshots in nodes that way: an attachment written the same way needs no new reader.

The page already uploads a picture (the background image, base64 in JSON, up to 8 MB), so the upload has a pattern to follow.

Only an open node's Title and Approach can be edited (tree.py edit_node refuses a determined one), so a picture for a determined node goes in a Refute/confirm note or an answer, which are log entries the page draws the same way.
