When does the author's message reach the session?

A work session is claude -p: one long turn of model calls and tool calls, with no prompt to type into. Pick a way in to see where a message the author sends mid-tool lands.

What follows

    What would show it wrong

    The author needs a message to cut into a long tool call or a long model answer at once, rather than wait for it to end.

    ▸ Evidence so far

    A real claude-code 2.1.308 run with -p against a stand-in model: a message written while a 3-second Bash call ran was in the very next model request, as "PostToolUse:Bash hook additional context". A message waiting when the model ended its turn was handed back by the Stop hook, and the session took one more turn and answered it.
