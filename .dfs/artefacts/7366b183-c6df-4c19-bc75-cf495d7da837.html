An attachment is a file named in what you write

On the web page, each box you write in on a node (an answer, a correction, a new or edited node, a goal) gets an Attach button. It uploads the picture or file to .dfs/artefacts/<uuid>.<ext> and puts ![name](.dfs/artefacts/<uuid>.png) (a file: [name](...)) into the text, where the page already draws it and an agent reads the path. Pick another design to see what it would change.

What would show it wrong

Wrong if you want attachments kept apart from the text (a list on the node that is not part of a correction or answer), or want to attach from the terminal screen too, or want file types beyond pictures (png, jpeg, gif, webp) and plain documents (pdf, txt, md, csv, json, log).

The evidence so far

The page already draws ![alt](.dfs/artefacts/x.png) found in any prose (index.html ART_RE), and web.py lists every artefact a task's text names, so a reference in the text needs no new storage.
