What a node view tells a reviewer about the code

Assumption: linking the code explainer from a node would show something on about one node in twelve, because notes exist for three files; what every code node lacks is the list of files its commits changed. Refute this if you want the explainer's call tree for code that has no note, or the commit subject alone is enough for you to see what a node touched.

What was counted

Notes (docs/explain/*.json) exist for inbox.py, ptyrelay.py and walk.py; those are the green boxes. Of 953 node commits in this repository, 74 (8%) touched one of them. None of the four nodes drawn did. The Files line is built (commit_files in scripts/tui.py, shown in the terminal node view and the web sheet): it costs one git show per commit when a node is opened, and it shows nothing when git cannot show the commit.

If you refute this, the Files line is taken out and the explainer link is built instead.
