Does a new page miss a change between its read and its connect?

A page reads the roadmap, then its event stream connects. A change that lands between the two is in neither.

What closing it costs

The server sends the version it held before building each answer. When the stream connects it names its version once. If the page's read is older than that, the page reads once more. A page whose read is as new (the usual case, since the stream connects first) reads nothing extra, so a load still makes one set of reads.

It assumes a change raises the version only after its file is written, so a read that starts at version R holds every change announced up to R. It is wrong if a writer can announce before the file is final.
