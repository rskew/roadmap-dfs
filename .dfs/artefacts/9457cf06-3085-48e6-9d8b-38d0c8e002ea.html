Attach clears the screen: does it stop the chat erasing rows it never drew?

A chat that redraws in place erases its last frame with cursor-up moves, one per line it drew. When you press c the cursor sits under the roadmap's own text, so those moves go over rows the chat never drew. The fix writes a clear-and-home to the terminal as attach starts, so the moves have only blank rows to go over. This assumes a real claude erases its frame the way the stand-in does.

What would show it wrong


A real claude's first screen after c still shows fragments of the roadmap's
  banner, or still wraps oddly at the terminal's width (then the cause was neither the fixed 120 columns
  nor the erase, and the parked replay of the chat's output is next). Also wrong if a real claude does not
  erase upward on attach at all, in which case the clear only costs the ctrl-] hint.
