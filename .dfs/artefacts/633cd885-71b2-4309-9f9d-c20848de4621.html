When does a tooling fault "block the Goal"?

E5 says a raise stays only for a fault that blocks the task's Goal. Of 26 tooling raises, how many E5 removes depends on what "blocks" means. Pick a reading to see which raises it keeps.

What each reading says

A. A fault blocks the Goal only if the author's answer had to be a fix (or an act only the author can do) before the task could finish. A bypass, an ignore or a filed task shows it did not. This is the test the Goal's wording gives. It needs the worker to be allowed to bypass a refusing hook, which the law does not say.

B. A fault blocks if it refused the next commit or the finish. This is how W153.4 first read it. It removes only faults that left the task able to commit.

Why it matters

Under A, 9 more raises go away (all hook refusals the author answered "go around"), but only if a worker may use --no-verify or finish by hand. Today the law is silent and the git safety rules forbid it unasked; two of the raises themselves say so.
