Which clauses count for W5

Why the reading is an assumption

For C5 (fences)

At the starting commit the chat renderer md() in scripts/web/index.html already draws fenced blocks, code and bold. "Render rich text" for task prose asks for that renderer's reach to widen, so a task tree that draws code and bold but not fences is short of it.

For C4 (lists), the weaker case

The starting md() draws no lists; its own comment says fences, code and bold are "all a chat reply needs". Lists come from the original W5 run, whose Summary I had seen when writing the rubric. The control tree here (W5-c2a) read the Goal as inline markup only and says so in its own node.

Not independent of the original

The rubric was written after reading the original run's Summary, which lists lists and fences. Its W5.2 (terminal styling) is confirmed in the live task, and C7 asks for it, yet all ten replay trees miss C7: the rubric asks more than any replay read the Goal to ask.

Wrong if a rubric written without the original's Summary leaves out C4 or C5. The table shows that then the W5 pair stops being better, and candidate 1 is still not kept.
