"Chat with codex and others" means the chat works under every agent

Today the web page's chat refuses any agent but claude, and the screen's c opens codex, kiro or opencode as a separate session the page cannot see. The work takes the Goal to mean: the page's chat, and the one conversation the page and the screen share, work under codex, kiro and opencode as they do under claude. A conversation keeps the agent it began with; switching agent with x changes which agent the NEXT new chat uses.

Which reading of the Goal

Rule on this node: what the work takes to be true is settled by the choice above.

This page is also the answer to a raise. Choose above, then send it.

What would show it wrong

Wrong if the author meant several agents taking part in one conversation (asking codex and claude the same thing, or one answering the other), or wants a running conversation to move to whichever agent x now names.

The evidence so far

chat.py's send raises "chat on the page runs under claude"; run.sh's --chat-turn exits 2 for any other agent; tui.py's chat_env shares a session only for claude. That gap is what the Goal names.

All three others resume a session by id: codex exec resume <id> and codex resume <id> (0.162.0), opencode run --session <id> and opencode --session <id> (1.18.35), kiro-cli chat --resume-id <id> (2.27.1). So one shared conversation per agent is possible.

Nothing in the task or its log mentions several agents in one conversation.
