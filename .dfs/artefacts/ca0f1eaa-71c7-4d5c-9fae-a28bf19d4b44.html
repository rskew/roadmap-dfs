May the list be up to 2 s old for what only git shows?

The page's list and walk reads share one build of the roadmap for up to 2 s while no watched file changes. A change that moves only git (a commit of a task file clears its "uncommitted" mark; a push changes "ahead") touches no watched file, so the shared build keeps showing the old value until the 2 s are up.

What was checked

Every page action (accept, draft, add, edit, delete, archive, open PR, answer, new task, order, walk and chain actions) writes a task file, the order file or the activity log, all of which the build is keyed on. So the very next read after a page action is a fresh build, and the lag is only for a change made outside the page. Nothing pushes that kind of change to a page either way: the page learns of it at its next read, so the shared build adds at most 2 s to that.

The assumption is wrong if a page action moves only git and the page re-reads the list within 2 s.
