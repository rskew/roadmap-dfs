# W3 · Stop cache stampedes

## Summary

Concurrent callers of cache.get_or_set for the same expired key now share one computation: the first computes while the others wait and then read its result, or all see its failure without retrying. Per-key bookkeeping exists only while a computation runs, so nothing accumulates for old keys, and a slow key does not delay other keys. Tests with 8 threads cover the shared success, the shared failure, and a slow key beside a fast one. The Goal was fully met; the earlier per-key-lock design was dropped because it kept a lock per key forever.

## Goal

When a hot key expires in cache.get_or_set, every in-flight request for it recomputes against the upstream at once (the upstream fell over twice last month). Make concurrent callers for one key share a single computation. Done = N threads asking for one expired key cause one upstream call, and a slow key does not hold up other keys.
