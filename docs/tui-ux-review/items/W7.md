# W7 · Higher limits for the enterprise tier

## Summary

Users listed in the optional `enterprise_users` config key now get their own rate limit and burst, read from `enterprise_rate_limit_per_sec` and `enterprise_rate_limit_burst`; everyone else keeps the standard limits. Unset enterprise limits default to twice the standard ones, since sales has not given numbers yet, and a 1.x config without the new keys loads without warnings and behaves as before. Tier is identified by a hand-kept user list rather than by the token, which keeps issued tokens working.

## Goal

Enterprise customers should get higher rate limits than everyone else. Wire it into the limiter so the numbers come from config.

## Tree

### W7.1 · Find where the tier of a client can be known
Status: confirmed
Approach: Read src/auth.py, src/server.py, src/ratelimit.py and src/config.py, and grep src and tests for "tier" and "enterprise", to see what identifies a client's tier when `handle` calls `limiter_for`.
Determination: Nothing carries a tier today. `auth.verify` returns only the user name (tokens are `user.expiry.mac`), `handle` keys the limiter on that name, and `limiter_for` takes a single rate and burst; grep finds no tier anywhere. So tier must come from a new source: a config list of enterprise users, or a tier field in the token. The Goal wants the numbers in config, and a config list keeps tokens unchanged, so the work goes via config, which adds keys to the config file's contents.

### W7.2 · Add per-tier limits to config
Parent: W7.1
Status: confirmed
Approach: In src/config.py add optional `enterprise_users` (list), `enterprise_rate_limit_per_sec` and `enterprise_rate_limit_burst` to DEFAULTS, per the author's answer (a). When a limit is not set by file or env, `load` makes it 2x the effective standard limit; `GATEWAY_ENTERPRISE_USERS` is comma-separated. Tests in tests/test_config.py cover defaults, that gateway.example.json (a 1.x-style config) loads with no warning and no enterprise users, and file and env overrides.
Determination: Passed: tests/test_config.py 9 passed, including the 1.x example loading silently with nobody enterprise. The keys are optional, so a config without them behaves as before. Next, use them in `handle`.

### W7.3 · Apply them in handle
Parent: W7.2
Status: confirmed
Approach: In src/server.py `handle`, pick the rate and burst from `enterprise_rate_limit_per_sec` and `enterprise_rate_limit_burst` when the verified user is in `CFG["enterprise_users"]`, else from the standard keys, and pass them to `ratelimit.allow_for`. New tests/test_server_tiers.py drives `handle` with a zero refill rate and counts 200s for an enterprise user, a standard user, and an empty enterprise list.
Determination: Passed: the enterprise user got 6 allowed requests against 3 for a standard user, and with no enterprise users everyone got 3; the full suite is 28 passed. The Goal is met: enterprise users get higher limits, the numbers come from config, and a 1.x config loads unchanged.
