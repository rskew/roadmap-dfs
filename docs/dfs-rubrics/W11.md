# W11 rubric · "Can't edit items"

Written from the Goal and the starting code, before any replay was scored. Not read for it: any replay tree or
task file. Seen before writing: the original run's Summary of this task, which read "items" as the tasks the
page lists and took the terminal's `e` (open the item's file in `$EDITOR`) as already working, so the web page
is the surface that cannot edit. A tree that edits the terminal side instead must still satisfy the clauses
that name behaviour (persist, refuse, preserve) for the surface it chose; C1 asks for a control on the web page
because the starting web page (`scripts/web/index.html`, `scripts/web.py`) has no way to edit and the terminal
already has one.

| # | Clause (met only if wholly true) |
|---|---|
| C1 | The web page shows a control, reachable from a task's view on a phone-size layout, that lets a person edit an item (the task's name and Goal text). |
| C2 | Saving sends the edit to the server, and the server writes it into that task's file on disk (the change is there after a reload of the page and of the server), by a route in `scripts/web.py` that checks the request is for an existing task. |
| C3 | The edit changes only what was edited: the task file's other sections (the tree of nodes, the log, the summary, any background) are kept as they were, byte for byte. |
| C4 | A bad edit is refused with a message the page shows and the file is left unchanged: an empty name or Goal, a Goal that would add a `## ` heading and so split the task file into new sections, text too long for the limit the page sets, or a task that does not exist. |
| C5 | After a save the page shows the new text without a manual reload, and the other open views of the same task (the list row, the title bar) show it too. |
| C6 | An edit made at the same time as another change to the same file (an agent session writing the log) does not lose the other change: the write re-reads the file under the write, or the request is refused when the file changed. |
| C7 | The terminal's existing way to open an item's file (`e`) still works as before. |
| C8 | A server-side test exercises the save route (a good edit and at least one refused edit). |
