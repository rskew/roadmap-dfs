# W22 rubric · "All the all-caps text, should be lowercase instead"

Written from the Goal and the starting code (the web page `scripts/web/index.html`, `scripts/web/design.css`,
`scripts/web/design.html`, the terminal screen `scripts/tui.py`, `scripts/state.py`, `scripts/web.py`), before
any replay was scored. Not read for it: any replay tree or task file. Seen before writing: the original run's
Summary of this task. "All-caps text" is read as words a person sees on the web page or the terminal screen
(and the server's printed messages) that are shown in capitals. Identifiers (task ids such as `W22`, node ids)
and the user's own text are not all-caps text and may stay as written.

| # | Clause (met only if wholly true) |
|---|---|
| C1 | `scripts/web/index.html` no longer forces capitals on any visible text: no `text-transform: uppercase` remains in its CSS (labels, tabs, filters, status words, buttons, dialog labels, section headings). |
| C2 | The web design system (`scripts/web/design.css` and the `design.html` sample page) no longer forces capitals: no `text-transform: uppercase` remains for `.cap`, `.btn`, `.textbtn`, `label.cap`, `.raise h4` or the sample page's own styles. |
| C3 | Words the terminal screen (`scripts/tui.py`) draws in capitals for a person to read (for example the raise marker, the walk state line and its stop hint, the staged warning, the missing-artefact title) are drawn in lowercase. |
| C4 | Where the terminal screen compares or looks up a value that is also a capitalised word (a log entry's `type` such as `RAISE`, `SESSION`, `ANSWER`, `NODE`), the lookup still matches the value it is given: the change did not break a comparison by lowercasing only one side. |
| C5 | The web page's own text that is typed in capitals in the HTML or JS (not made capital by CSS), such as a literal button, tab or heading word, is lowercase too. |
| C6 | Printed server messages shown to a person (web.py's startup and warning lines, if any are in capitals) are lowercase, or there are none in capitals. |
| C7 | Nothing that is not display text was changed: identifiers, keys, file formats and the data written to task files keep their case (a status or log kind written to disk is not lowercased by this change). |
| C8 | Tests or docs that assert or describe the old capital text (the design notes, a test comparing a label) are updated to the new text, so none still expects capitals that are no longer drawn. |
