# W132 rubric · "Map view improvements"

Written from the Goal and the starting code (farm-app at c757d4ea), before any replay was run or scored. Not read
for it: any replay tree, and the original W132 task file past its Goal and Log (its nodes, Summary and review notes).
Seen before writing: `replay.py plan W132` (the original's cost and counts) and the subjects of the original's
`W132.n` commits in `git log`, so clauses C2 and C4 to C9 may read the Goal as those subjects do; C1, C3 and C10 follow the
starting code alone.

The Goal, whole: "Labels for small farm objects should show when zoomed out of there's space. Small greenhouse
requires lots of zooming to he able to select in the map view. Add box select tool for dragging a region of map to
zoom in to." Read as three asks: (a) labels are shown when there is room, zoomed out; (b) a small object such as the
demo farm's greenhouse can be selected without zooming far in; (c) a tool on the map that zooms to a dragged box.

At the starting commit (`farm-operator/static/map.js`): `declutter()` hides a label (class `nolabel`) when its box
overlaps an already placed label or icon; a marker's label box is 32 px high and a zone's 34 px even when the
second line (`t2`) is empty; a zone is a polygon (`.zone`, `data-zone`) with its name at the centroid; `mapTap()`
opens what is under the tap, `nearestMarker()` gives a device within a fingertip of the tap priority over its zone;
a one-pointer drag pans, two pointers pinch, wheel and double-click zoom (`zoomAt`, `clampView`, `fitView`); the
zoom limit is `proj.F.w / 25`; there is no box tool. The demo farm's greenhouse is a zone `farm-operator/demo-site/site.toml`
(a few tens of metres across), which is about 26 by 22 px in the whole-farm view on a phone.

| # | Clause (met only if wholly true) |
|---|---|
| C1 | In `declutter()` (or what replaces it) a label is hidden only for a real overlap with another shown label or an icon: the space reserved for a second line that has no text (an empty `t2`) no longer counts as occupied. |
| C2 | A label that would overlap is tried in at least one other place beside its object (another side of its icon, or of its zone) before it is hidden. |
| C3 | The rest of the label rule still holds: labels hidden zoomed out are shown again zoomed in, a hidden label stays in the marker's or zone's `aria-label`, and declutter still runs after every view change. |
| C4 | Zoomed out to the whole farm on a phone-sized page, a tap on the greenhouse zone (on its polygon or its name) opens its card, with no zoom first; the code gives a small zone a tap area larger than its drawn polygon or shows its name as a tap target. |
| C5 | A tap that lands within a fingertip of a device icon still opens the device, not a zone around or beside it (the `nearestMarker` priority is kept), and the larger tap area of C4 does not take a tap off a device. |
| C6 | There is a control on the map, in the view-control group or beside it, with an accessible name that says it is a box, region or zoom-to-area tool, which arms the tool, and an armed state a person can see and the screen reader reads (for example `aria-pressed`). |
| C7 | With the tool armed, a drag across the map draws a visible rectangle while it is dragged, and on release the view zooms to that region: the new `viewBox` covers the dragged box, and is held to the zoom limit and the farm by the same `clampView`/zoom limit as other zooms. |
| C8 | Armed, a drag does not also pan the map; not armed, a drag pans and a pinch, wheel and double-click zoom as before; a tap without a drag while armed neither zooms to a point nor leaves the tool stuck, and the tool can be left (disarmed after one box, or by pressing the control again, or by a key). |
| C9 | The box is drawn with pointer events (a finger or a pen) and does not need a keyboard modifier: it can be done on a phone. |
| C10 | The map editor still works: the box tool is not offered or not armed while editing (`edit` is set), and the editor's drags (`editGrab`, `editDrag`, `editDrop`) and taps are unchanged. |
| C11 | A test in `farm-operator/tests/` (Playwright, run by `test-farm-operator`) drags a box with the tool and asserts that the map's `viewBox` narrows to that region, and would fail on the starting code. |
| C12 | A test in `farm-operator/tests/` asserts (a) a label shown zoomed out that the starting code hid, or (b) the greenhouse opened by a tap in the whole-farm view; it would fail on the starting code. |
