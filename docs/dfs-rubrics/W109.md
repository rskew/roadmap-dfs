# W109 rubric · "A new task file that isn't committed stops the walk when it reaches that task"

Written for W153 before any W109 replay was run or scored. Written from the Goal (the bug report: a task file
that exists in the main checkout but was never committed stops the walk with "a session could not be briefed",
after a worktree was already cut) and the starting code at f693aa6f (`scripts/branch.py` cuts the worktree and has
`carry_uncommitted`; `scripts/paths.py` links `.dfs` entries into it). Not read for it: any replay tree, and the
tree of the original W109 (its raise was read earlier, for the answer table, and says nothing of the code).
Either design in the Goal counts: carry the file to the worktree, commit it on the default branch, or refuse
early and name the files.

| # | Clause (met only if wholly true) |
|---|---|
| C1 | A task file that exists untracked in the main checkout is briefed: after the worktree is cut for that task, the session can read `.dfs/items/<task>.md` there with the main checkout's current content, with no manual commit. |
| C2 | If the chosen design is to refuse instead of carry, the walk refuses before a chain is launched and the message names the untracked files. (Met without further work when C1 is met by carrying or committing.) |
| C3 | Nothing else in the author's main checkout is committed, stashed, deleted or overwritten by the fix: only the task file (and `order.md` if the design commits it) is touched. |
| C4 | The same fix covers every entry point that cuts a worktree for a task (the walk and a single-item run), because they share the cut; neither is left with the old failure. |
| C5 | A test in the repo's test suite goes red on the starting code and green on the fix, for an untracked task file reaching the briefing. |
| C6 | A task file that is tracked and committed is cut as before, and the existing tests for `branch.py` and the chain still pass. |
| C7 | Untracked artefacts named by a task (attachments) are still handled as before the change. |
| C8 | The behaviour for an untracked task file is stated where the next reader finds it: in the code's docstring or a doc, not only in the commit message. |
