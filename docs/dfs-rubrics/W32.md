# W32 rubric · "Sale item changes say tills out of date until refresh"

Written from the Goal and the starting code (shop-app at 1da34d2f), before any replay was run or scored. Not read
for it: any replay tree or task file. Seen before writing: the original run's Summary of this task (it names the
detail, row, header and mismatch-only list, retail edits, undos, new items, online and offline, and other tabs),
so clauses C5 to C8 may read the Goal more widely than a one-line Goal asks; C1 to C4 and C8 follow the starting
code alone. At the starting commit a pricing row carries `registers_match` (`'false'` means the row disagrees with
the registers); `isRegMismatchRow` (`shop-app/static/js/table.js`) is the one predicate behind the row's
`reg-mismatch` class (`paintRegWarn`), the header mark and the mismatch-only filter; the open pricing detail shows
the line `#pd-registers` from `renderPdRegisters` (`shop-app/static/js/detail.js`), whose text is "Tills out of
date" or the registers-offline advice. The Goal is read as: after a sale-item change, the "tills out of date"
wording stays on screen when it should not, and clears only on a page refresh.

| # | Clause (met only if wholly true) |
|---|---|
| C1 | In the open pricing detail, after a sale-item change is saved whose fresh row has `registers_match` true, the "tills out of date" line (`#pd-registers`) is empty without a reload. |
| C2 | The same holds when the row has a field held (being edited, or a save in flight) at the moment the fresh row arrives: the line follows `registers_match`, not the hold. |
| C3 | The pricing table row's mismatch mark (`reg-mismatch`, `paintRegWarn`) clears without a reload after such a change. |
| C4 | The header mark and the mismatch-only list stop counting and showing the row once `registers_match` is true, without a reload or a toggle of the filter. |
| C5 | A change that really leaves the registers out of date (`registers_match` still `'false'`) keeps all of these surfaces saying so: nothing is cleared that should not be. |
| C6 | The same clearing happens when the change came from another tab or device (the stream's echo of the row), not only from this tab's own save. |
| C7 | A change made offline or queued does not leave the wording stuck after the queue drains and the server answers; it clears when the change is answered. |
| C8 | The wording a person sees in each state (checking the link, registers offline, re-save the price, nothing) is still correct and still reaches the right case: the change does not remove the register-link advice. |
| C9 | A Playwright spec in `shop-app/e2e/` fails on the starting code and passes on the tree for the detail line (C1), as the repository's own checks for pricing are specs. |
