# W17 rubric · "How to end chat sessions so we don't leak resources on the sever"

Written from the Goal and the starting code (64806b5d), before any replay was run or scored. Not read for it:
any replay tree or replay task file. Seen before writing: the original run's task file, with its Summary and
the Determinations of its nodes (the tree is complete in the repo's history), so the clauses below may be
coloured by what that run found: C7 (an idle chat is closed) is its choice, and C6 and C4 are cases it
found after a review. They are put as the Goal's own words ("so we don't leak") read at the code, not as
the original's design: any way of meeting the clause counts.

At the starting commit a chat's agent lives in one of two places. A chat the terminal screen started is a
`Relay` in `scripts/ptyrelay.py` held by a `ChatHost`; `Relay.close` sends the agent's pid a hangup and a
daemon thread sends SIGKILL two seconds later. A turn the web page runs is `Chats.turn` in
`scripts/chat.py`, a `subprocess.run(..., timeout=TURN_TIMEOUT)`. The screen (`scripts/tui.py`) closes its
chats with `close_all` in a `finally`; the page's server is `scripts/web.py`.

| # | Clause (met only if wholly true) |
|---|---|
| C1 | Closing a chat in the terminal (`Relay.close`, `ChatHost.close`) ends an agent that ignores the hangup: it is sent a stronger signal after a short grace, and that follow-up does not depend on a thread that dies when the process exits. |
| C2 | Closing a chat also ends the processes the agent started (helpers, tool processes), not only the agent's own pid, including one that left the agent's process group or session. |
| C3 | When the terminal screen exits normally, every background chat's agent (and what it started) is gone before the screen's process ends: the exit waits for it. |
| C4 | When the screen is stopped by SIGTERM or SIGHUP (a kill, a dropped ssh session), its background chats are closed as on a normal exit. |
| C5 | A page turn that times out (`Chats.turn`, `TURN_TIMEOUT`) is ended together with everything it started, not only the direct child. |
| C6 | A page turn that is running when the page's server or the screen ends (normal exit, ^C, SIGTERM) is ended with it, and is not left running until it finishes on its own. |
| C7 | A background chat nobody is using (no output, nothing queued to it, no terminal attached) for a limit is closed without losing the conversation, so the next message resumes it; the limit can be changed or switched off. |
| C8 | Ending a chat that is already ended, or ending it twice, raises no error and sends no signal to a pid that is not the chat's. |
| C9 | Ending one chat leaves another chat's agent and the turns of other chats running. |
| C10 | The new paths are tested: a test starts an agent that ignores the hangup and (separately) one that starts a helper, ends the chat or turn by the route the clause names, and asserts nothing is left; at least one such test would fail on the starting code. |
